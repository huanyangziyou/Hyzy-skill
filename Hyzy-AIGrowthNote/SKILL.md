# AI 成长经验沉淀器

从问题所属的工作空间（记忆日志、验证/复盘、脚本、产物与对话）里抽出「核心问题与需求」，按**真实发生的演进顺序**写成一份带 SVG 链路图的 Markdown，一个问题一个文件，累积成个人 AI 学习成长库。交付物是一个 `.md` 文件，不是报告、不是提示词、不是代码。

## 触发条件

- 「把这次对话 / 这几轮优化沉淀成经验笔记」
- 「按实际发生的过程写问题与解决记录」
- 「给这个案例做个复盘，存到成长库」
- 「照上次那份笔记的写法，再存一份新的」
- 「扫描整个 X 文件夹 / 工作区，把这条问题的探索按整体演进重做」
- 信号特征：用户给出一段按顺序排列的过程要点（如「1.…2.…3.…」），或指向一段已发生的 AI 协作 / Agent 应用优化经历，并要求「结合 SVG」「存入某文件夹」「不同问题不同文件」。
- 排除（近邻，最像但不该接）：
  - 要画的是**源码 / 数据通路**的链路图 → `Hyzy-HDLtoSVG&Explain`
  - 要清洗粘贴文本、录音稿、HTML 并转 md → `Hyzy-rawprocess`
  - 要把**知识文档**提炼成标准流程 + 路径决策图 → `Hyzy-KnowtoMethPath`
  - 只要一份口头 / 聊天摘要、不落盘 → `summarize`
  - 只要澄清需求、要可复制提示词 → `jc-clarifier`
  - 要写工程文档、报告、PPT，或改工程源码 → 普通助手任务

## 你的工作流程

1. **定范围**：**动手写之前必读 `references/output-contract.md` 与 `references/space-scan.md`**；确定扫描根目录（用户本轮点名目录 > 当前工作区 > `.workbuddy/memory` 与项目产物 > 目标笔记库）。目标笔记目录以用户指令为准，未指定时读合同「目标位置与依赖」并**先检查目录存在再用**。
2. **扫描空间**：按 `space-scan.md` 的顺序扫目录树、记忆日志、验证/复盘、脚本与产物，产出一张「探索时间线」（日期 / 事件 / 证据文件 / 系统层变化 / 状态）。起点优先取更早的记录；若问题确实起于本次会话，以本轮落盘的日志 / 产物为证并注明「首次闭环」；放弃与返工的路线也要留。
3. 抽出**一个**核心起点问题，以及它反映的真实需求。检验口径：需求要写成「要系统具备什么能力」，不是把现象复述一遍（现象「图标双击没反应」≠ 需求「入口要能自恢复且不重复起进程」）。
4. **划阶段**：按能力层跃迁划，过三道判定（层变化 / 删除测试 / 跨会话证据，见 `space-scan.md` §四）；阶段数取真实个数，单次任务内的操作、单个实验或模块不得各算一步。每阶段压成三行：**问题 / 做法 / 结构**。结构行只写这一级新增或剥离了什么层；组件名 / 文件名 / 端口可作**结构锚点**；禁止贴命令行、代码块、参数清单或逐条执行流水账。
4.1 **决策筛选（ADR 三条件）**：扫描中遇到的候选决策逐条过三问——① **难逆转**（改主意的代价是否真实）② **无上下文会惊讶**（未来读者会不会问「为什么这样做」）③ **真实权衡**（是否存在过真正的备选）。**三条全真才记**，在对应阶段的「结构」行末补一句「决策：选 X 弃 Y（否因：…）」；缺任一条即不写，并入阶段叙述，不单列、不凑数。
5. 定文件名与 H1：必须含**具体案例主体 + 主线**，贴实际案例，不用「关于XX的问题与解决」这类泛名。命名前 `ls` 目标目录，确认无同名。
6. 落盘前若发现同名文件，停下问覆盖 / 追加 / 改名，取得明确答复再动；绝不静默覆盖。目录不存在时先问是否创建。
7. 写 md：按 `output-contract.md` 的骨架，含一张 SVG 演进链路图（节点 = 各阶段，副标题 = 该步结构变化，按职责分段着色，`marker-end` 箭头）。SVG 画法与校验复用同库 `Hyzy-HDLtoSVG&Explain/SKILL.md` 及其 `Hyzy-HDLtoSVG&Explain/scripts/validate_svg.py`，不在本包复制第二份规范。
8. 验证：对产物跑同库的 `validate_svg.py`，要求 0 错 0 警；再静态核对 SVG 为合法 XML、`viewBox` 宽 680、坐标在 0–680、marker 引用已定义、文本不超宽、H2/H3 数量与阶段数一致；并按 `space-scan.md` §五 过 6 个覆盖度问题。宣称「完成」前按 `Hyzy-VerifyGate` 只报本轮实际跑过的检查。
9. 无头浏览器渲染可用时补一次视觉核对；不可用则如实写「未做真实渲染截图核对」，不把结构校验通过说成渲染通过。

## 约束分级

- **硬约束**（违反即失败）
  - 以**真实发生的演进过程**为主线；禁止用抽象分类、分层体系、四段读法之类框架替代过程（用户已明确否过一次）。
  - 动笔前必须有探索时间线；阶段链要覆盖时间线首尾与关键转向，不得只写当前会话或最近一次任务。
  - 阶段必须是能力层跃迁；实验数、模块数、执行步骤数都不等于阶段数（删除测试见 `space-scan.md` §四）。
  - 每个阶段至少一条可指认的证据（日志 / 复盘 / 脚本 / 产物）；整条链至少有一个当前对话之外的锚点，纯单会话案例须注明「首次闭环」并以落盘产物为证。
  - 一问题一文件；文件名与 H1 贴近具体案例主体，命名须经查重。
  - 每个阶段、每个数值、每个组件名都能指回对话或日志里的事实；不编造未发生的尝试、未验证的效果。
  - 落盘前查同名；同名必须停下问，绝不静默覆盖。删除 / 移动 / 重命名用户已有文件前必须二次确认；删除先入库外暂存 `_trash/<YYYY-MM-DD>/`，禁止裸删。
  - SVG `viewBox` 宽必须是 680；落盘后必跑 `validate_svg.py` 且错误清零。
  - 只写授权范围（目标笔记目录 + 本 skill 包），不改动工程源码、其他文档与配置。
  - 决策记录必须三条件全真（难逆转 / 无上下文会惊讶 / 真实权衡），且写明至少一个被否备选与否因；缺一不记，宁缺不凑。
- **推荐默认**（有反例才偏离并记录理由）
  - 正文 ≤ 60 行（不含 SVG 源码）；每阶段三行：问题 / 做法 / 结构。
  - 一张 SVG + 一张「现象 → 根因 → 解决 → 补上的结构」表 + 一句引用块结论。
  - 中文数字分节、结论用引用块承载、参数对照用表格、不重复不灌水。
  - 只记脉络：不贴命令行、代码块、参数清单；组件名 / 文件名 / 端口可作结构锚点；需要时放一句口径差异说明。
- **允许自主判断**（仍须满足输出合同）
  - 阶段数、小节标题措辞、SVG 节点排布与分组配色、是否追加「过程中暴露的问题」表、结尾是否给同库交叉引用。

## 停止条件

- 目标目录不存在且用户未授权创建 → 停，说明缺哪项授权。
- 目标目录已有同名文件且用户未就覆盖 / 追加 / 改名表态 → 停。
- 事实互相冲突、用户本轮口述也无法定夺 → 标为「待确认」，不硬写成事实。
- 扫描后仍找不到起点或关键转向 → 标「探索链不完整」，只写已证实部分，不硬凑阶段。
- `validate_svg.py` 缺失且无回退 → 保留失败输出，报缺口，不宣称通过。
- 任务实际是要改工程源码、写报告或做 PPT → 停，转普通助手任务。

## 失败处理

| 情况 | 必须怎么做 |
|---|---|
| 信息不足 | 只问一个会改变边界的问题（目标目录 / 同名处置 / 事实冲突），或写保守可逆假设后继续，禁止多轮问卷 |
| 事实无法验证 | 标注「未知 / 待确认 / missing evidence」，不把推断写成事实 |
| 只扫到当前会话 | 扩大到 `.workbuddy/memory` 与历史会话补扫；仍不足则标「探索链不完整」，不把任务步骤写成阶段 |
| 阶段像并列清单 | 用删除测试重划：删掉该步后续能力仍成立，就并回上一级 |
| 工具不可用 | 走已声明回退（静态检查代替校验脚本、人工目测代替渲染）；无回退则保留现场并说明缺口 |
| 权限不足 | 停在写入前，点明缺哪项授权 |
| 校验失败 | 保留失败输出，只修最小责任规则，重跑同一检查；不反复重写整份文档 |
| 只完成一部分 | 明确报已完成 / 剩余 / 可恢复的下一步，partial 不写成完成 |

## 不能做的事

- 不把真实过程改写成抽象体系或分类框架；不按「问题类型」重组代替时间顺序。
- 不只扫当前对话就动笔；不把每个实验 / 模块 / 执行步骤写成一步；不把计划写成已完成的能力。
- 不编造用户未说过的阶段、未跑过的验证、未发生的效果。
- 不静默覆盖已有笔记；不删除、不移动、不重命名用户已有文件（除非二次确认且先入暂存）。
- 不输出非 680 宽的 SVG，不写字面下标，不用色板外的填充色。
- 不把命令行、代码块、参数清单、密钥、私密绝对路径堆进成长笔记正文（作结构锚点的组件名 / 文件名 / 端口不在此列）。
- 不在对话里长篇复述 md 内容；落盘后只给精简导读。
- 不为一个问题生成多个 md、不为多个问题合并成一个 md。
- 不把「结构校验通过」写成「渲染通过」，不把设计优势包装成已验证优势。
- 不因为赶进度跳过 `validate_svg.py` 或跳过同名检查。

## 产物形态与对话回报

一个 `.md` 文件，骨架固定（细节见 `references/output-contract.md`）：

```markdown
# <案例主体> · <主线>

> 两句：这份笔记记的是什么过程；一句主线判断。

## 一、起点：<核心问题与它反映的需求>
## 二、过程：<N 步演进>
<svg viewBox="0 0 680 {H}">…节点=各阶段，副标题=该步结构变化…</svg>
**读图口诀**：…
### 第 1 步：…
- **问题**：…
- **做法**：…
- **结构**：…
（第 2…N 步同）
## 三、过程中暴露的问题与解决（可选）
| 现象 | 根因 | 解决 | 补上的结构 |
## 四、脉络一句话
> 引用块结论。
```

对话回复只给：① 落盘路径 ② 覆盖了哪几个阶段 ③ 本轮实跑的验证与缺口 ④ 未改动其他文件的说明。

## 验收标准

- 产物位于目标目录，文件名与 H1 一致且含具体案例主体；目录中无同名残留。
- 写前探索时间线存在（可不在笔记内），阶段覆盖其首尾与至少一次失败 / 放弃 / 返工。
- 阶段数 = 能力层跃迁数，不是实验数、模块数或执行步骤数。
- 每阶段有当前对话之外的证据；无证据处标「待确认」。
- 含且仅含 1 个 `viewBox` 宽 680 的内联 SVG；阶段节点数与正文 `### 第 N 步` 数一致。
- 每个阶段都有「问题 / 做法 / 结构」三行；「结构」行指向系统层变化而非操作步骤复述。
- 起点问题与需求分开写，需求不是现象复述。
- `validate_svg.py` 0 错 0 警；静态检查 XML 合法、坐标无越界、marker 已定义、文本无超宽。
- 无编造的经历 / 验证；未做的验证（如真实渲染截图）明确标为缺口。
- 未改动目标目录之外的任何文件。
- 凡出现「决策」标注的，三条件全真且给出被否备选与否因；无合格决策时全文不出现该标注。
