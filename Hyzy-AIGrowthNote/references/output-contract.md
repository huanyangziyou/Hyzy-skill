# 输出合同与目标位置

> 落盘前必读。本文件是「产物长什么样、写到哪、怎么算合格」的单一事实源；根 `SKILL.md` 不复述细节。写前先按 `space-scan.md` 扫空间、建时间线。

## 一、目标位置与依赖（先检查再用）

| 项 | 解析方式 | 使用规则 |
|---|---|---|
| 成长笔记目标目录 | ① 用户本轮点名的目录；② 未给则取目标笔记库根下与主题同名的子目录；③ 两者都无则问用户 | **先 `ls` 确认目录存在**，不存在则停下问是否创建 |
| SVG 校验脚本 | `<同库根>/Hyzy-HDLtoSVG&Explain/scripts/validate_svg.py`。`<同库根>` = 本 skill 目录的上一级；先 `stat` 确认存在再用 | 落盘后必跑；缺失则走静态检查回退并标注缺口 |
| SVG 画法规范 | 同库 `Hyzy-HDLtoSVG&Explain/SKILL.md` + 其 `Hyzy-HDLtoSVG&Explain/scripts/validate_svg.py` | 复用，不在本包复制第二份规范 |
| 空间扫描协议 | `references/space-scan.md` | 动笔前必读；先建时间线再划阶段 |
| 风格锚点（已验收产物） | 目标目录下任一份已通过验收的同主题笔记；没有则跳过此项 | 只作排版与详略参照，不是模板硬规则 |

> 这一节是**解析规则**，不是本机断言。固定三段用法：`先 stat` → `存在就用` → `不存在就降级或问用户`。不要把某一台机器的路径当成唯一事实。

## 二、命名规则

- 格式：`<具体案例主体> · <主线>.md`，H1 与文件名一致（空格差异允许）。
- 主体必须是这次真实做的事，例如 `<工作台名>·六步演进`、`<链路名>·降采样调参`；禁止 `关于AI系统优化的问题与解决`、`经验总结`、`复盘记录` 这类泛名。
- 一问题一文件；不同问题不合并，同一问题不拆多份。
- 落盘前 `ls` 目标目录查同名。同名 → 停下问覆盖 / 追加 / 改名，取得明确答复再动。

## 三、Markdown 骨架

| 节 | 必含内容 | 上限 |
|---|---|---|
| 引言 | 2 句引用块：记的是什么过程 + 一句主线判断 | 2 行 |
| 一、起点 | 核心问题 + 它反映的真实需求；需求写成「系统要具备什么能力」，不是现象复述，且必须能回答「没有它会怎样」 | 3 行 |
| 二、过程 | 1 张 SVG + 读图口诀 + N 个 `### 第 N 步`；阶段覆盖完整探索链（起点 → 关键转向 → 当前能力） | 每步 4 行 |
| 三、问题与解决 | 可选；表头固定「现象 / 根因 / 解决 / 补上的结构」 | ≤ 6 行 |
| 四、脉络一句话 | 引用块结论，点出整条主线 | 1–2 行 |

「三、问题与解决」优先收导致转向的失败 / 放弃 / 返工，只写最终修复会丢掉探索过程。

每步固定三行，顺序不可换：

```markdown
- **问题**：这一步当时卡在哪。
- **做法**：实际做了什么（组件名 / 文件名 / 端口可作结构锚点；不贴命令行、代码块、参数清单）。
- **结构**：这一级让系统多出 / 剥离了哪一层，为什么算结构变化。
```

**决策标注（可选）**：仅当该步涉及一个决策，且 ADR 三条件（难逆转 / 无上下文会惊讶 / 真实权衡）全真时，在「结构」行末追加一句「决策：选 X 弃 Y（否因：…）」；**不新增行、不单开小节**。三条件缺一即不写。

正文合计 ≤ 60 行（不含 SVG 源码）。禁止堆时间线流水账以外的空泛方法论，禁止按「问题类型」重组代替演进顺序。

## 四、SVG 最小规格

- `<svg viewBox="0 0 680 {H}" width="100%" role="img">`，带 `<title>` / `<desc>` / `defs` 里的 `marker id="flow"`。
- 竖排节点：`x=40 width=600 height=50 rx=8`，步进 74；标题 `y=节点y+21`、副标题 `y=节点y+39`；箭头 `x1=x2=340`，`y1=节点y+50 → y2=节点y+74`，`marker-end="url(#flow)"`。
- 节点数 = 演进阶段数；**副标题写该步的结构变化**，不是动作复述。
- 按职责分段着色（封闭色板，只用 50/600/800 三档）：会话内 `#E6F1FB`/`#185FA5`/`#0C447C`，固化与调度 `#E1F5EE`/`#0F6E56`/`#085041`，独立系统 `#EEEDFE`/`#534AB7`/`#3C3489`；连线 `#888780`。嵌套图内层用 `#FFFFFF`。
- 文本最远到 `x=620`；中文长句先精简再画。`<svg>` 图形写完再闭合，不提前收口。
- 落盘后跑 `validate_svg.py <产物>.md`，要求 0 错 0 警；再静态复核 XML 合法、坐标 0–680、marker 引用已定义、文本无超宽。

## 五、事实恢复优先级

1. 用户本轮口述的过程要点（最高，覆盖历史推断）
2. 空间扫描到的硬证据：`.workbuddy/memory` 日志、验证报告、复盘、脚本、产物
3. 当前对话上文里已发生的操作与实测结果
4. 目标目录中已有笔记（避免重复、对齐写法）
5. 我的推断 —— **不得单独作为执行依据**

冲突时取高位。无法指回来源的步骤写「待确认」并说明缺什么，不硬编造。

## 六、已验收样例（fixture，不是模板硬规则）

`<案例主体>·六步演进.md` 是一份通过验收的产物形态样例：起点是一个能力缺口（「只能看到汇总数、想看按天按月」）；六步演进（人工导出→AI 自找数据源→脚本化 skill→定时任务落盘→独立工作台→桌面常驻入口）；SVG 六节点按「会话内 / 固化调度 / 独立系统」三段着色；三坑对照表；结尾一句「把能力从 AI 会话里一层层搬出来」的主线判断。

**泛化边界**：「六步」「按天按月」「固定端口」「单一 skill 调用」都属单样本细节，只留在本节作参照，**不得升为核心规则**。核心不变量只有：真实演进顺序、一问题一文件、命名贴案例、每步写结构变化、SVG 680 宽并校验、不编造不覆盖。
