# 空间扫描与探索时间线

> 写成长笔记前，先把「问题所在的工作空间」扫一遍。只靠当前对话写出来的，是任务流水账，不是探索史。

## 一、什么算「相关空间」

「空间」指与这个问题有关、且能提供事实的目录集合，不是全盘扫描。根目录按优先级取：

| 优先级 | 根目录 | 取什么 |
|---|---|---|
| 1 | 用户本轮点名的目录 | 用户说「扫描整个 X 文件夹」时的 X，最高优先 |
| 2 | 当前工作区（Workspace Folder） | 目录树、项目脚本、产物、约束文件 |
| 3 | `<工作区>/.workbuddy/memory/` | `YYYY-MM-DD.md` 日志与 `MEMORY.md` 长期约定（跨会话骨架） |
| 4 | 项目子目录 | `scripts/`、`验证输出/`、`backups/*/MANIFEST*`、各实验/模块目录 |
| 5 | 目标笔记库 | 同主题旧笔记、索引，用于查重与对齐写法 |
| 6 | 历史会话 | 前五层仍缺起点时，用 `conversation_search` 补早期对话 |

跨项目只在问题确实跨项目时扩展（如用户级 skill 包、多个工作区共用的流程）。默认不扫整块磁盘。

## 二、扫描顺序（先便宜后昂贵）

1. **目录树**：`ls` / Glob 到 3 层，排除 `node_modules/`、`.git/`、`_trash/`、`__pycache__/`；`backups/` 只记目录名与清单文件。
2. **记忆日志**：读 `MEMORY.md` 与按日期排序的日志，先拿到跨会话时间轴。
3. **结论性文档**：验证报告、定稿复盘、README、约束规范——转折与判据通常都在这里。
4. **执行件**：构建脚本、检查脚本、schema/config——结构锚点与门禁在这里。
5. **产物元信息**：docx/xlsx/pdf 先取页数、表数、图数、修改时间；需要细节再解包 `word/document.xml` 或读关键页。
6. **目标笔记库**：查同主题旧笔记，避免重复造一份。
7. **历史会话**：仅补缺口，不拿它替代文件证据。

预算：关键文件 ≤30 个；大文件只读目录/结论段；不整包通读 docx、pdf、xlsx。

## 三、探索时间线（写前必产出）

先落一张表，再动笔。它不必进最终笔记，但必须存在，否则阶段一定漏。

| 日期 | 事件 | 证据文件 | 系统层变化 | 状态 |
|---|---|---|---|---|
| 2026-11-11 | 定稿后做段落级 diff，提炼内容规则 | `.workbuddy/memory/2026-11-11.md` | 纠正 → 回灌通道 | 采纳 |
| 2026-11-13 | 流程与脚本打包成用户级 skill | `Hyzy-PhysLabReport/SKILL.md` | 会话内 → 可装载 | 采纳 |
| 2026-11-14 | 数据契约验证稿人工评价通过 | `验证输出/验证报告.md` | 数值 → 机器契约 | 采纳 |

状态只用四种：**采纳 / 放弃 / 返工 / 待确认**。放弃与返工要留，它们解释「为什么后来换路线」。

## 四、从时间线到阶段

阶段不是任务清单，是能力层的跃迁。三道判定全过才算：

1. **层变化**：这一级让系统多出或剥离一层（数据源、判据、门禁、调度、打包、入口）。
2. **删除测试**：删掉它，后面的能力是否不成立？不成立才是阶段；仍成立就是操作细节。
3. **跨会话证据**：至少一条证据来自当前对话之外；纯单会话案例需以落盘日志 / 产物为证并注明「首次闭环」，否则多半是任务步骤。

反面清单（已被用户否过）：

- 把每个实验 / 每个模块各写成一步——那是并列清单，不是演进。
- 把 P0–P6、安装步骤、命令序列当阶段——那是执行流水账。
- 只写最近一次任务——那是短期上下文，不是整条探索。

正面形态：按「问题形态变化」分，例如聊天框试错 → 文件系统承载 → 判据外化 → 门禁执行 → 能力打包。

## 五、覆盖度自检（落笔前 6 问）

1. 起点是否取到了最早形态（能早于当前会话就早于）？**判据锚在因果链第一环——「当时为什么会想建立或改变这个机制」，不是时间上最早的一条日志；续篇笔记不得以上一篇的终点充当起点。**
2. 至少有一次失败、放弃或返工吗？
3. 每个阶段都能指回具体文件或日志吗？
4. 阶段之间有因果，不是并列吗？
5. 终点是当前真实能力，不是下一步计划吗？
6. 目标目录没有同主题重复笔记吗？

任一为「否」：回到 §二 补扫；补不到就在笔记里标「探索链不完整」，不得宣称覆盖完整。

## 六、边界

- **只读**扫描：不改源文件、不动 `_trash/` 与 `backups/`。
- 不把密钥、隐私、完整绝对路径写进正文；组件名、文件名、端口可作结构锚点。
- 扫不到的事实写「待确认」，不硬编；旧版本只作演进证据，不当现行事实。
- 扫描结果只用于这篇笔记，不额外生成中间文件。
