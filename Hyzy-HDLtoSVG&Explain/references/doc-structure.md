# 九节文档结构与写作口径（第四步展开）

> **何时读**：图画完、开始写说明文字之前**必读**。九节的顺序与职能是固化的，节名可微调但顺序不能变。

本 skill 的文档结构**固化**为以下九节。节名可按主题微调（如"数据"改"控制"），但**顺序与职能不变**：

| 节 | 标题 | 内容要求 |
|---|---|---|
| 一 | **图：主数据通路** | 原样嵌入 SVG（`<svg …>` 直接写在 md 里，Obsidian 可渲染）+ **读图口诀**（按颜色分组解读各段职责） |
| 二 | **一句话总览** | 用生活化类比把整条链路讲成一句话（如"七道工序：拆包→还原→美化→入库→出库→精简→发车"）+ 三节导读表 |
| 三 | **逐级详解** | **每一级一个小标题**（`### 第 N 级：模块名（一句话定位）`），每级一个表格：参数 / 输入 / 输出 / 干什么 / 为什么。**"为什么"必写**——只写"是什么"等于没解释 |
| 四 | **数据变形总表** | 一张表看完全程"每级格式 / 每拍携带什么"，收尾给一句"最值得记住的话" |
| 五 | **时钟域** | 表格（时钟域 / 来源 / 谁在用 / 节拍由谁决定）+ 为什么不能合成一个钟 + 跨域桥接机制（FIFO/握手）+ 源码里的保护性写法逐条解释 |
| 六 | **控制与配置链** | 配置类模块的角色表 + **上电时序步骤**（谁先谁后、靠什么握手推进） |
| 七 | **其他细节速查** | 零散但重要的 assign / 原语 / 计数器 / 空接项 → 表格；再给一张 **故障对照表**（现象 → 首先怀疑什么） |
| 八 | **参数一览** | 全部常量 → 表格（常量 / 值 / **推导**）。凡是有算术能推出来的（位宽、拍数、容量），**必须写出推导式**，不许只列值 |
| 九 | **总结** | 不超过 5 句话，每句一个层级（通路 / 变形 / 时钟 / 关键约束 / 配置） |

## 文件骨架

```markdown
# <主题> · <源码文件>.v 数据处理流程

> 工程：<工程名> ｜ 平台：<平台> ｜ 输出：<输出规格>
> 本文以图为主，逐级解释「每一级在干什么、每个参数为什么是这个数」。

---

## 一、图：主数据通路
<svg …></svg>
**读图口诀**：…
```

**写作口径**：

- 用「**读者视角**」写，不是"我提取到了什么"。每个抽象概念配一个类比（差分 → 两根线相减抵消干扰；AXI-Stream → tvalid/tready 握手；帧缓存 → 仓库）。
- 技术名词首次出现时**展开英文全称**（HS = High Speed、TPG = Test Pattern Generator）。
- **限制与坑要明写**，包括"这不是 bug 是设计行为"这类澄清（如读侧裁切 vs 缩放）。
- 关键结论用 `>` 引用块承载。
- 末尾给出**同目录相关文档的交叉引用**（若有）。
