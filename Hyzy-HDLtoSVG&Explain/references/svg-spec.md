# SVG 画法硬规范（第三步展开）

> **何时读**：**动手写第一个 `<svg>` 之前必读**，不是写完再对照。这里的每条都是已返工过的硬约束，`scripts/validate_svg.py` 会在末轮抓违规。
> 校验器只认字面标签，**看不到真实排版**——视觉层面还要跑 `render-check.md` 的渲染核对。

## 3.1 画布与骨架

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 680 {H}" width="100%" font-family="'Microsoft YaHei',sans-serif" role="img">
  <title>图的标题</title>
  <desc>一句话说明这张图画了什么</desc>
  <defs>
    <marker id="flow" viewBox="0 0 10 10" refX="8" refY="5" markerWidth="7" markerHeight="7" orient="auto-start-reverse">
      <path d="M2 1L8 5L2 9" fill="none" stroke="context-stroke" stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round"/>
    </marker>
  </defs>
  ...
</svg>
```

> ⚠️ **`viewBox` 宽度必须是 680**。宿主渲染器会拒绝非 680 宽的 SVG（报 `must use a 680px-wide viewBox`）——这是最高频的返工原因。

## 3.2 竖排流程节点（主通路标准画法）

以节点 1 的 `y=30` 为基准，**步进固定 74**（节点高 50 + 间距 24）：

| 元素 | 公式 | 示例（第 n 个节点，n 从 0 起） |
|---|---|---|
| 节点矩形 | `x=40 y=30+74n width=600 height=50 rx=8` | `y=30`、`104`、`178`、… |
| 标题文本 | `x=60 y=节点y+21 font-size=13 font-weight=500` | `y=51` |
| 副标题文本 | `x=60 y=节点y+39 font-size=12` | `y=69` |
| 连接箭头 | `x1=x2=340`，`y1=节点y+50` → `y2=节点y+74` | `y1=80 → y2=100` |

**文本框右边界 = 640**（`x=40+600`），文本最远可到 `x=620`。文字超过 580px 宽就必须换行或缩字号——**用 `scripts/validate_svg.py` 检查，别靠目测**。

## 3.3 配色：按「职责分段」着色，不按模块类型

| 分段 | 用途 | 填充 | 描边 | 标题字 | 正文字 |
|---|---|---|---|---|---|
| 🔵 接收/物理段 | MIPI、D-PHY、解包、协议层 | `#E6F1FB` | `#185FA5` | `#0C447C` | `#185FA5` |
| 🟢 处理段 | 转换、ISP、算法 | `#E1F5EE` | `#0F6E56` | `#085041` | `#0F6E56` |
| 🟡 存取段 | DMA、读写通道 | `#FAEEDA` | `#854F0B` | `#633806` | `#854F0B` |
| ⚪ 存储/外部 | DDR、外部芯片、总线 | `#F1EFE8` | `#5F5E5A` | `#444441` | `#5F5E5A` |
| 🟣 输出段 | 输出编码、发送器 | `#EEEDFE` | `#534AB7` | `#3C3489` | `#534AB7` |
| — 箭头/连线 | 流程箭头 | — | `#888780` | — | — |

- 节点矩形统一 `stroke-width="0.5"`、`rx="8"`。
- 箭头 `stroke="#888780" stroke-width="1.5" marker-end="url(#flow)"`。
- **配色承载语义**：读者不看文字也能看出"这一段是什么职责"。不要给同职责的节点配不同色。

> ⚠️ **色板是封闭集合，多一档就报警（W4）**。`scripts/validate_svg.py` 里的 `PALETTE_PRIMARY` **只收每个色系的 50 / 600 / 800 三档**（即上表那 15 个值 + 连线色 `#888780`），**没有 100 / 200 / 700 档**。凭"容器浅一点、内层再浅一点"的直觉去挑 `#9FE1CB`、`#FAC775`、`#D3D1C7` 这类中间档，必然触发 W4（实测：一次踩出 11 条）。脚本另有一张 `PALETTE_TOLERATED` 白名单：`#FFFFFF` / `#FFF` / `#000000` / `#000` / `#B9C2D0` / `#C83C3C` / `#7846AA` / `#536DAA` / `#888`。

**嵌套结构图的唯一正解**（画"容器套子模块"时必须照抄，不要自己发明层次）：

| 层 | 填充 | 描边 |
|---|---|---|
| 外层容器（分组框） | 该职责段的 **50 档**（如 `#E6F1FB`） | 该段 **600 档**（如 `#185FA5`） |
| 内层子模块 | **`#FFFFFF`** | 该段 **600 档** |

- 想表达"这块要强调 / 是坑 / 未使能"，**不要换颜色，换描边 + 字色**：`fill="#FFFFFF" stroke="#C83C3C"`，标题与正文都用 `#C83C3C`（该色在白名单内）。深红填充（`#FCEBEB` / `#791F1F` / `#A32D2D`）**不在白名单**，照样报警。
- 遇到 W4 时**只做一种修改**——"换成同段 50/600/800 档，或换白名单色"，**不要重新发明配色**。改完立刻重跑脚本。

## 3.4 必踩的坑（已返工过，别再犯）

1. **字面下标渲染失败**：写 `u_c` 会原样显示下划线。**必须**用
   `<tspan baseline-shift="sub" font-size="10">c</tspan>`（下标字号取主字号的 ~0.77）。
2. **数值缺失**：电路/数据流图上的电源、时钟、位宽等**必须标数值**。交付前逐元件过一遍「**数值 + 极性 + 单位**」三件套清单，并与源码里的常量做**集合比对**，缺哪个一眼看出。
3. **文本溢出边框**：副标题常常超出节点右边界。先跑校验脚本，再决定是缩字号、精简措辞还是换行。
4. **参数值必须直接从文件读，不得凭记忆或上下文补**：同一个模块在不同工程里参数可能**方向相反**（实测：`Brightness_adjustment` 一处是 `ADD(0)/MINUS(20)`，另一处是 `ADD(20)/MINUS(0)`），`Read` 该 `_top.v` 时顺手把每个实例的实参**逐个抄下来**，不要用"上次那个值"。上下文摘要、前一轮对话、甚至我自己的推断都可能记反。
5. **算法系数要用算式反推一遍，再写"为什么是这个数"**：源码注释不一定等于算式语义。实测：`Saturation_adj` 注释写"默认 128"，但按算式 `(255+v)/256` 算，128 已经是 **1.5 倍**饱和增强，真正的"不调"是 **0**。凡涉及定点/移位/系数，一律把公式整理成"输入 → 输出"的代数式，再与注释对账；**不一致时以算式为准，并把差异写进文档**（这是高价值发现，不是噪音）。
6. **`<svg>` 提前闭合**：多写一个 `</svg>`（常见于"先写 title/desc，再补图形"的顺序）不会报错、不会崩，但**后面所有图形元素都掉到 svg 之外，在宿主里渲染成一行行裸文本**。这类错最阴的地方是"页面看着有东西"，所以肉眼容易放过。落盘后**必须**跑 `validate_svg.py`——它已内置 E10（开闭标签计数 + 空壳块后紧跟孤儿图形的双重判据）来抓这一类。写图时养成习惯：**图形元素写完再敲 `</svg>`**，不要中途收口。

## 3.5 视觉自查（画完立刻做，不留到交付）

- [ ] `viewBox` 宽 = 680；`width="100%"`；有 `role="img"` + `<title>` + `<desc>`
- [ ] 所有 `rect`/`text`/`line` 的坐标都在 `0~680` 内
- [ ] 每个 `marker-end="url(#x)"` 的 `#x` 在 `<defs>` 里定义过
- [ ] 无字面下标、无未替换的占位符
- [ ] **用到的 `fill` / `stroke` 全部落在 50/600/800 三档或白名单内**；嵌套图的内层是 `#FFFFFF`（W4 的高频失分点）
- [ ] **`<svg>` 与 `</svg>` 数量相等**（每个图的图形元素都在自己的 svg 里，无提前闭合）
- [ ] 跑 `scripts/validate_svg.py <文件>`，错误清零（**必跑**，别靠肉眼）
