# 环境自适应协议（IndustryRadar）

本 skill 不绑定任何机器。报告输出位置写成占位符 `<VAULT>`：占位符原样出现，就意味着「本机未配置」，而不是「路径字面值」。

## 一、占位符与解析责任

| 占位 | 含义 | 谁定 |
|---|---|---|
| `<VAULT>` | 知识库根目录；本 skill 的报告落到其下 `raw/行业视野/`（路径可按用户习惯调整） | **必须问** |

本 skill 不需要 Python、不需要脚本、不需要 venv——它唯一的机器依赖就是这个落盘位置。

## 二、三步处理

1. **先看下文有没有线索**：用户在当前会话里若已提过知识库/资料库位置，直接沿用，并在回复里写「按你前面给的 `<VAULT>` 落到 …」。
2. **没有线索就问，只问一次**：
   ```
   报告要落盘到哪里？给我一个目录即可（我会在其下建 `raw/行业视野/`）。
   如果你希望只在对话里给结论、不落盘，说一句「不落盘」我就只输出摘要。
   ```
3. **用户说不落盘 / 只要口头分析** → 不写任何文件，但随即说明「这不属于本 skill 的完整流程，产出不含 html 与存量盘点」——不要假装跑完了整套。

## 三、硬门（违反即失败）

- `<VAULT>` 未确认就写文件 —— 禁止。往用户没指定的目录写 5 万字报告是越界。
- 拿文档里的示例路径当默认值 —— 禁止。
- 把解析结果写回本 skill 的任何文件 —— 禁止。占位符必须原样保留。
- 无人值守（定时）模式下的特殊处理：此时无法提问，**必须**从定时任务的 prompt 或已有约定中取 `<VAULT>`；取不到就**不落盘**、只在结果里写明缺配置并中止，不允许自己编一个目录。

## 四、目录约定可改，不要硬套

`raw/行业视野/` 与「`行业名-行业深度分析报告-YYYY-MM-DD.md` + 同名 `.html`」是原作者的习惯，不是硬要求。若用户的知识库结构不同，与其对齐：先问一句「你的行业报告放在哪个目录、文件怎么命名」，再按用户的来。**盘点存量（工作流第 1 步）依赖命名格式，命名变了这步要跟着改**——这是移植时最容易漏的一处。
