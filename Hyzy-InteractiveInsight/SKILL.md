# 本地互动理解物生成器

把一份本地资料变成自包含 HTML 互动理解物：读者先看一屏主干抓住脉络，再逐层展开卡片、块、细项，并靠自测检验理解。**核心是理解支架，不是网页外壳；默认视图不是一大长条。**

> 生成前必读 `references/baseline-v2.md`（稳定锚 v2，含四层折叠契约与验收项）。`references/baseline-v1.md` 仅作历史。本文件只写流程与边界，不复述基线正文；少数会被脚本按字面检查的格式约束在这里重述一次，便于单页执行。

## 触发条件
- "做成互动理解物 / 按理解架构解析 / 主干清晰细节可展开 / 疑问句模块加折叠推导"
- 信号：指定本地 .md/.docx/文本，要求"好懂、能展开、能自测"，非归档摘要
- 排除：只摘要（→ summarize）、纯转 md（→ Hyzy-rawprocess）、画链路图（→ Hyzy-HDLtoSVG&Explain）、提方法路径（→ Hyzy-KnowtoMethPath）、可托管网站或联网

## 你的工作流程

1. **定锚与定界**：确认输出目录（用户本轮指定 > 当前工作区 > 停下问）；确认源资料可读。若用户尚未提供"他喜欢的样子"的样板，先追问一次；拿不到就按基线附带保守默认出 v2，并在"生成说明"标注待校准。不编造用户偏好。

2. **入库保真**：源为 .docx 时运行 `scripts/extract_docx.py <file> --stats` 还原正文与 OMML 公式，禁止只用普通文本提取（会丢公式与上下标）。源为 .md 时直接读；源为 PDF 时先转成文本再按 md 处理（本包不含 PDF 提取脚本）。转换后先出结构化提纲（模块候选＋各级标题），供人工扫一眼确认主干未断，再进入生成。

3. **按 v2 基线组织四层折叠**：拆 3–7 个疑问句模块。**L0 常显**：序号 + 疑问句 + 结论 + 徽章；**L1** 每模块一个 `<details class="mod" id="mN">` 默认收起；**L2** 模块内五个 `<details class="blk">`（通俗直觉／核心定义与对比／硬核推导／知识关联／交互自测），保留 `### 块名`，默认收起；**L3** 每块至少一个 `<details class="sub">`——推导拆步骤边界、闪卡一问一答各一卡、定义拆例外易混、关联拆前提推论。导航"前置概念"与"知识树状大纲"各用 `<details class="nav">` 折叠，树节点写成 `[疑问句](#mN)` 可跳转。**导航摘要行必须含「知识树状大纲」四字**——校验器按字面匹配，只写「知识树」会判导航缺失。

4. **双质量自检**：关键论断须能回指源段落，定位不到就删或标"推断"。区分源事实／源未核实数字／软件仿真结果／待复核项，不得写成实测，不得漏成立前提。摘要行写实质内容，不写"点击展开查看"空话。

5. **落盘与校验**：写 md 源 → 跑 `scripts/verify_structure.py <md>`（模块 3–7、五块逐项相等、L1/L2/L3 数量、嵌套深度=3、details 配对、导航三段、树跳转、无外链盘符）→ PASS 后**必须**跑 `scripts/md_to_html.py <md>` 生成同名 HTML（自包含、离线可开、折叠真可点、四档控制条、图形真显示）→ 再跑 `scripts/verify_structure.py <html>` → 最后跑 `scripts/register_workbench.py <html> --manifest <dir>/manifest.js [--topic 主题]` 自动登记（不会覆盖理解物）；目标目录还没有工作台时先跑 `init_workbench.py <dir>`。FAIL 保留输出，修最小责任规则后重跑。

5b. **渲染实证（不可跳过）**：浏览器截图确认：① 默认一屏见全部疑问句与结论、非长条；② 展开后五块与表格真显示；③ 无裸 `**`/`##`；④ **上下标可读**——`V_(ref)`、`a_n` 显示为 V_ref / aₙ，不得是 `Vref` 或 LaTeX 命令；⑤ 无乱码。DOM 验证：仅主干 L1 开 L2 关，树链接可跳转。仅"文本 PASS"不算完成。

5c. **旧产物迁移**：v1→v2 跑 `upgrade_v1_to_v2.py <files>`（仅重排结构、不改正文，带结论覆盖表），升级前先备份。不要用于首次生成。

6. **迭代分流**：反馈只涉及视觉或闪卡内容 → 改迭代层并写回版本表；要改基线第二~六节 → 先确认再升版，不在生成中悄悄改稳定层。

## 约束分级
- **硬约束**：纯本地零外发；单文件断网可读；四层折叠与疑问句主干不打折；L0 结论句有实质内容；关键论断可回指原文；软件/仿真与实测分层；删改用户文件前二次确认，删除先入 `_trash/<date>/`，禁裸删。
- **推荐默认**：模块 3–7；每模块 L3 ≥3 项；保留原始术语并当场解释。有反例可在生成说明里记理由。
- **允许自主判断**：模块切分、表格列、L3 拆法、SVG 是否必要（有真实关系才画）。仍须满足输出合同。
- **图形层（可选）**：有清晰依赖或多支汇一流时，在导航层放 680px viewBox 的 SVG 主干镜像图；只镜像主干、不引入新关系；内联 SVG 省略 `xmlns`（否则被外链正则误判）；`_(...)` 由渲染器转 `<tspan>`。不成图则宁可不画。

## 可复用平台载体（工作台层）

生成层"做一份"，平台层"可导入、累积复用"。

- **初始化**：`init_workbench.py <目录>` 铺开工作台 + 空 `manifest.js`，已有 SKIP；拷到任意目录即用，无安装无服务。
- **自动登记**：`register_workbench.py <html> [...] --manifest <dir>/manifest.js --topic <主题>` 解析标题/摘要/模块数/图形层，按名去重。须用 `.js` 而非 `.json`——`file://` 下 `fetch()` 读本地 JSON 被同源策略拦，`<script src>` 不会。
- **可编辑工作台（工作台模板 v3，与基线 v2 是两个独立版本号）**：三层状态——manifest.js 只读基线 + localStorage 本机覆盖层 + 手动导入项；界面编辑只写本机层，不回写基线。默认折叠的管理面板支持：主题增删改名/改色/排序（删主题其卡片落「未分类」）、卡片元数据编辑（自动项写覆盖层、导入项改本机记录）、导入项编辑排序、全局展示（排序/密度/默认筛选/显隐元信息/标题）、配置导出导入（整套迁移到别的项目）、清除本机编辑回基线、恢复隐藏项。File API 读本地 HTML 存本机、blob URL 打开、刷新仍在；另有搜索、主题筛选、导出清单、清空导入。所有卡片有「编辑」「移除」：移除仅本机隐藏或删记录，可恢复，不删原文件；永久生效就导出清单替换 manifest.js。
- **零外发**：清单与导入内容只留本机，编辑与迁移均离线，file:// 双击可用。

## 停止条件
- 输出目录未定且工作区不可写 → 停，问边界问题。
- 源资料读不出主干 → 停，报缺口，不硬生成。
- 需求变成多人收集/公网分享/在线模型 → 停，说明无本地等价。
- 会覆盖无关文件且未获二次确认 → 停。

## 失败处理
| 情况 | 必须怎么做 |
|---|---|
| 缺样板 | 追问一次；拿不到按保守默认出 v2 并标注待校准 |
| docx 公式丢失 | 改用 extract_docx.py，不手写重打公式 |
| 事实无法验证 | 标"未核实 / 待复核"，不把推断写成事实 |
| 校验 FAIL | 保留失败输出，修最小责任规则，重跑同一检查 |
| 只完成一部分 | 报已完成 / 剩余 / 可恢复的下一步 |

## 不能做的事
- 不调用外网、在线 LLM 或付费 API，即使声称离线。
- 不把整篇资料塞进单一平面页；默认视图不得是一大长条。
- 不做动效堆砌；互动与可视化只服务理解。
- 不把云端托管写成"能本地做"。
- 不覆盖、删除、移动、重命名用户文件而无二次确认；删除先入 `_trash/<date>/`，禁止 `rm -rf` / `del /S /Q`。
- 不编造偏好、样板、完成证据；脚本没跑就说没跑。
- 不在产物里写本机绝对路径、私人身份或专有信息。
- 不为了"更完整"擅自改基线稳定层。

## 产物形态
**交付物是 `.html`（自包含单文件，浏览器双击即用），`.md` 为源。** 固定结构：标题 → 生成依据引用块 → v2 导航（一句话总结常显／前置概念折叠／知识树折叠可跳转）→ 可选 SVG 主干图 → 3–7 个 L1 模块卡片（L0 摘要行 + L2 五块 + L3 细项）→ 生成说明四项。

## 交付汇报格式
固定回四项：① 落盘路径 ② 模块数与四层折叠计数 ③ 校验结果（md/html 双 PASS＋截图结论）④ 遗留与缺口。

## 验收标准
- md 源 `verify_structure.py` PASS：疑问模块 3–7、五块逐项相等、L1/L2/L3 数量正确、depth=3、details 配对、导航与跳转齐、外链盘符 0。
- html `verify_structure.py` PASS：data-lv 含 1/2/3、details 配对、四档按钮齐、无未渲染 `_(`/`^(`、无 http/https、无裸标记。
- **浏览器截图实证**：默认视图紧凑、逐层展开可见、公式上下标可读、无乱码——硬门槛，不是可选项。
- 产物断网可读，关键论断可回指原文，软件/仿真/实测分层清楚。
- 无本机绝对路径、私人身份或编造声明。

## 安全审计（scripts）
- `extract_docx.py`：zipfile + 标准库，递归解析 OMML 上下标/分式/根式/求和；只读无网络无删除。
- `verify_structure.py`：re + 标准库，token 级 details 深度扫描（同行多标签也准）；只读无写盘无网络。
- `md_to_html.py`：re/html + 标准库，写同名 .html；嵌套 details 深度解析并写 data-lv；`[[徽章]]`、`[文字](#mN)`、`_(...)`/`^(...)`、SVG tspan 上下标；不引外部资源。
- `upgrade_v1_to_v2.py`：re + 标准库，仅重排 v1→v2 结构、保留正文；需显式 --out 或覆盖目标。
- `register_workbench.py`：re/json + 标准库，从 HTML 解析元数据并写 manifest.js；去重保留旧序，无网络无删除。
- `init_workbench.py`：复制 templates/workbench.html 与空清单，已有文件 SKIP 不覆盖。
- 六者均有 `--help` 契约（实测 rc=0）。2026-11-23 用一份独立样例实跑整条链路：`verify_structure.py`（md）→ `md_to_html.py` → `verify_structure.py`（html）→ `init_workbench.py` → `register_workbench.py`，全部通过；html 侧四档控制条 4/4、上下标已渲染（raw_notation=0）、外链 0。
