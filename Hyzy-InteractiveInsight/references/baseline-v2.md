# 互动理解物 · 风格基线 v2（稳定锚）

> 本文件是 Hyzy-InteractiveInsight 的稳定层规范 v2，依据 2026-11-23 的反馈「默认视图不要一大长条」确立，同日升 v2 并整体重做。生成前必读。改动需显式确认后升版，不得在生成中临时调整。v1 全文保留在 `baseline-v1.md`，仅作历史。

## 一、产物形态与硬边界

- 交付物是自包含单文件 HTML（`.md` 为源），断网可读、浏览器双击可用，零外部请求；`.md` 源同时保留，便于 Obsidian 内检索与再编辑。
- 生成链路不调用外网、不上传任何资料内容；云端能力若无本地等价，明确标注做不到，不默认可用。
- 产物可公开：不出现本机绝对路径、私人资料名、非公开的内部或厂商专有信息。
- 主干清晰优先：折叠与互动只服务细节层，不得让主干变乱或阅读路径变长。**默认视图必须是一屏可读的骨架，不是一整条长文。**

## 二、全局导航层（文件开头固定三段）

1. **一句话总结**：常显，不超过 40 字，回答「这份资料讲什么、对我有什么用」。
2. **前置概念**：默认折叠，摘要行写「前置概念（N 条）— 点开查看」；展开后每条一行「概念名 — 一句说明」，无则写「无」。
3. **知识树状大纲**：默认折叠，摘要行写「知识树状大纲（N 模块）— 点开跳转」——必须含「知识树状大纲」四字，`verify_structure.py` 按字面匹配，只写「知识树」会判导航缺失；展开后为可点击的两级列表，一级是模块疑问句并锚定到对应模块，二级只列五块名称，不展开内容。

> 作用：读者默认只看到「一句话 + 两个折叠入口 + 模块卡片列表」，一屏抓住全文地图；树节点点击即打开对应模块，不必手动滚动找。

## 三、模块化拆解与四层折叠架构（v2 核心）

按语义转折拆 3–7 个模块，标题一律疑问句。折叠分四层，层级契约固定：

| 层 | 名称 | 默认状态 | 内容合同 | 视觉标签 |
|---|---|---|---|---|
| L0 | 主干 | 常显 | 序号 + 疑问句标题 + 一句结论（≤40 字）+ 五个徽章（每块一个，标出块内可展开细项数） | 模块卡片标题行 |
| L1 | 模块 | 收起 | 一个 `<details class="mod" id="mN">` 包住该模块全部五块 | 卡片边框 + 左侧色条 |
| L2 | 五块 | 收起 | 五块各一个 `<details class="blk">`，块内保留 `### 块名` 标题 | 徽章：直觉 / 定义 / 推导 / 关联 / 自测 |
| L3 | 细项 | 收起 | 每块内至少一项 `<details class="sub">`：推导按步骤拆、闪卡按「一问一答」逐张拆、定义块把「例外与易混」拆出、关联块把「前提 / 推论」拆出 | 子项小标题 |

- **L0 摘要行有机器格式**：`<summary>[[N]] 疑问句？· 结论：一句话</summary>`——必须以 `[[N]]` 开头、含全角「？」、含字面「· 结论：」，且三者在同一行。校验按此匹配，格式不对会报「疑问句模块摘要 N != modules=M」。
- **行首顶格**：`<details class="mod">` 与 `### 块名` 必须行首顶格、不能缩进——校验按 `^` 行首匹配，缩进会导致模块切分与五块计数错位。
- L0 常显的是**结论句**而不是摘要占位符：读者即使一层不展开，也能顺着疑问句 + 结论句读完整个主干。
- L1 展开后只出现五条带徽章的折叠行，不直接倾倒正文——这是「不是一大长条」的关键。
- L2 展开后才出现该块正文；L3 是真正的关系、步骤、答案细项。
- 任何一层展开都不得改变上层语序；收起时不得丢失该层的信息提示（摘要行要能说明里面有什么）。
- 全局控制条提供四档：**仅主干**（只开 L1 模块卡片，块与细项仍收起）/ **展开到块**（开到 L2）/ **全部展开** / **全部收起**。四个按钮文字按字面校验，不可改写。树状大纲的模块链接点击后自动打开对应 L1 卡片。

## 四、单模块内容结构（五块，顺序固定）

| 块 | 名称 | 写法要求 | L2 摘要行 | L3 细项 |
|---|---|---|---|---|
| 1 | 通俗直觉 | 大白话＋打比方，先给可感知画面再引入术语，不堆定义 | 一句话画面 | 若含多个比方，把「另一个比方」拆到 L3 |
| 2 | 核心定义与对比 | 精确定义；同类概念用表格横向对比，列至少含「概念 / 适用场景 / 代价」 | 表格在讲什么 | 「例外与易混点」拆到 L3 |
| 3 | 硬核推导 | 公式、证明、边界条件；公式上下标按 `_(...)` / `^(...)` 记法写 | 推导路线一句话 | 按步骤逐条拆 L3；边界条件单独一项 |
| 4 | 知识关联 | 写明与前后模块、外部知识点的因果 / 对比 / 前提 / 推论 | 关联到哪几个模块 | 「前提与推论」拆到 L3 |
| 5 | 交互自测 | 1 道思考题（L2 常显题干、给提示不给答案）＋ 2 张 Q&A 闪卡 | 自测点数 | 每张闪卡一问一答各自 L3 折叠 |

> 块 1–5 顺序不可增删；某块确无内容则保留块并显式标注省略，该块 L3 可为空（摘要行写「无细项」），但**每个模块合计**仍需 ≥3 项 L3——校验按模块计数，不按块。

## 五、表达风格

- 简洁精准：一句话只承载一个意思，删掉不增加理解的铺垫与形容词。
- 大白话保术语：先用人话讲原理，保留原始术语并当场解释，不换成含糊俗称。
- 结构最小完备：只保留能支撑理解的块；不填水。
- 带单位与变量说明：数值一律带单位；公式变量单独提行解释。
- 摘要行写法：用名词短语或短句，不写「点击展开查看内容」这类空话；徽章只标结构与数量，不标营销词。

## 六、双质量门槛

1. **转换保真**：资料转 Markdown 后段落、表格、主干层级不丢不乱；先出结构化提纲供人工扫一眼。docx 必须用 `scripts/extract_docx.py` 还原 OMML 公式**及其上下标结构**，输出 `V_(ref)`、`h_(T)`，再由 `md_to_html.py` 渲染为 `<sub>`，不得出现 `Vref`、`hT` 这类拍平文本或 LaTeX 命令。
2. **理解不幻觉**：每个关键论断能定位回原文段落；定位不到的删除或标「推断」。软件结果与仿真结果不得写成实测；源给出的成立前提不得省略。

## 七、可检查验收项

- 同一资料生成两次：导航三段结构、疑问句标题形式、四层折叠契约、五块顺序完全一致。
- 不同资料生成：默认视图一屏内可见全部模块疑问句与结论句；任意细项三次点击内可达；无「一大长条」。
- 模块 L1 数 = 模块数；每模块 L2 恰含五块；每模块至少 3 项 L3；嵌套深度恰为 3 且开闭配对。
- 树状大纲的一级节点全部可点击且目标模块存在；四档控制条齐全。
- 每个关键论断可回溯原文；无外部请求；无本机路径与私人名。
- **渲染实证不可跳过**：真实浏览器截图确认默认视图紧凑、折叠可点、徽章与图形显示、公式上下标可读、无裸 `**` / `##`、无乱码。文本结构 PASS 不等于渲染通过。
