# 案例写法与验算手段

## 1. 案例的唯一职责

案例不是"例题演示"，是**判据的落地证明**：读者看完要能反过来认出"什么条件下该走这条路径"。

因此每个案例必须包含三拍：

1. **算例**：完整题干，独立可读。
2. **为什么走这条**：点名判据。这一句是案例的灵魂——没有它，案例退化成习题解答。
3. **推导 + `\boxed{}` 结果**。

## 2. 选题原则

| 原则 | 反例 | 正例 |
|---|---|---|
| 每个子类型**条件不同**，不是计算量不同 | A1 算 $z$、A2 也算 $z$ | A1 用 $\bar z$（被迫参数化），A2 用整函数（本可免算） |
| 优先选**能暴露误判**的题 | 分母显然无根 | 分母有根但根在区域外 → 逼读者验条件 |
| 同路径不同子类型要有**判据差异** | E1、E2 都取 $n=0$ | E1 用 $n=0$，E2 用 $n=2$，结果差一个因子 |
| 允许"同题多解互检"，但要标注 | 换方法重算却不说明 | 注明"与 X1 互为验证，结果一致" |

## 3. 推导写法

- 每步一个 `$$` 块，块间空行。与源文档风格一致（若源文档用 `aligned`，跟随）。
- 结果用 `\boxed{...}` 收尾，全部案例统一。
- 中间量单独成块，不塞在句子中间。
- 不写"解："、"由此可得"这类口头引导，直接给式子。
- 需要标注量纲 / 单位时，写在公式后的行内说明里。

## 4. 验算手段对照

案例交付前**必须**用一条独立于推导的途径反算。按领域选：

| 领域 | 推荐手段 | 代码要点 |
|---|---|---|
| 复分析 / 积分 | `cmath` 数值 + 留数反算 | 复积分数值化，或对 $2\pi i\sum \mathrm{Res}$ 独立求留数 |
| 线性代数 | 残差 $\lVert Ax-b\rVert$ | `numpy.linalg.norm` |
| 微积分 / 级数 | `sympy.integrate` / `.series` 符号互检 | 与手算结果符号比对 |
| 概率 / 统计 | 蒙特卡洛采样 | 固定随机种子，样本量 ≥ 1e6 |
| 组合 / 计数 | 小规模穷举 | `itertools` 枚举后比对闭式解 |
| 数值方法 | 缩小步长看收敛性 | 两档步长结果差应同阶于截断误差 |
| 无可数值化的纯逻辑判据 | 构造反例验证边界 | 至少一个"不该走这条"的反例 |

### 验算模板

```python
import cmath, math

def chk(name, got, exp, tol=1e-9):
    ok = abs(got - exp) < tol
    print(("OK  " if ok else "ERR ") + f"{name}: got={got:.10g} exp={exp:.10g}")

chk("A1 ∫z̄dz", 1.0, 1.0)
chk("G2 ∮z²e^{1/z}dz", 1j*math.pi/3, 1j*math.pi/3)
```

### 验算记录

写进目标目录的 `_verify-log.md`：

| 案例号 | 方法 | 期望值 | 实算值 | 一致 |
|---|---|---|:--:|:--:|
| A1 | 手算 ∫₀¹2t dt | 1 | 1 | ✓ |
| G2 | 洛朗展开 a₋₁=1/6 → 2πi/6 | πi/3 | πi/3 | ✓ |

交付时把这张表贴进对话，不写"已验证通过"这种无证据的话。

## 5. 数量与篇幅控制

- 每子类型 **1 个**案例（用户可选 2 个：基础 + 易错）。
- 单个案例推导块数控制在 2–6 个 `$$`。超过 8 个说明选题太重，换题。
- 全文案例总数 ≈ 子类型总数，脚本会核对覆盖率。

## 6. 案例与正文的分工

| 内容 | 放哪 |
|---|---|
| 方法的适用条件、公式 | 路径章节开头的正文段落 |
| 判据如何触发 | 案例的「为什么走这条」一句 |
| 边界与反例 | 易错判定对照表 |
| 方法间的互检关系 | 案例后的 `>` 引用块备注 |
