# 六阶段执行细则 · 输出与工具速查（从 SKILL.md 决策层剥离）

> **何时读**：进入任一 Stage 之前必读对应小节；交付报账、查脚本参数、遇沙箱异常时读后两节。
> 本文件是 SKILL.md 原有内容的**原样搬迁**，数字与措辞未改；阶段判据与决策点的权威口径见 `pipeline.md`，坑的完整表格见 `pitfalls.md`。

## Stage 0 · 契约勘察（必做，先读库再动手）

读目标库，产出一张**库契约卡**（先读后写，禁止盲动）：

| 勘察项 | 从哪读 | 用途 |
|---|---|---|
| 写作规范 | `<库根>/_规范-*.md` | 结构/命名/图片/链接/风格的唯一标准 |
| 总索引 | `<库根>/**/000-概念地图.md`（或同类） | 概念清单、已入库 vs 规划中、域结构 |
| 域结构 | 库根一级目录 | 现有域清单、编号规则 |
| 风格基准 | 规范里点名的 1–2 篇样本 | 动笔前必读，校准密度与句式 |
| 链接白名单 | 总索引里所有 `[[...]]` | 核验脚本的越界判据 |
| 已有域目录 | `os.walk` 统计篇数 | 判断"新增"还是"补强" |

- **有规范** → 严格照它，本 skill 的 `references/note-contract.md` 只作背景。
- **无规范** → 用 `references/note-contract.md` 的**内置九小节兜底**，并**明确告知用户"该库无规范，我按内置契约写，建议先落一份规范文件"**。
- 契约卡要回显给用户确认，Stage 3 的域映射才有依据。

## Stage 1 · PDF → md

用 `scripts/convert_pdf2md.py`（封装 `pymupdf4llm`，产物沿用素材库约定 `‹源目录›/<stem>/<stem>.md` + `images/`）。

```bash
# 变量解析见「环境自适应」；--py 省略时脚本自动探测含 pymupdf4llm 的解释器
PY="${PY:-python3}"
SKILL="${SKILL_DIR:?先解析 <SKILL_DIR>（见 references/env-adapt.md）}"
"$PY" "$SKILL/scripts/convert_pdf2md.py" --src "<素材目录>"
```

- **数字版 PDF** → `--ocr-mode never`（快、无错字）。**扫描版** → `--ocr-mode auto`。
- 已存在 md 默认跳过（`--force` 覆盖）。单本失败不中断，日志落 `convert_pdf2md.log`。
- 转换完再用 `--verify-only` 复查一次：体积 / 图片数 / H1H2 数 / 行数。

## Stage 2 · 章节行号定位表

用 `scripts/build_locator.py` 把每本书的 **标题 + 行号 + 图片名前缀 + 页数**索引成一张定位表。

```bash
"$PY" "$SKILL/scripts/build_locator.py" --src "<素材目录>" \
      --out "<素材目录>/_素材定位表.md"
```

**这张表是整个流程的省 token 关键**：子任务靠行号 `Read --offset/--limit` 取段，**绝不整篇读**（一本 380 页的 md 整读一次就能吃光子任务上下文）。表里同时给出图片名正则前缀（从实际文件名反推，不要硬编码模板 —— 转换器会把空格/括号变下划线）。

## Stage 3 · 域级映射分组 + 分批

1. 逐本教材列**章节 → 域**映射；域不存在时先判断是"新增域"还是"并入现域"。
2. **新建域属于结构决策 → 必须用提问卡向用户确认**（历史确认：新增 `45-通信与网络`、`95-FPSoC软硬协同` 两域）。
3. 产出 `_规划-<资料集>融合方案.md`：域级映射 + 批次表（含**状态列** ✅/⬜）+ 素材编号规则。
4. 同步在总索引里**登记规划条目**（`⬜`），让进度可追踪。
5. **批次切分原则**：P0 结构先行 → 之后**每批一个主题域或一组同源章节**（约 8–30 篇），批内再按主题切 3–7 个并行组。
6. **每批交付后停下等用户确认**再推进下一批。

## Stage 4 · 并行子任务写笔记

按 `references/parallel-prompts.md` 的分组原则切 3–7 组，用 Agent 并行派活。每组 prompt 必带五件套：

1. **域与篇名清单**（逐字，含全角括号）
2. **素材定位表的行号范围**（让子任务按行号取原文）
3. **规范文件路径**（子任务自己读规范，不要你转述）
4. **图片目录与命名规则**
5. **汇报协议**（见下）

> 铁律：**子任务产出必须回传主控，由主控跑核验脚本复核**，不得直接采信。
> 铁律：派活时**不得把你凭先验记得的技术参数写进正文要求**——素材里查无实据的一律不许写（案例：凭先验写"AD9248 双通道 14 位"，素材全库只提过名字 → 子任务拒绝写入是对的，`references/pitfalls.md` §3）。

**子任务必须原样上报的 4 类信息**（诚实标注机制）：
- 原文**矛盾**处（含两说 + 你采信哪一说 + 依据）
- 原文**未载**、需要臆测的地方（标"待核实"，宁可空着）
- 派活说明里**与素材不符**的地方（当场反驳，不迁就）
- 借用了**其他章节/其他书**的参数（逐行标来源）

## Stage 5 · 脚本核验（每批必跑）

先写批次清单 JSON，再跑核验：

```jsonc
// batch-P4.json
{ "NEW":   { "45-通信与网络": ["以太网协议与帧结构", "UDP 协议与硬件实现"] },
  "PATCH": ["70-图像与视频/视频接口.md"] }
```

```bash
"$PY" "$SKILL/scripts/verify_notes.py" --base "<库根>" --batch "$SKILL/../batch-P4.json"
```

核验项：文件到位 / 必备小节齐全 / **断图** / **wikilink 越界** / 来源行 / 「多书对照」≥2 本 / 「插图」节内混入 H3 / 空文件。
**0 缺陷才进下一批**；有问题一次性合并修正后重跑，不来回抖。

> ⚠️ **大面积断图先查图片搜索根，不要动笔记**：核验脚本默认把「库根 + 库的上一级」当搜索根（短嵌入图片通常在素材区而非笔记目录内）。若素材在别的盘符或更上层，会**全量假断图**（实测首次误报 178 篇）。看到就跑 `--img-root "<素材目录>"` 重来。

## Stage 6 · 地图同步 + 全库终校

1. 规划条目 `⬜` → `✅`（**章节号按实际内容校正**，不要照抄规划）。
2. 更新进度行 `X 已入库 / Y 规划中`；新增/细化交叉热力表行；补来源行。
3. **一致性核对**：总索引 ✅ 数 ↔ 磁盘实际篇数（差 1 通常是辅助页/术语对照表，**必须有明确解释**，不能含糊）。
4. 跑全库终校：

```bash
"$PY" "$SKILL/scripts/fullcheck.py" --base "<库根>"
```

输出分两类：**【A】本次融合范围内**（必须为 0）/ **【B】历史遗留**（口径确立前的旧写法，列表交用户裁定，**不得擅自批量改**）。

## 输出格式

**每阶段汇报**：
```
Stage N · <名称>  |  产物：<路径>  |  核验：<✅/⚠️ + 数字>  |  待确认：<项>
```

**每批交付表**：

| 篇名 | 域 | 行数 | 图 | 核验 |
|---|---|---|---|---|
| UDP 协议与硬件实现 | 45-通信与网络 | 488 | 15 | ✅ |

**收尾报账**（三个数必须对得上，对不上要解释）：
```
概念笔记 A → B 篇 ｜ 域 X → Y 个 ｜ 规划条目 Z → 0 ｜ 全库终校：A 类 0 缺陷 / B 类 n 篇待裁定
```

**过程留痕**：原文矛盾清单（表：位置 / 原文两说 / 采信 / 依据）+ 待核实清单（原文未载项）。

## 脚本清单（`scripts/`，均已安全审计：仅本地读写，无网络外发、无删除操作）

| 脚本 | 阶段 | 用途 | 关键参数 |
|---|---|---|---|
| `convert_pdf2md.py` | 1 | PDF → md + images，跳过已转、单本失败不中断 | `--src` `--ocr-mode` `--force` `--verify-only` |
| `build_locator.py` | 2 | 生成章节行号定位表（含图片前缀/页数） | `--src` `--out` `--tag-map` |
| `verify_notes.py` | 5 | 批次核验（文件/小节/断图/越界/来源行/多书对照/插图H3） | `--base` `--batch` `--img-root` `--no-img-auto` `--extra-whitelist` |
| `fullcheck.py` | 6 | 全库终校，输出 A（本次）/ B（历史遗留） | `--base` `--std` `--opt` `--hist` `--img-root` `--no-img-auto` |
| `patch_sources.py`（可选） | 6 | 让"来源行"覆盖「多书对照」引用书目 | `--root` `--apply`（默认 dry-run） |

命令模板见 `references/pipeline.md`；**一律用绝对路径，禁用 `$HOME`**（Git Bash 下 `$HOME` 常为空，会导致脚本路径断裂、首跑失败需重跑）。

## 沙箱 / 环境要点（速查，详见 `references/pitfalls.md`）

- **PDF/Excel 转换需要带 `pymupdf4llm` 的解释器**（`convert_pdf2md.py` 会按 `references/env-adapt.md` 自动探测；探不到则按提示询问用户，不猜）。脚本本身用任意 python3 就能跑。
- bash 的 `ls/grep/find/dirname` 可能 command not found（`cd: null directory`）→ **用 Python 做文件探查**。
- Glob 在**含中文 + 半角括号**的路径下常无返回 → 改用 `os.walk`。
- 内联 `python -c` 里的**反引号会被吞** → 写临时 `.py` 文件再跑。
- 派活/建团队后 **TaskList 的 task ID 会重编号** → 每批开工先 `TaskList` 确认当前 ID。
- 长任务**放后台跑**（`run_in_background`），完成后自动通知，不要 sleep 轮询。
