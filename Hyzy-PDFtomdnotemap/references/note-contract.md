## 1. 契约探测顺序

```
1) <库根>/**/_规范-*.md              ← 首选，唯一执行标准
2) <库根>/**/000-概念地图.md 等总索引  ← 概念清单 + 进度行 + 域结构
3) 索引里点名的"风格基准"样本 1–2 篇    ← 动笔前必读
4) 库内多数笔记的共性结构（统计 H2 频次）← 无规范时的实证来源
```

**第 4 步可用脚本统计**（无规范时最靠谱）：

```python
import os, re, collections
c = collections.Counter()
for dp, dn, fn in os.walk(BASE):
    for f in fn:
        if f.endswith(".md"):
            t = open(os.path.join(dp, f), encoding="utf-8").read()
            for h in re.findall(r"^## .+$", t, re.M):
                c[h] += 1
print(c.most_common(20))
```

取出现频次最高的那组 H2 作为兜底契约（**按频次排序，不按字母排序**，顺序信息藏在笔记内部）。

## 2. 内置九小节兜底

> 来源：实战库 `_规范-概念笔记写作规范.md`。**顺序固定，不得增删。**

```markdown
# 概念名（English Name）

> 分类：<域目录名>
> 来源：<书目编号>《书名》<章节> · ...
> 状态：已入库

## 一句话解释          ← 一句大白话；这句话里不出现新术语

## 类比                ← 表格 | 已知（<用户既有领域> / 日常） | 对应到这里 |，2–4 行；必须有锚点

## 细节                ← 主体，篇幅最大；用 ### 组织，尽量用表格

## 多书对照            ← 仅当 ≥2 本书覆盖同一概念时才写；表格 | 视角 | 来源 | 要点 |，末附综合评述

## 插图                ← 表格 | 图 | 说明 | 来源 |；无图则整节省略

## 什么时候会用到

## 容易混淆的点        ← `**A ≠ B**：说明`，3–5 条

## 本机适配 / 赛题关联  ← 2–3 条，环境相关（本库专用名，见下）

## 参考                ← <书目编号>《书名》章节，页码
```

### 可省略的节

| 节 | 可省略条件 |
|---|---|
| `## 多书对照` | **只有 1 本书覆盖该概念时整节省略**（不是"只写一本书"，是整节不要写） |
| `## 插图` | 源书无图 / 该概念无配图 |

### 顺序与嵌套硬约束

- 九节的**相对顺序不可乱**（核验脚本会检查单调递增）。
- **H3 不得夹在「插图」与「什么时候会用到」之间** —— 这是历史高频错位（把「选型权衡」等 H3 写到插图节后面去了）。所有 H3 归「细节」节。
- 分隔符写法按库规范；`·` 与 ` / ` 混用会被判为"旧写法"（核验里归入历史遗留类）。

### 「本机适配 / 赛题关联」的泛化

这一节名是具体库的写法，本质是 **「环境落地 + 应用关联」**：

| 变量 | 含义 | 该库实例 |
|---|---|---|
| 本机 | 用户当前硬件/工具链 | 例：`<厂商> <芯片/系列> · <板卡型号> + <工具链简称>` |
| 关联 | 用户的选题/项目/课题 | 竞赛题号 → 详见 `[[00-总览与分类索引]]` |

固定两条式：

```markdown
- **本机（<硬件> + <工具链>）**：这个概念在本机能不能用、怎么用、有什么具体参数或坑。
- **关联**：对应哪些选题/项目的技术点（可写编号简称）→ 详见 [[<索引页>]]。
```

关联信息不确定时写通用判断（如"图像类赛题通用"），**不要硬凑**。

### 长度

- **信息密度优先，不注水**。上限由目标库规范决定（部分库已取消行数限制）。
- 短笔记（< 80 行）只要内容完整即可接受；长笔记允许，但每一段都要有原文支撑。

## 3. 命名硬规则

| 规则 | 说明 |
|---|---|
| **逐字一致** | 概念名必须与总索引清单**逐字相同**（含全角括号、英文原名后缀）。索引写 `行缓存（Line Buffer）` → 文件必须是 `行缓存（Line Buffer）.md` |
| **禁用 Windows 非法字符** | `\ / : * ? " < > |`（半角）。全角 `：` 合法 |
| **多值并列用顿号** | 一律 `、`，**绝不用半角 `/`**。例：`形态学滤波：腐蚀、膨胀、Tophat` |
| **域目录名不擅改** | 目录改名会断所有引用 |

**产前必做**：从总索引抽出该批概念名清单 → 生成文件清单 → **机器校验**是否含非法字符 / 是否与已有文件重名。

## 4. 图片规则

- **只用短嵌入** `![[文件名.png]]`（Obsidian 嵌入）。
- **严禁**相对路径 `![](../../<素材区>/...)`。
- 短嵌入成立的前提是**文件名在 vault 内唯一**。图片来自素材区的 `images/` 目录，转换器已保证前缀唯一；**不要手动重命名图片**。
- 「插图」节的「说明」列要写清 **图意 + 原书图号**；「来源」列写 `B3 P.135` / `T2 P.135`。
- ⚠️ **不要把素材目录加进 Obsidian 的排除列表**，否则短嵌入解析不到 = 全库断图。
- 图片**可以跨篇复用**（同一框图服务多个概念）——这是有意设计，不是错误。

### 页码推导

```
<stem>.pdf-<4位页>-<2位序>.png  →  页号 = 4 位数字
```
- ⚠️ **并非所有书都成立**（见过某书系约 +12 偏移）。**首次使用前，抽一张已知页的图核对页码**；不确定就只写章节不写页码。
- OCR 版教材可能有识别错字，**涉及关键数字时按上下文校正，不确定就不写具体数字**。

## 5. 链接规则

1. 只允许链接到**总索引已列出的概念名**（逐字）+ 少数辅助页（总索引本身、分类索引、术语对照表等）。
2. **不得自创概念名做链接**。想指向清单外内容 → 用纯文本，不加 `[[]]`。
3. 目标笔记尚未创建也照常写 `[[概念名]]`（Obsidian 标为待创建，全量铺开后自动闭合）。
4. 每篇正文里指向其他概念的链接 **2–6 条**为宜，自然嵌入行文，**不要堆在末尾**。

**核验脚本的白名单来源**：总索引里所有 `[[...]]` ∪ `--extra-whitelist` 指定项（辅助页）。

### 新概念要入链怎么办

本批新增的概念**必须先登记进总索引**（Stage 3 已做规划条目登记），核验才不报越界。若核验报越界但概念确实已规划 → 说明**索引登记漏了**，去补索引，不要改笔记。

## 6. 「多书对照」节的写法与取舍

| 情形 | 做法 |
|---|---|
| ≥2 本书覆盖同一概念 | 写该节，表格 `\| 视角 \| 来源 \| 要点 \|`，末附综合评述 |
| 只有 1 本书覆盖 | **整节省略**（多数笔记属于此类，不要硬凑第二本） |
| 两书结论**冲突** | 写进该节并**明确标注分歧**，不要静默择一 |

**常见连锁问题**：写了「多书对照」引用了 B4/T4，但顶部「来源行」只写了 B3 → 核验时报"来源行未覆盖"。用 `patch_sources.py` 自动求差集补齐。

## 7. 真实性红线

1. **必须实际读原文**。动笔前按定位表行号 `Read` 对应章节，读够再写（禁止凭记忆或凭先验写）。
2. **不得编造**：图号、公式、页码、结构名、参数值、厂商数据，一律以原文为准。**原文没有就不写**。
3. **原文矛盾** → 按"代码 / 原理图 / 实物 / 实际测量"为准，**并在笔记内注明原文两说**。不得擅自统一，不得静默择一。
4. **不得把主控凭先验给的参数当事实**（见 `pitfalls.md` §3）。
5. **原文未载的内容** → 标"待核实"，宁可空着也不臆造。子任务对未载项应主动上报。

## 8. 风格规则

| 项 | 规则 |
|---|---|
| 精简 vs 极简 | **精简 ≠ 极简**：删的是**冗余**（冗余修饰、重复解释、冗余展开），不是句法。完整句要带句号 |
| 分层 | 定义层用极短短语（可省句号）；解释层用完整句加句号 |
| 表格 | 优先于长段落 |
| 数学 | LaTeX `$...$`，**带单位**；公式变量单独提行 |
| 排版 | 不用花哨排版，**不要 emoji** |
| 语言 | 中文；术语首次出现给英文原名 |
| 缩进 | 库规范规定（该库为 4 空格缩进、**不用列表符号**） |

**动笔前必读风格基准样本**，不要凭本文件的描述想象风格。
