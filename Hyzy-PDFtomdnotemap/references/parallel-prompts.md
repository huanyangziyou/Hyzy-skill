## 1. 分组原则

| 原则 | 说明 | 反例 |
|---|---|---|
| **按同源材料切** | 同一本书的相邻章节 → 同组。避免两组抢读同一段原文 | 把「第5章 UDP」拆给两组 |
| **3–7 组** | 太少则单组上下文过载；太多则汇编与核验成本上升 | 一组 12 篇、或每组 1 篇 |
| **组名要能定位** | `<项目>-<主题>`，如 `p5-axi` / `p4-lwip` | `group1` / `子任务A` |
| **篇数不均没关系** | 按内容体量切，不按篇数平均。重篇（如 488 行的 UDP）可独占一组 | 强行每组 4 篇 |
| **新建与补强可混编** | 若某组同时新增+补强同域笔记，让一组做完，避免两个 agent 改同一文件 | 两组同时补强同一篇 |
| **跨书概念给同一组** | 同一概念要在两本书里对照（「多书对照」节）→ 必须同组 | 拆开导致各写一半 |

**规模参考**：一批 24–30 篇 → 切 7 组；一批 8–10 篇 → 切 3 组。

## 2. 单组 prompt 模板（可直接复制）

> 下列模板是**实测跑通过 7 组**的版本，填空即可用。**每条「铁律」都不要删**——它们各自对应一次真实翻车。

```
你是 <项目> 概念笔记生产子任务「<组名>」。只做本组清单，不做其他。

## 任务
按目标库规范，产出/补强以下笔记：
新增（<域目录>）：
1. <概念名1>
2. <概念名2>
补强（在原文件上追加内容，不删原文）：
- <域目录>/<文件名>.md

## 素材定位（用 Read --offset/--limit 精确取段，❌禁止整篇读源 md）
素材根：<素材根路径>
- <tag>：`<book md 绝对路径>`
  - <章节名> → 行 <start>–<end>
  - <章节名> → 行 <start>–<end>
图片目录：`<images 绝对路径>`（<n> 张，文件名形如 `<前缀>-<4位页>-<2位序>.png`）

## 必须先读的规范（自己去读，不要靠转述）
1. `<规范文件绝对路径>` —— 结构/命名/图片/链接/风格唯一标准
2. `<风格基准样本绝对路径>` —— 先读它校准密度与句式
3. `<总索引绝对路径>` —— 概念名逐字依据 + 链接白名单来源

## 图片
- 只用短嵌入 `![[文件名.png]]`，**严禁**相对路径。
- 说明列写清图意 + 原书图号；来源列写 `<tag> P.<页>`。
- 图片文件名必须来自上面 images 目录的**真实文件**，不得编造。
- 本组若无对应图：整节 `## 插图` 省略；或注明"借用邻章图 <文件名>（来源 P.x）"。

## 铁律
1. **必须实际读原文**再写；参数、页码、图号、寄存器名一律以原文为准，不得编造。
2. **原文自相矛盾时**：按代码/原理图/实物为准，**并在笔记内注明原文两说**（写"原文 X 处作 A、Y 处作 B，此处按 …为准"）。❌不要擅自统一、❌不要静默择一。
3. **原文未载的内容**：标注"待核实"，宁可空着，**绝不臆造**。本组若发现任务说明里给了素材查无实据的参数，**当场指出并拒绝写入**。
4. **借用了其他章节/其他书的参数**：逐行标明来源。
5. <tag> 系列素材若 OCR 残缺，涉及无出处的内容一律不写。
6. 「多书对照」节：**仅当 ≥2 本书覆盖同一概念时才写**；只有 1 本 → 整节省略。
7. 链接 `[[...]]` 只允许指向总索引里已列出的概念名；不得自创概念名。
8. 补强类：**只加不删**，先在原文件里定位应插入的 H3 位置，再追加。

## 交付
- 每篇一个文件，路径 `<库根>/<域目录>/<概念名>.md`（**文件名与上面清单逐字一致**，含全角括号）。
- 文件顶部三行元信息（`> 分类：` / `> 来源：` / `> 状态：已入库`），来源行必须覆盖「多书对照」里引用的所有书目。
- 每篇写完后**自己逐条过一遍 `references/note-contract.md` §9 自检清单**（在 `<skill>/references/note-contract.md`）。
- 全部完成后回传**汇报**（见下），不要只说"完成了"。

## 汇报格式（必须）
1. 【清单】`| 篇名 | 状态 | 行数 | 图 | 自检 |`
2. 【原文矛盾】每处：位置 / 原文两说 / 采信 / 依据
3. 【待核实】原文未载但读者可能关心的点
4. 【与派活说明不符】任务说明里与素材冲突之处（若有）
5. 【借用来源】从其他章节/书借用的参数及出处
```

### 模板里的 3 处最容易偷懒、也最致命的地方

| 位置 | 偷懒后果 |
|---|---|
| 「素材定位」给整本 md 路径而不给行号 | 子任务整篇读 → 上下文爆掉 → 后半段开始编 |
| 「必须先读的规范」写"按规范来" | 子任务不知道规范在哪 → 自造结构 → 核验全红 |
| 「铁律 2/3」被删掉 | 原文矛盾被静默择一 → 事实错误入库，且无留痕 |

## 3. 汇报协议（子任务必须回传的 4 类信息）

**为什么必须**：这 4 类信息构成后续所有批次的质量基线；缺了它们，主控只能看到"✅ 完成"，把事实错误当成果汇总上去。

| # | 信息 | 用途 |
|---|---|---|
| 1 | **原文矛盾清单** | 主控汇总成"矛盾台账"，决定是否需要用户裁定（如约束文件后缀 `.adc` vs `.xdc`） |
| 2 | **待核实清单** | 明确哪些是"原文没讲"而不是"我们漏了"，避免反复返工 |
| 3 | **与派活说明不符** | 反向纠正主控的错误假设（见 `pitfalls.md` §3 的 AD9248 案例） |
| 4 | **借用来源** | 跨书/跨章借用的参数逐行标源，保住"真实性红线" |

**主控动作**：收齐后合并成两张表回显用户：
- 矛盾台账：`| 位置 | 原文 A | 原文 B | 采信 | 依据 | 是否需裁定 |`
- 待核实清单：`| 概念 | 缺什么 | 素材出处 | 是否阻塞 |`

## 4. 主控汇编口径

- **不代写**：任何一篇正文都必须由子任务产出。主控发现缺漏 → 回派，不自己补。
- **不预判**：子任务未回报前，不要假设它写了什么。
- **不转发原始素材**：把产出**路径**转给下一环节，不要把整篇正文贴进消息（否则上下文爆炸）。
- **核验先行**：子任务自检 ≠ 验收。主控跑 `verify_notes.py` 后再宣布该组通过。
- **ID 重编号**：`TeamCreate` / 派生 agent 后 `TaskList` 的 ID 会变。每批开工先 `TaskList`，用当前 ID 更新状态，否则 `TaskUpdate` 静默失效。

## 5. 失败与回派

| 现象 | 处理 |
|---|---|
| 子任务回报"已完成"但核验报缺小节 | 回派，**把核验脚本的原始输出贴给它**（精确到行），不要只描述 |
| 子任务说素材里没找到某内容 | 先自查定位表行号是否给错；确实没有 → 接受它的"待核实"结论，不要逼它编 |
| 子任务拒绝写入你给的参数 | **它大概率是对的**（素材查无实据）。不要施压，改为在笔记里标"非本批素材" |
| 一组超时/失联 | 重派该组；已完成的篇目让它跳过（`SendMessage` 说明已有文件） |
| 两组改了同一文件 | 立即停一组，改为串行；已产生冲突则 `Read` 该文件人工合并 |

## 6. 实测规模参考

| P2 | 单本基础篇+工具链 → 4 域 | 3 | 9 新建 + 10 补强 | 19 项全 ✅ |
| P3 | 单本 ISP 篇 → 1 域 | 3 | 10 新建 + 6 补强 | 16 项全 ✅ |
