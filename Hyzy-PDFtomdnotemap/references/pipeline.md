## 0. 总览与耗时结构

| 阶段 | 主导成本 | 可压缩手段 |
|---|---|---|
| 0 契约勘察 | 读规范 + 总索引 + 样本 | 只读必要文件，不整库遍历 |
| 1 PDF→md | **墙钟**（一本 380 页约数分钟~十几分钟） | 后台跑；已转的跳过；数字版不用 OCR |
| 2 定位表 | 秒级 | 脚本一次生成，全流程复用 |
| 3 域映射 | LLM 推理 | 一次成表，勿反复修订 |
| 4 写笔记 | **token + 轮次**（主导项） | 并行分组；按行号取段；禁整篇读 |
| 5 核验 | 秒级 | 每批一次，合并修正 |
| 6 同步终校 | 秒级 | 收尾一次 |

**结论：真正的成本在 Stage 4。** 压缩 Stage 4 的杠杆按收益排序：
1. 分好组（同源章节一组，避免重复读同一段）
2. 给行号（子任务不搜索、不整读）
3. 让子任务自读规范（不由主控转述，避免信息损耗与二次确认）
4. 一次成文（禁止"写一半→问→再写"）

## 1. Stage 0 · 契约勘察

### 1.1 必须读的 5 类文件

```python
# 用 Python 探查（bash 的 ls/find 在本沙箱可能不可用）
import os, re
root = r"<库根>"
for dp, dn, fn in os.walk(root):
    if dp.count(os.sep) - root.count(os.sep) > 1:
        dn[:] = []; continue
    print("DIR:", dp)
    for f in fn:
        if f.startswith("_") or f in ("000-概念地图.md", "首页.md", "README.md"):
            print("     ", f)
```

| 类型 | 命名特征 | 读什么 |
|---|---|---|
| 写作规范 | `_规范-*.md` | 全篇（这是唯一执行标准） |
| 总索引 | `000-概念地图.md` / `00-总览与分类索引.md` | 概念清单、进度行、域列表、交叉表 |
| 域目录 | 形如 `10-器件与平台` | 目录名 + 各域篇数 |
| 风格基准 | 规范里点名的样本 | 整篇，校准密度/句式 |
| 素材区 | `<素材区>/` | 已有几本书、每本目录结构 |

### 1.2 库契约卡（回显给用户确认）

```markdown
## 库契约卡 · <库名>
- 库根：<路径>
- 规范：<文件路径>（✅存在 / ❌无 → 启用内置九小节兜底）
- 域：<n> 个 → <域目录清单>
- 现有笔记：<n> 篇（含辅助页 <m> 篇）
- 总索引：<路径>，进度行现状「X 已入库 / Y 规划中」
- 链接白名单来源：总索引 `[[...]]` + <辅助页清单>
- 风格基准：<路径>
- 素材区：<路径>，已有 <k> 本，结构 `<stem>/<stem>.md` + `images/`
```

### 1.3 闸门

- 规范存在 → 后续一律以规范为准，冲突时**不改规范去迁就 skill**。
- 规范不存在 → 明确告知用户"该库无规范，将按内置契约写」，并建议落一份规范文件。
- 域结构不清 / 总索引缺失 → **停下来问**，不要在无索引的库里批量产笔记（无法核验越界链接）。

## 2. Stage 1 · PDF → md

### 2.1 转换

```bash
PY="${PY:-python3}"                       # 脚本只需标准库
SKILL="${SKILL_DIR:?先解析 <SKILL_DIR>}"

# 数字版（默认，快）
"$PY" "$SKILL/scripts/convert_pdf2md.py" --src "<素材目录>"

# 扫描版
"$PY" "$SKILL/scripts/convert_pdf2md.py" --src "<素材目录>" --ocr-mode auto

# 只转其中几本
"$PY" "$SKILL/scripts/convert_pdf2md.py" --src "<素材目录>" --only "书名关键词1,书名关键词2"
```

**长任务放后台**（一本 380 页可能十几分钟）：

```
Bash(command="...", run_in_background=true)
```
完成后系统自动通知，**不要 sleep 轮询**。

### 2.2 复查

```bash
"$PY" "$SKILL/scripts/convert_pdf2md.py" --src "<素材目录>" --verify-only
```

输出每本：`mdKB / 图片数 / 行数 / H1 / H2 / 状态`。判据：

| 现象 | 处理 |
|---|---|
| md < 1KB | 转换失败 → 单本重跑，看 stderr |
| 图片数 = 0 但 PDF 明显有图 | 加 `--write-images`（脚本默认已开）；或 PDF 为纯矢量 |
| 行数明显偏少 | 可能是扫描版未 OCR → 改 `--ocr-mode auto` |
| H2 = 0 | 该 PDF 无书签/标题层级 → 定位表退化为按页搜索，需在派活时说清 |

### 2.3 素材库目录约定（沿用，不要自创）

```
<素材根>/
  <pdf 文件名去掉扩展名>/
     <同名>.md          ← 正文，`![](...)` 已被替换为相对引用
     images/
        <stem>-<4位页>-<2位序>.png
```

`pymupdf4llm` 会把空格与半角括号转成下划线 / 差异符，**图片名前缀必须从实际文件反推**（`build_locator.py` 已内置该逻辑），不要硬编码模板。

## 3. Stage 2 · 章节行号定位表

```bash
"$PY" "$SKILL/scripts/build_locator.py" \
      --src "<素材目录>" \
      --out "<素材目录>/_素材定位表.md"
```

带标签/书名/页数（推荐，书目编号是后续"来源行"的锚）：

```bash
# 写一个 tagmap.csv：stem,tag,显示名,页数
"$PY" "$SKILL/scripts/build_locator.py" --src "..." --out "..." --tag-map ".../tagmap.csv"
```

产物结构：

```markdown
## T2《平台基础篇》
- 文件：`<素材目录>/<stem>/<stem>.md`
- 图片目录：`...\images`（312 张，文件名形如 `3_1_01_....pdf-<4位页>-<2位序>.png`）
- 页数：380

| 行号 | 层级 | 标题 |
|---|---|---|
| 27 | H2 | 第1章 开发环境 |
| 41 | H3 | 1.1 TD 安装 |
```

**用法（关键）**：派活时只把该组相关行号摘给子任务：

```
素材定位（用 Read --offset/--limit 精确取段，禁止整篇读）：
- T2 第2章 键控LED → 行 1240–1580
- T2 第5章 UART → 行 4310–4700
图片目录：`<素材目录>/<stem>/images`，前缀 `T2stem.pdf-`
```

### 页码反推规则（只在书里验证过才用）

- 一般规律：`<stem>.pdf-<4位页>-<2位序>.png` → 页码 = 4 位数字。
- ⚠️ **不是所有书都成立**：B4 系有约 +12 偏移。**动笔前从已知文字页抽 1 张图核对**，偏移不确定就不写具体页码，只写章节。

## 4. Stage 3 · 域级映射分组 + 分批

### 4.1 映射表（先出表，再动手）

```markdown
| 教材 | 章节/主题 | 目标域 | 处置 | 篇数 |
|---|---|---|---|---|
| T3 | 第2–3章 以太网物理层 | 45-通信与网络 | **新增域** | 4 |
| T3 | 第5章 UDP | 45-通信与网络 | 新增 | 1 |
| T3 | 第4章 图像传输 | 70-图像与视频 | 补强 | 0(+1) |
| T5/T6 | PS 基础/调试 | 95-FPSoC软硬协同 | **新增域** | 4 |
```

**处置三档**：`新增`（写新笔记）/ `补强`（在已有笔记上追加内容）/ `单列`（原为某篇的一节，内容够厚独立成篇 —— 需用户裁定）。

### 4.2 规划文件模板

`<_规划-<资料集>融合方案.md>` 放库根或索引目录：

```markdown
# <资料集> 融合方案

## 一、目标库现状
（库契约卡摘要 + 现有篇数/域数/进度行）

## 二、域级映射
（4.1 的表）

## 三、批次计划
| 批次 | 范围 | 产出一 | 状态 |
|---|---|---|---|
| P0 | 结构先行（建域/改规范/登记规划条目） | — | ⬜ |
| P1 | T1 语法篇 → 20-HDL + 30-方法论 | 10 新建 + 8 补强 | ⬜ |
| ... | | | |
| P6 | 全库终校 + 索引同步 | — | ⬜ |

## 四、素材编号规则
（如：参考书 B0–B5，平台教程 T1–T6，互不占用）

## 五、决策点
- [ ] 新增域？
- [ ] 本机适配口径？
- [ ] 执行节奏？
```

### 4.3 分批原则

| 原则 | 说明 |
|---|---|
| **P0 永远先做结构** | 建域目录 → 改规范 → 登记规划条目 → 建规划文件 → **校验规划清单可解析**（无 Windows 非法字符 / 无重名 / 与旧笔记不冲突）。P0 只改结构，不写正文。 |
| 每批 = 一个主题域 or 一组同源章节 | 8–30 篇为宜；太小组装成本高，太大核验难定位 |
| 批内再切 3–7 组 | 按"同源材料"切（同几章 → 同组），避免两组抢读同一段 |
| 每批结束**停下等确认** | 用户既定节奏，不要自作主张跨批 |
| 核验不过不进下一批 | 见 Stage 5 |

### 4.4 需提问卡确认的三类决策

1. **域结构**：新增/合并/改名域 → 必问。
2. **口径**：目标库有历史平台/历史版本口径时，"新笔记按新口径、旧笔记是否随动改" → 必问。
3. **节奏**：分批逐步确认 / 一次跑完 → 必问（默认分批）。

## 5. Stage 4 · 并行子任务写笔记

细则见 `references/parallel-prompts.md`。此处只给主控动作序列：

1. `TeamCreate`（命名 `<项目简称>-fusion` 之类）→ 团队与任务清单就位。
2. **`TaskList` 确认当前 task ID**（建团队后会重编号，先用 ID 会失效）。
3. 按组 `Agent(subagent_type="general-purpose", name="<组名>", prompt=...)` 并行派发；**同一消息内发多个调用**才算真并行。
4. 每组回报后 → `SendMessage` 收结果 → 汇总。
5. 全部回报 → 跑 Stage 5 核验 → 不合格则回派修正（带具体缺失项）。
6. 收尾：`SendMessage(type="shutdown_request")` 逐组关停 → `TeamDelete`。

**主控只做编排与汇编**：不代写任何一篇正文。子任务产出未回传前，不得据自己的理解"补写"。

## 6. Stage 5 · 脚本核验

### 6.1 批次清单 JSON

```jsonc
{
  "NEW": {
    "45-通信与网络": ["以太网 MAC 与 PHY", "MDIO 管理接口"],
    "90-系统与工程": ["基于 UDP 的 AD7606 采集方案"]
  },
  "PATCH": [
    "70-图像与视频/视频接口.md",
    "40-存储与总线/Block RAM.md"
  ]
}
```

`NEW` 用「域目录: [概念名数组]」，`PATCH` 用「域目录/文件.md」相对 `--base` 的路径。

### 6.2 运行

```bash
"$PY" "$SKILL/scripts/verify_notes.py" \
  --base "<库根>" \
  --batch "<库根>/_batch-P4.json" \
  --img-root "<库根>/<素材区>" \
  --img-root "<素材目录>"
```

### 6.3 判读

| 输出 | 含义 | 动作 |
|---|---|---|
| `✅ 域/篇名 (行数, 图n, 链m)` | 全过 | 记账 |
| `缺小节 [...]` | 必备小节缺失 | 回派补齐 |
| `断图 [...]` | 图片不存在 | **先查"搜索根"列表是否覆盖素材区**；补 `--img-root "<素材目录>"` 后重跑。仍是真断图才去换图 |
| `越界链接 [...]` | `[[...]]` 不在白名单 | 概念名打错 / 需先登记进总索引 / 改纯文本 |
| `多书对照仅 ['T3']` | 只有 1 本书覆盖却写了该节 | 按规范：删该节（规范原文「仅当 ≥2 本才写」） |
| `插图节内含 H3` | H3 夹在「插图」与下一节之间 | 移回「细节」节末尾 |
| `缺来源行` | 无 `> 来源：` / YAML `来源:` | 补来源 |

**修正纪律**：把一轮里发现的所有问题**合并成一次修正**回派，不要"发现一个改一个再重跑"（轮次是主要成本项）。

## 7. Stage 6 · 地图同步 + 全库终校

### 7.1 索引同步清单

- [ ] 规划条目 `⬜` → `✅`，**章节号按实际内容校正**
- [ ] 进度行 `X 已入库 / Y 规划中` 更新
- [ ] 新增域在域清单/域说明处登记
- [ ] 交叉热力表：行方向过粗时按实际拆分（如把「以太网/UDP」拆成 7 行）
- [ ] 来源行补该批次书目（`patch_sources.py` 可自动求差集）
- [ ] 规划文件批次表状态列 `⬜` → `✅`

### 7.2 一致性核对（必做，且必须解释差异）

```python
# 索引 ✅ 数 vs 磁盘实际篇数
```
- 两者相等 → ✅
- 差 n 篇 → **必须给出解释**（常见：辅助页/术语对照表/模板/README 不入概念网络）。**无法解释的差异 = 幽灵条目或漏登记，必须查清**。
- 同时反查：`⬜` 条目是否有磁盘文件已存在（= 重复登记）、是否有同名重复。

### 7.3 全库终校

```bash
"$PY" "$SKILL/scripts/fullcheck.py" --base "<库根>"
```

输出两类：

| 类 | 判定 | 处理 |
|---|---|---|
| **A 本次融合范围内** | 除历史成因外的任何缺陷 | **必须修到 0** |
| **B 历史遗留** | 全部缺陷都由口径确立前的原因造成（旧分隔符写法 / 旧附加节 / 多书对照仅 1 本 / 非标准 H2） | **列表交用户裁定，不得擅自批量改** |

> **不要误报为问题**：同一张图片被多篇笔记引用属于**有意设计**（一个框图服务多个概念），`fullcheck.py` 会列出来仅供参考，**不计入缺陷**。

## 8. 增量开发（库已存在时再融合一批）

库不是新建、只是再加一批教材时：

| 阶段 | 差异 |
|---|---|
| 0 | 契约勘察**走全流程**（规范可能已更新） |
| 1–2 | 同标准 |
| 3 | 映射时**先查是否已有该概念**：有 → 补强（改旧文件）；无 → 新增。**补强清单必须先给用户确认** |
| 4 | 派活时明确「这是已有笔记的补强，只加不删」；要求子任务先读旧文件再动笔 |
| 5 | 加跑 `PATCH` 清单（补强篇也要核验） |
| 6 | 同时管「规划条目清零」与「存量笔记未动」两件事 |

## 9. 命令模板汇总

> 占位符解析规则见 SKILL.md「环境自适应」与 `references/env-adapt.md`：`<PY>`/`<SKILL_DIR>` 自解析，`<素材目录>`/`<库根>` 必须问用户。不要用 `$HOME`（Git Bash 下常为空 → 路径断裂 → 首跑失败需重跑）。

```bash
PY="${PY:-python3}"                    # 任意 Python 3；PDF 解析器由 --py / 自动探测决定
SKILL="${SKILL_DIR:?先解析 <SKILL_DIR>}"
S="$SKILL/scripts"

# Stage 1
"$PY" "$S/convert_pdf2md.py" --src "<素材目录>"                    # 转换（长任务加 run_in_background）
"$PY" "$S/convert_pdf2md.py" --src "<素材目录>" --verify-only       # 复查

# Stage 2
"$PY" "$S/build_locator.py" --src "<素材目录>" --out "<素材目录>/_素材定位表.md"

# Stage 5
"$PY" "$S/verify_notes.py" --base "<库根>" --batch "<批次.json>" \
      --img-root "<素材目录>" --img-root "<库根>/<素材区>"

# Stage 6
"$PY" "$S/fullcheck.py" --base "<库根>"
"$PY" "$S/patch_sources.py" --root "<库根>"             # dry-run
"$PY" "$S/patch_sources.py" --root "<库根>" --apply     # 需用户确认
```
