## 1. 环境 / 工具链坑

| 坑 | 现象 | 对策 |
|---|---|---|
| **解释器缺库** | `ModuleNotFoundError: pymupdf4llm` | 转换类脚本必须用**带 `pymupdf4llm`（Excel 还需 openpyxl）的解释器**：`convert_pdf2md.py` 省略 `--py` 会自动探测，探不到按 `references/env-adapt.md` 提示询问用户。不要假定任何固定路径 |
| **bash PATH 坏** | `ls` / `grep` / `find` / `dirname` → `command not found`；`cd: null directory`；但 stdout 可用 | 文件探查改用 Python（`os.walk` / `os.listdir`） |
| **Glob 中文+半角括号路径无返回** | 形如 `<素材目录>/某课程(1)/` 这类含中文与半角括号的路径下 Glob 返回空，误以为文件不存在 | 用 `os.walk` 或 `os.listdir` 代替 |
| **内联 `python -c` 反引号被吞** | 命令静默截断或语法错 | 写临时 `.py` 文件再跑 |
| **`$HOME` 在 Git Bash 下为空** | 脚本路径断裂，首跑失败需重跑 | 命令模板**全部写绝对路径** |
| **中文路径 + Windows 控制台编码** | `UnicodeEncodeError` | 脚本内 `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')`（本 skill 脚本已内置） |

## 2. 转换与素材坑

| 坑 | 现象 | 对策 |
|---|---|---|
| **图片名前缀模板不准** | 手写 `stem + "-"` 前缀拼图片名 → 找不到文件 | 从实际文件名**正则反推**前缀。转换器会把空格/括号替换为下划线化形式（如 `..._课程基础篇-1-.pdf-0037-08.png`），硬编码模板必错 |
| **页码偏移** | 用 `<4位数字>` 直接当页码，写进笔记后与实物不符 | 页码推导规律**只在验证过的书上成立**（见过某书系约 +12 偏移）。首次使用前**抽一张已知页的图核对**；不确定就只写章节 |
| **扫描版未 OCR** | md 体积极小、正文空洞 | `--ocr-mode auto`；纯数字版用 `--ocr-mode never`（快、无识别错字） |
| **纯矢量 PDF** | 图片数 = 0 但书里明显有图 | 检查是否 `--write-images`（默认已开）；若确实无位图，笔记里省略「插图」节 |
| **教程里"无图"被误认为漏做** | 校验发现某几章没有图，怀疑转换丢图 | 先独立复核（脚本统计图分布在哪些章），确认"确无图"→ 对应笔记省略「插图」节或注明借用邻章图，**不是漏做** |
| **素材目录被 Obsidian 排除** | 全库短嵌入 `![[...]]` 全部断图 | **绝不把素材目录加进 Obsidian 排除列表** |

## 3. 派活坑（最容易出事实错误）

### 3.1 ⛔ 主控凭先验写参数 → 子任务照抄（真实案例）

**事故**：派活时凭先验写下「AD9248 是双通道 14 位 ADC」，要求写进笔记。而**素材全库只提过这个名字，没有任何参数**。

**正确结果**：子任务**拒绝写入**，只在备注标「非本批素材、仅供选型参考」。

**教训（双向）**：
- 主控派活时**只写素材能支撑的内容**，不要把自己的知识当事实。
- 子任务**有权也有义务反驳**派活说明；发现与素材不符要当场指出。
- 从别处（其他章节/其他书）借参数**必须逐行标来源**。

### 3.2 ⛔ 把甲书的话当成乙书的话

**事故**：派活时用"英文路径"描述某书要求。原文实际只说「路径不能有下划线以外的字符」，**并没有"英文路径"这个措辞**（那是另一本书的说法）。

**正确结果**：子任务按原话表述，未把甲书的话冒充成乙书的。

**教训**：措辞也要忠于原文。**跨书迁移结论时必须显式标注来源书号**。

### 3.3 ⛔ 让子任务整篇读源 md

后果：380 页一本书整读一次，上下文就满了，后半段开始编造。
对策：**只给行号区间**，明确写「用 Read --offset/--limit 精确取段，❌禁止整篇读」。

## 4. 笔记结构坑

| 坑 | 现象 | 对策 |
|---|---|---|
| **H3 夹在「插图」与下一节之间** | 结构错位，「插图」节被 H3 内容污染 | 所有 H3 归「细节」节末尾。曾出现 1 处孤例（「选型权衡」），已修 |
| **「多书对照」只写 1 本书** | 规范要求 ≥2 本才写 | 只有 1 本 → **整节省略**。核验已加此项（`verify_notes.py` / `fullcheck.py`） |
| **来源行未覆盖「多书对照」引用书目** | 顶部 `> 来源：` 只写 B3，正文却引用了 B4/T4 | 用 `patch_sources.py` 求差集补齐（自动从对照表第二列提书目） |
| **分隔符写法不一致** | `## 本机适配·赛题关联` vs `## 本机适配 / 赛题关联` | 按目标库规范统一；历史遗留的**列表交用户裁定，不擅自批量改** |
| **文件名与索引不逐字一致** | 索引写全角括号，文件用了半角 | 产前用脚本机器比对清单，别靠眼看 |
| **半角 `/` 进文件名** | 文件名含 `腐蚀 / 膨胀` → Windows 非法字符 | 多值并列一律用顿号 `、` |
| **误报**：同一图片被多篇引用 | 终校列出多篇共用同一图 | **这是有意设计**（一个框图服务多个概念），不计入缺陷 |
| **误报**：终校把历史写法判为缺陷 | A 类里混入"口径确立前"的旧写法 | 终校已分 A/B 两类；B 类需**全部缺陷都由历史成因造成**才归入 |
| **误报**：图片搜索根没覆盖素材区 → 全量假断图 | 泛化脚本首次运行报"178 篇需修"；实际是图片索引只搜了笔记目录，而图片都在 `<素材区>/`、`<教材目录>/` 等素材区 | 核验/终校默认会**自动加入库根 + 库的上一级**作为搜索根；若素材在别的盘/更上层，必须显式补 `--img-root`。**看到大面积断图先查搜索根，不要动笔记** |

## 5. 索引同步坑

| 坑 | 现象 | 对策 |
|---|---|---|
| **进度数对不上文件数** | 索引 ✅ 195 ↔ 磁盘 196 | 找出那 1 篇是什么（通常是辅助页/术语对照表/模板/README），**在汇报中明确解释**。无法解释的差异 = 幽灵条目或漏登记 |
| **规划条目章节号照抄规划** | 规划时猜的章节号与正文实际不符 | 同步时按**实际内容**校正章节号 |
| **新增域没有入口** | 新域/新辅助页在索引里无引用入口，成孤岛 | 建域时同步在索引里加域说明与入口链接 |
| **重复登记** | 同一概念既在 ✅ 又在 ⬜，或磁盘已有同名文件 | P0 阶段就机器校验：规划清单 vs 磁盘文件，查重名与非法字符 |

## 6. 团队协作坑

| 坑 | 现象 | 对策 |
|---|---|---|
| **task ID 重编号** | `TeamCreate` / 派生 agent 后，旧 ID 的 `TaskUpdate` 静默失效 | **每批开工先 `TaskList` 确认当前 ID**，必要时重建 TaskCreate |
| **主控代写** | 主控"顺手"补了某篇 → 破坏职责边界 | 主控只编排；缺漏一律回派 |
| **子任务自检当验收** | 子任务报 ✅，实际缺小节/断图 | **主控必须跑核验脚本**再宣布通过 |
| **把整篇正文贴进消息** | 上下文爆炸 | 消息里只传**路径** |
| **回派时只描述问题** | 子任务不知道具体缺哪 | 把核验脚本**原始输出**贴给它 |
| **忘记关停团队** | 残留 agent 占资源 | 收尾 `shutdown_request` 逐组关停 → `TeamDelete` |

## 7. 原文矛盾处理协议

**原则：以代码 / 原理图 / 实物 / 实测为准 + 在笔记内注明原文两说 + 不擅自统一 + 上报待裁定。**

| 矛盾类型 | 采信顺序 | 实例 |
|---|---|---|
| 正文 vs 代码 | **代码** | 数据位宽正文写 32、代码 `#define ... 64` → 以 64 为准 |
| 正文 vs 原理图 | **原理图**（必要时直接读图核实） | 启动拨码正文 `OFF-OFF-ON` vs 原理图 `ON-ON-OFF` → 读图确认 ON-ON-OFF |
| 引脚表 vs 开发板手册 | **pinlist / 原理图** | KEY 引脚手册写 K14/J14（与网口复用冲突）→ 采用 pinlist 的 K19/J19 |
| 注释 vs 代码逻辑 | **代码逻辑** + 标注注释错位 | CRC 判据注释与代码错位（`32'hc704dd7b` 实为校验通过） |
| 标题 vs 框图实际 | 以**框图/实际方案**为准 | 标题写「HDMI 采集显示」，框图里源是测试图案、无 HDMI_RX → 实为 TPG 模拟源 |
| 正文复制未改（跨篇串味） | 以**标题/实际方案**为准 | 某篇正文写「把 X 采集到的数据…」与邻篇逐字相同；另一篇正文写了「通过 ADC 采集」但该方案无 ADC |
| 结论真的无法判定 | 两说并列 + 标"待核实" + **上报用户裁定** | 约束文件后缀 `.adc`（甲书 17 处）vs `.xdc`（乙书 5 处）—— 与库内"约束非 XDC"口径冲突，两写法并存带出处标注 |
| 位宽/数值与标准不符 | 若与器件口径自洽 → 判为**器件口径**并标待核实 | AXI `AxLEN` 4 bit（标准 8 bit）—— 与同书"直连最大 16 拍"自洽 |

**留痕格式**：

```markdown
> ⚠️ 原文两说：<位置A> 作 `<值A>`，<位置B> 作 `<值B>`；此处按 <依据> 取 `<值>`。
```

**矛盾台账要回显用户**，特别是需要用户裁定的事项（如上面 `.adc` vs `.xdc`）。

## 8. 8 条翻车对照表

| # | 翻车 | 后果 | 一句话对策 |
|---|---|---|---|
| 1 | 跳过契约勘察直接写 | 结构全错，整批返工 | Stage 0 先读规范 + 索引 + 样本 |
| 2 | 主控凭先验给参数 | 事实错误入库 | 素材没写的就不写；子任务要敢反驳 |
| 3 | 不给行号让子任务自己找 | 整篇读 → 上下文爆 → 编造 | 定位表 + `--offset/--limit` |
| 4 | 子任务自检当验收 | 缺陷进入成果汇总 | 主控跑 `verify_notes.py` |
| 5 | 发现一个错就改一个再重跑 | 轮次爆炸（主要成本项） | 合并成一轮修正 |
| 6 | 原文矛盾静默择一 | 无留痕、无法追溯 | 注明两说 + 上报待裁定 |
| 7 | 终校把历史写法当缺陷 | 误报 20+ 篇，掩盖真问题 | 分 A（本次）/ B（历史遗留） |
| 8 | 索引进度数与文件数不符还不解释 | 幽灵条目/漏登记长期潜伏 | 差异必须给出明确解释 |
