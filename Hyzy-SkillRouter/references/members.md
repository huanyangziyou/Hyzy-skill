# 治理层成员清单

> **调用任一成员之前必读。** 本文件给的是**调用前要知道的最小信息**：第一步、能做什么、不能做什么、依赖什么、已知坑、与相邻成员的差异。判据、公式、完整规则清单在各自 `SKILL.md`，这里不重写第二份。
>
> **按处境路由，不按触发词。** 触发词在各自 frontmatter 的 `description` 里，而五个成员的触发词大量重叠——查触发词不如查「你现在处在哪一步」。这也是本文件不从各自 `description` 抄触发词的原因。
>
> 与 `SKILL.md` 同步于 2026-11-20。改本文件或改任一成员的流程后，两处要一起看。

## 总表

| 成员 | category | 是否写文件 | 产物 |
|---|---|---|---|
| `find-skills` | skill-dev | 否，全程只读 | 候选清单 + 推荐 |
| `Hyzy-startupSkill` | skill-dev | 是，新建 skill 包 | 新 skill 包 |
| `Hyzy-skillPortable` | skill-dev | 是，改造已有包 | 改造后文件包 + 变更台账 + 证据 |
| `Hyzy-VerifyGate` | meta | 否，只跑命令 | 证据汇报 |
| `skill-library-governance` | meta | 否，全程只读 | 审计报告 + 观察名单 |

## 一、`find-skills`

**第一步**：确认检索范围——用户是只在本机库找，还是允许查开放目录。范围没定就问一句，别默认联网。

**做什么**：把模糊需求映射成可核验的候选 Skill 清单。三层检索——本地库 → 开放目录（`www.skills.sh` 排行与 GitHub API）→ 源码 / 中文源。

**不做什么**：不安装、不写文件、不刷新索引、不提交 git。默认只列不装。

**依赖**：第 1 层只用本地文件系统；第 2 层需要联网与 `npx`；第 3 层需要联网。断网时只能走第 1 层，且要明说「只查了本地」。

**已知坑**：

- 第 1 层本地检索依赖 `<库根>/INDEX.md`；没有索引时退化为扫 `<库根>/*/SKILL.md` 的 `name` 与 `description`。**只有 `skills/<name>/SKILL.md` 的仓库（例如本仓库）没有 `INDEX.md`，会直接走降级扫描——这是预期行为，不是故障，不要因此报错或中止。**
- `npx --yes skills find` 实测易超时，20s 未返回按失败降级，不要反复重试。
- 候选清单不等于「已安装」。用户没点名之前不给安装。
- 单一中文词命中 0 不算完成检索，必须做中英同义扩展后再判「本库无可复用技能」。

**与相邻成员的差异**：只解决「有没有」，不解决「怎么造」。命中可复用的就停，交回用户决定。

## 二、`Hyzy-startupSkill`

**第一步**：查现成——先走一次 `find-skills`，确认没有可复用的包再动手造。

**做什么**：从需求到可用 skill 包的全流程——复盘记忆、三问选型、最轻包设计、行为规则与泛化门、四级验证、安装与刷新索引。

**依赖**：对库根有写权限（要新建目录）；若库里有 `tools/refresh_index.py` 则需能运行 Python。

**不做什么**：不做一次性问答、普通文档、翻译；用户只想了解概念时不硬造。

**已知坑**：

- 会先调 `find-skills`。已确定要造且明知没有现成方案时可直接进本流程，但要在收尾说明「跳过查现成」的理由。
- 泛化门是它最容易被跳过的一步：一个只服务单次任务的流程不该被封成 skill。

**与相邻成员的差异**：造新的。改造已有包走 `Hyzy-skillPortable`。

## 三、`Hyzy-skillPortable`

**第一步**：备份——把待改的包整份打包到库外，并核实包里文件数与源一致。备份没成就停，不要开始替换。

**做什么**：A–F 六类探查 → 物理备份 → 逐处 assert 替换 → 保真四道，产出可移植或可公开版本。

**依赖**：对目标包有读写权限；备份目标目录有足够空间；行为测试需要能另起一个不知情的代理。

**不做什么**：不在没备份时批量替换；不为了「通用化」删掉真正有用的本机默认值；不把设计优势说成已验证优势。

**已知坑**：

- 两个必停点：动手前的方案卡、删除 / 改名 / 覆盖前点名到具体路径。
- 「硬编码」的判据是**无检查、无回退、无条件信任**；具体路径 + 先 `stat` + 缺失降级是好实践，不要当罪证删掉。
- 行为测试（派不知情代理读改后的文件）经常能发现替换脚本发现不了的残留引用与内部矛盾。
- 只报实际达到的证据等级：结构校验 < 保真校验 < 行为测试 < 对照评测。

**与相邻成员的差异**：只改一个包。整库体检走 `skill-library-governance`。

## 四、`Hyzy-VerifyGate`

**第一步**：写清「这一轮到底要证明什么」——把待验结论拆成可执行的具体检查项。拆不出来说明结论本身还不成立，先回去做完。

**做什么**：任何「完成 / 已修复 / 已通过 / 已上传 / 已安装 / 已公开」结论前的五步闸门。步骤名只作对齐用，每步的判定标准在它自己的文件里。

**产出「证据三件套」= 命令 + 关键输出 + 退出码。** 三者缺一即视为没跑过。三件套齐了也不等于结论成立——判定标准仍以它自己的文件为准。

**依赖**：能跑命令、能读回真实输出。只有推测没有命令可跑时，它的输出就是「未核实」+ 阻断点，这也是合法结果。

**不做什么**：不替代具体验证命令；不把推测补进结论；不用「绑定成功」「命令没报错」替代结果证据。

**已知坑**：

- 退出码 0 不等于业务结果达成。
- 「上次跑过」不算本轮证据，必须本轮重跑。
- partial 要列出未完成的具体项，不宣称全部成功。

**与相邻成员的差异**：横切闸门，不是流程的一环。其他四个成员交付前都要过它。

## 五、`skill-library-governance`

**第一步**：摸家底——列出库根下所有目录、每个目录是否有 `SKILL.md`、文件数与最后修改时间，先得出一张清单再谈诊断。

**做什么**：库级全量体检——摸家底、标功能重叠与内容残次、出观察名单与「保留 / 合并 / 暂存淘汰」三选一建议。

**依赖**：只需读权限。它不写、不删、不移动，所以**没有备份环节**——处置动作全在它之外。

**不做什么**：全程只读；不删除、不移动、不改名；不给「使用率」这类没有数据支撑的结论。

**已知坑**：

- 「长期未用」没有真实调用日志，只能用「人工自认 + 上次审计时间戳」近似，必须如实标注为近似值。
- 依赖引用检查要区分**真实缺失**与**示例占位符**（`xxx.jsx`、`assets/google.svg` 这类是文档示例，不是缺失）。
- 编码问题必须用 Python 精确 decode 判断，不要凭终端 grep 的中文显示下结论——终端 locale 会把正常 UTF-8 渲染成乱码。
- 删除类建议只提不做，即便用户说「帮我清一下」。

**与相邻成员的差异**：看整库、只读、出报告。改单个包走 `skillPortable`。

## 六、成员缺失时

按当前库实际存在的成员走。上表中某个成员不存在时：

1. 明确告诉用户「未安装 X」，不要把相近成员顶替成它。
2. 给出替代路径，通常是「用领域 Skill 直接做」或「先造一个（`Hyzy-startupSkill`）」。
3. 若缺失的是 `Hyzy-VerifyGate`，仍要执行同样的证据要求，只是没有专门的 skill 承载——在回复里直接写命令、输出、退出码。

## 七、成员在但跑不动时

目录存在不等于能跑（缺依赖、断网、无写权限、`npx` 超时）。遇到时按「降级 + 明说」处理，不要静默换做法：

| 情况 | 怎么办 |
|---|---|
| `find-skills` 断网 / `npx` 20s 未返回 | 只做第 1 层本地检索，回复里写明「只查了本地，未查开放目录」，不反复重试 |
| `skill-library-governance` 无读权限的目录 | 跳过该目录并在报告里单列，不把它当「已检查且干净」 |
| `Hyzy-skillPortable` 备份写不进去 | **停**。没有备份就不做批量替换，任何理由都不例外 |
| `Hyzy-VerifyGate` 要验的东西没法跑命令 | 结论写「未核实」并给出阻断点，不用推测补位 |

**共同原则：能力缺失要显式降级并标注，不能假装做到了。** 这比「结果不完整」更糟——不完整还能补，假装过就无从发现。
