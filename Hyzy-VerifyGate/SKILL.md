# Hyzy-VerifyGate · 完成前验证闸门

> 证据先于断言。违反字面，就是违反精神。

> **找出该跑的命令之前必读 `references/env-adapt.md`**（校验资产定位、证据标准、验证动作的权限边界）。

## 铁律

```
NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE
```

本轮没跑过验证命令，就不能说「通过 / 完成 / 已修复 / 已上传 / 已安装」。
不得用「绑定成功」「未找到用量」「命令没报错」「上次跑过」替代结果证据。

## Gate 五步（缺任一步 = 未验证）

1. **IDENTIFY** — 找出能证明该结论的**完整命令**是什么。
2. **RUN** — 本轮重新跑一次，跑 FULL，不是片段、不是复用上次结果。
3. **READ** — 读全输出、退出码、失败计数、关键字段值。
4. **VERIFY** — 输出是否真的支持该结论？否 → 如实报实际状态与缺口；是 → 带证据下结论。
5. **ONLY THEN** — 才允许表达完成或满意。

跳过任一步 = 撒谎，不是验证。

## 证据对照表

| 结论 | 必须 | 不算 |
|---|---|---|
| 校验通过 | 本轮 `validate_*.py` 完整输出：0 错误 0 警告 | 上次跑过 / "应该没问题" |
| 文件已生成 | 实测路径 + 字节数 + 内容抽样 | 写入命令退出 0 |
| 链接无死链 | `verify_links.py` 全量输出 | 只抽查几条 |
| 上传成功 | 服务端状态 + 最近上传时间戳 | 绑定成功 / 未找到用量 |
| 后台任务已装 | 系统任务状态查询 + 下次运行时间 | install 命令退出 0 |
| 子代理完成 | 独立复核产出物 / diff | 子代理自报 success |
| 图/渲染正常 | 实际渲染检查 | SVG 语法通过 |
| 数量/哈希一致 | 本轮文件计数 + MD5/SHA256 实测 | 按预期值推算 |
| 需求已满足 | 逐条对照清单核完 | 校验脚本通过 |

## Red Flags（出现即 STOP）

- "应该可以了" / "大概率" / "看起来" / "似乎" / "应该是"
- 验证前表达满意（"好了""搞定""完美""大功告成"）
- 只做了部分检查就外推整体
- 信任子代理、客户端、安装器的自报成功
- "就这一次" / "时间紧先交付" / "累了想收工"
- 任何暗示成功的措辞，但本轮没跑验证

## 反合理化表（本土版）

| 想法 | 现实 |
|---|---|
| "上次跑过，没改动" | 本轮重跑 FULL |
| "退出码 0 就是成功" | 退出码 0 不等于业务结果达成 |
| "脚本没报错" | 要读输出，不是只看没异常 |
| "时间紧，先报完成" | 先报实际状态 + 缺口 |
| "这是个小改动，不用验" | 小改动也要一条命令 |
| "partial 也算传完了吧" | 列出未完成项，继续后续步骤，不宣称全量 |
| "工具被拦，就不提了" | 明确写「未验证」及阻断点，不用推测补结论 |

## partial / 失败处置

- **partial**：报告未完成的具体项（日期 / 文件 / 条目），照常继续后续安装或步骤，**不宣称全部成功**。
- **状态已保存但动作失败**：排查后用专用重试命令（如 `upload`）重试，**不重复生成凭证或接入码**。
- **无法验证**（工具被拦、权限不足、环境限制）：明确写「未验证」+ 原因，禁止用推测补结论。
- **汇报字段被要求裁剪**时：仍须保证每个保留字段有证据支撑。

## 交付汇报格式

每项结论后附证据三件套：**命令 + 关键输出 + 退出码**。
无法核实的项单列「未核实」并写明阻断点，不混入成功结论。

## 阶段收尾与决策日志

每个阶段（定位完 / 执行完 / 验证完）结束，向当日日志追加一条，四元组缺一不可：

| 字段 | 要求 |
|---|---|
| 关键问题 | 本阶段问过的关键问题，一次列全，不拆多轮 |
| 用户原话 | 含糊回答保留原话，不改写、不美化 |
| 因此改变 | 触发了什么决策 / 产物 / 范围变化；无改变写「无」 |
| 时间戳 | 阶段起止真实时间；无计时则不写，禁止估算或调用数替代 |

- 日志位置 `.workbuddy/memory/YYYY-MM-DD.md`（append-only），**不新建 `案例日志.md`**。
- 下一阶段开始时先读当日日志，避免重复问、重复猜。
- 与「交付汇报格式」分开：那里是给用户看的证据，这里是给未来会话看的决策依据。

## 边界

- **不替代二次确认原则**：删除、修改、移动、重命名、覆盖仍须先向用户确认。
- 不为「看起来完成」跳过任何一步。
- 验证命令本身优先只读；若验证动作需改动用户文件，须已获该动作的授权。
- 与 `SOUL.md` 的操作原则冲突时，以 `SOUL.md` 为准。
