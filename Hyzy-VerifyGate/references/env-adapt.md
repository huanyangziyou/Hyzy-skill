# 环境自适应（VerifyGate）

> **何时读**：Gate 第二步「找出该跑的命令」时必读；准备宣称完成之前复核第三节。

本 skill 不含产物路径、不含解释器探测，但**依赖其它 skill 的校验脚本存在**。所以环境自适应的核心是「先确认工具在，再宣称验过」，而不是解析路径。

## 一、校验资产在哪

| 资产 | 归属 | 找不到时 |
|---|---|---|
| `validate_md.py` | `Hyzy-rawprocess/scripts/` | 如实标注「该校验未跑」，不得用其它检查冒充 |
| `validate_svg.py` | `Hyzy-HDLtoSVG&Explain/scripts/` | 同上 |
| `verify_links.py` | 目录重组/移动后死链复核 | 同上 |
| `validate_methpath.py` | `Hyzy-KnowtoMethPath/scripts/` | 同上 |
| `verify_notes.py` / `fullcheck.py` | `Hyzy-PDFtomdnotemap/scripts/` | 同上 |
| `validate_skill.py`（若有） | `Hyzy-startupSkill` | 同上 |

各资产由**对应 skill 的目录**相对定位，不写死盘符。宿主换机器后先列一次实际存在的脚本清单，再决定本轮能跑哪几条。

## 二、验证动作的权限边界

- 验证命令**优先只读**。若验证动作本身需改动用户文件（如 `--apply`、重跑会覆盖产物），须已获该动作的授权。
- 备份、MD5、文件计数、渲染检查都属只读证据，可直接做。
- **不替代二次确认原则**：删除、修改、移动、重命名、覆盖仍须先向用户确认。
- 与 `SOUL.md` 的操作原则冲突时，以 `SOUL.md` 为准。

## 三、证据标准不随环境放宽

| 声称 | 必须拿到的证据 |
|---|---|
| 校验通过 | 本轮 `validate_*.py` **完整输出**：0 错误 0 警告 |
| 文件已生成 | 实测路径 + 字节数 + 内容抽样 |
| 链接无死链 | `verify_links.py` 全量输出 |
| 上传 / 安装成功 | 最近时间戳与系统任务状态，不是"绑定成功 / 未找到用量" |

**退出码 0 不等于业务结果达成**；"上次跑过 / 应该没问题"不算证据。脚本缺失、环境不具备时，结论要写 **partial** 并列出未完成项与缺口，不能写"已通过"。

## 四、硬门

- 五步不可跳：找出该跑的命令 → 实际跑 → 读全输出与退出码 → 对照证据表 → 汇报（含 partial）。
- 出现 Red Flag（"这是小改动不用再问"、"时间紧先报完成"等）即 STOP。
- 不把「调用步数变少」当「墙钟变短」；耗时拆解 T1 摄取 / T2 生成 / T3 机械 / T4 重跑，skill 改造通常只动 T3 与 T4。

## 五、本机默认值

无。校验资产一律按 skill 目录相对定位，不固定本机路径。此节留空是**有意**的。
