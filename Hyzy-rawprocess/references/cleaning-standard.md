# 清洗标准（本机默认：中度）

来源：`2026-08-20.md`（纯文本会议记录管线）、`2026-08-25.md`（直播逐字稿管线）。

## 档位
- **light**：仅删系统音/转写标记 + 同音错字纠正，最大保留原文。
- **medium（默认）**：light + 删语气词/口头禅 + 合并 3+ 叠字。
- **heavy**：medium 基座 + Agent 用 LLM 把冗余连接词整理成通顺段落（脚本只给 medium 基座）。

## medium 去噪动作
1. **系统音 / 转写标记**：`系统音：`、`转写内容：`、`说话人X：`、`[...]`、`【...】`、`（背景音）`、`（音乐）` 等 → 删除。
2. **语气词 + 口头禅（仅左边界删除）**：嗯/啊/呃/唉/额/然后/其实/就是/对吧/的话/那个/这个。
   - ⚠️ 必须用 `BOUND + token -> 保留 group1` 的「仅左边界」写法；不能用前后都带边界的 lookbehind，否则句首语气词后紧跟正文会漏删。
3. **合并 3+ 叠字**：`哈哈哈哈` → `哈哈`。
4. **同音错字**：`原词（纠正）` 保留原字，绝不直接替换。当前高置信 15 组仅示例 3 组（西电→西理工、扇形→善事、造型→早读），其余原文保留，可二次迭代扩充。

## 结构动作
- 复制体 / 手册：按原文章节建 H2/H3；适合表格的做表格。
- **录音稿 / 逐字稿（重点）**：去噪后的**正文必须按语义话题切分并补 H2/H3 小标题**——由 LLM 判读内容、归纳每段核心来标小标题（如「需求背景」「方案取舍」「落地步骤」「待办」），绝不只做「每 4 句一段」的扁平切分。小标题要能概括该段主题，让长录音稿可读、可检索。仅在确实无法归纳话题时才退化为 4 句/段兜底。
- 直播逐字稿：以「内容记录（AI总结）」切分；前半逐字稿按「录音稿」规则补内容小标题（4 句/段仅作可读性兜底，仍需按话题分段）；后半 AI 纪要按「N、」转 H3。
- 普通会议记录：按句切段（默认 4 句/段），如有明确议题切换同样补 H2/H3。

## 校验
- 0 残留系统音/转写标记（grep `系统音|转写内容|【|说话人`）。
- 标题层级正确、图片链接可打开、编码无乱码。
- docx 覆盖率可用 tag-safe 正则 `<w:t[^>]*>([^<]*)</w:t>` 统计真实文本，与 markitdown 输出比对（≈100%）。
