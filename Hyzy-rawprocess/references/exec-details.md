# 提速 · 成本 · 图片映射细则（从 SKILL.md 决策层剥离）

> **何时读**：第 1 轮开工前必读「提速约定 / 积分成本意识」；**处理图片之前必读**「图片映射与占位约定」。
> 本文件是 SKILL.md 原有内容的**原样搬迁**；档位定义见 `cleaning-standard.md`，剪贴板落地命令见 `image-localization.md`。

## 提速约定（来自 10款配图Skill 实战：有 skill 却比无 skill 的副本2 慢的根因）
- **结构化路径**：复制体/长文类一律 LLM 直接 Write 成品，**禁止写解析脚本**。副本2（无 skill 时期）正是这么做，反而比本次（有 skill 却写脚本、因层级误判重跑）更快更准。
- **图片本地化一步到位**：用 `scripts/localize_clipboard.py` 一键取最新 N 张并语义重命名（见 `references/image-localization.md`），**禁止每次手写 20 行 cp**，避免图序错位。
- **校验合并为单步**：产出后调用 `scripts/validate_md.py <产物>.md`，一次输出结构/图片引用解析/残留/围栏/大小，**禁止每次临时重写 Python 校验**。
- **整树 relink 校验**：复制/移动整树后调用 `scripts/validate_tree.py <根目录>`，批量扫所有 md 的图片引用，避免手动遍历断链。
- **命令模板变量自解析（禁用 `$HOME`）**：`SKILL`/`PY` 按「环境自适应」解析占位符，**既不要写死绝对路径，也不要用 `$HOME/...`**——Git Bash 下 `$HOME` 常为空，会让脚本路径断裂、首跑失败需重跑，直接吞掉数十秒。见下方代码块。

```bash
# 三个变量自解析（规则见上方「环境自适应」；不要依赖 $HOME，Git Bash 下常为空）
SKILL="${SKILL_DIR:-$(cd "$(dirname "<本 SKILL.md 路径>")" && pwd)}"
PY="${PY:-python3}"          # 校验/清洗脚本只需标准库
S="$SKILL/scripts"
# 单文件校验
"$PY" "$S/validate_md.py" "<OUT_DIR>/产物.md"
# 整树校验（复制/移动后）
"$PY" "$S/validate_tree.py" "<OUT_DIR>/目标目录"
# 剪贴板图本地化（取最新 3 张按 @image#1..#3 命名）
"$PY" "$S/localize_clipboard.py" --dest "<OUT_DIR>/images" --latest 3 --names "01-a.png,02-b.png,03-c.png"
```
- **可选增强：顶部速查表**。若材料是「清单 / 多篇 / 多工具对比」（如 10 款 Skill、多账号），可在 H1 下插一张总览表（编号 / 名称 / 来源 / 安装名 / 路线 / 适合场景），提升检索效率。非必需，按需。

## 积分 / 成本意识（42.61 复盘 + Skills Manager 单样本校准）

**根因排序已校准**：实测发现**「轮次」取代「原文长度」成为主导成本项**——每轮都要重灌 SKILL.md（~3K tokens）+ 原文 + 历史。带图复制体若拆成 7 轮，累计输入可达 ~60K tokens，与万字长文单持平。故**第一杠杆是压缩轮次**，其次才是原文注入方式。

- **轮次压缩（核心，目标 ≤ 3 轮）**：把**互不依赖的调用批量并入同一条消息**（一条消息内的多次工具调用只算一轮）：
  - **第 1 轮**：Skill 加载 +（查目录与 `localize_clipboard.py` 合并为一条 Bash）+ **Write 成品**（目标图片名由语义决定，不依赖本地化结果，故可并行）。
  - **第 2 轮**：`validate_md.py` 校验一次。
  - **第 3 轮**：记日志 + 呈现交付。
  - 禁止：查目录 / 本地化 / Write / 校验各占一轮的线性串行；禁止「写→校验→改→再校验」的往返。
  - 兜底：Write 早于本地化确认，若本地化失败会被第 2 轮校验抓出，再修一轮即可（可接受）。
- **入口闸门（分档）**：
  - **纯长文（无图）> ~1500 字**：先请用户存 `.txt` 再发路径，用 Read 单次注入；仅在其不便存文件时降级为内联。
  - **带图复制体 > ~3000 字**：同样提示存 `.txt`（图已必须走剪贴板落地，文本另存摩擦明显，故阈值放宽）。
  - **带图复制体 ≤ ~3000 字**：直接内联处理，完成后再提示「下次可先存 `.txt`」。
  - 原理：`.txt` 只进上下文一次，消除 ×轮次 乘数。
- **单 pass 产出**：结构化成品**一次性 Write 成完整 md**，不迭代拼装。
- **校验只跑末轮一次**：`validate_md.py` 在成品写完后跑一次，发现的问题**合并到一轮修正**回写，不中途反复校验。
- **任务中途零追加**：不追加澄清、不重贴/补发内容，避免上下文二次膨胀。
- **图片 / zip 零 token**：剪贴板图（localize_clipboard.py）与附件（./attachments/）走本地落地，**不消耗 LLM token**；多图任务无需为省积分删图——贵在文本与定位推理，不在素材。

## 图片映射与占位约定（正确性基线）

> 以下规则解决「图片与正文错位」「占位写法不一」「飞书占位随意处理」三类历史问题。校验只查文件存在，不保证图义正确，故映射环节必须留痕。

## 1. 图片↔内容映射协议
- **顺序信号**：用户消息里的 `@image#1 … @image#n` 顺序，与剪贴板目录文件名的时间序一致，映射一律以 `@image#n` 顺序为准，禁止仅凭「目录最新 N 张」猜序（跨轮/延迟粘贴会错位）。
- **多模态可用时**：本地化后，对每张图**抽取 1 句视觉描述写入图注/alt**（如 `![视觉设定板：母亲、女儿、车辆、道具](./images/01-visual-board.jpg)`），留痕可回溯。
- **多模态不可用时**：禁止凭文本位置猜图义。改为在 md 对应位置用 `<!-- @image#k 待补图注 -->` 占位，并**向用户索要每张图的说明与顺序**，拿到后再回填命名与图注。

## 2. 缺图占位统一写法（唯一约定）
原文有 `[图片]` 但无对应截图时，统一用：
```
> [!note] 原文此处有配图但未随文本提供
```
禁止出现 `配图未随文本提供`、`缺图`、`图略` 等其它变体（校验按此唯一串统计）。

## 3. 飞书「暂时无法在飞书文档外展示此内容」处理规则
原文出现该占位时，按内容类型判定，不临场随意处理：
- **表格类数据**（垂类/变量表/规格表等）→ 展开为 Markdown 表格；
- **音视频/文件/外链类**（成片、压缩包、资料包）→ 以可点击链接保留（外部链接或附件路径）；
- **无法归类** → 按规则 2 标缺图。
> 禁止把「暂时无法展示」整段静默丢弃。

## 4. 校验边界声明
`validate_md.py` / `validate_tree.py` 只验证「文件是否存在、结构是否闭合」。**存在性通过 ≠ 图片内容与正文语义一致**；图义正确性需人工或模型核对（见映射协议留痕）。
