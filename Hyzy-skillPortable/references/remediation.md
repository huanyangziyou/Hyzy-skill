# 改造手法：六种做法、模板与翻车点

第 4 步动手前必读。每条都给可直接套用的模板，别临场发明格式。

## 零、通用前置（三条，缺一条就别开始）

1. **物理备份**。Git 不可靠——skill 目录常是未跟踪状态（`git status` 一片 `??`），或外层有个无关仓库，`git rev-parse --show-toplevel` 指到别处。备份到工作目录之外：
   ```bash
   tar -czf /c/Users/<名>/_backup/<skill>-preopt-$(date +%Y%m%d-%H%M).tar.gz -C <skills根> <skill名>
   ```
   Git Bash 下**不能写 `C:/...`**，tar 会当成远程主机；用 `/c/...`。备份后核对「包内文件数 == 磁盘文件数」+ 记 MD5。
2. **逐处替换带 assert**，不要 `sed -i` 全局替换：
   ```python
   got = text.count(old)
   assert got == want, f"期望 {want} 处，实际 {got}"
   ```
   期望值写不出来，说明你还没查清它出现在哪几处。
3. **收尾清副产物**：`py_compile`、测试运行会生成 `__pycache__`，那是你造的，不是用户的，要删掉并复扫确认。

## 一、路径类 → 占位符 + 解析责任表

每个占位符必须回答「谁定」：自动推导 / 自动探测 / 必须问人。三列缺一不可。

| 占位 | 含义 | 谁定 |
|---|---|---|
| `<SKILL_DIR>` | 本 skill 目录 | 自动推导，不问人 |
| `<PY>` | 跑脚本的解释器 | 自动探测（只需标准库） |
| `<素材目录>` | 输入材料目录 | **必须问** |
| `<库根>` | 输出成品库根 | **必须问** |

写占位符时的两条硬规矩：

- **正文保持占位，不要把解析结果写回文件**。写回去下次换机器又要手改一遍。
- **占位符不许出现在无法解析的位置**（如文件名、不可插入变量的正则字面量）。

顺手要查的一类 bug：占位符被**重复拼接**。例如 `<库根>` 本身已经是「概念笔记库根」，模板却写 `--base "<库根>/01-概念笔记"`，真跑会指向不存在的目录。改占位符时逐条把拼出来的值代入念一遍。

## 二、本机事实 → 隔离进「本机默认值」段

**不要删掉本机值**。删了，本机也要重新填一遍。正确做法是把它塞进一个可整段删除的隔离区：

```markdown
## 五、本机默认值（只服务这台机器；**先检查再用**）

> 这一节是**本机的具体值，不是断言**。固定三段用法：`先 stat` → `存在就用` → `不存在就退回上文的探测顺序或问用户`。
> **换机器时整节删掉即可**，其余内容不受影响，删掉后行为自动退回通用版。

| 项 | 本机值 | 检查 |
|---|---|---|
| `<VENV>` | `<绝对路径>` | 文件存在，且 `import <依赖>` 通过 |
| `<库根>` | `<真实路径>` | 目录存在 |

**硬门补充**：本机默认值**不得**直接拼进命令当确定路径；必须先检查存在性。
```

配套要改正文的三处，否则会自相矛盾（这三个地方真漏过）：

- SKILL.md 里「问一句」的措辞 → 「有本机默认值就直接用并声明，**不为此单独问一轮**」
- `env-adapt.md` 的责任表 → 该占位不再写「只由用户给」
- 其他 references 里「不自带默认值」这类断言 → 一并改掉

改完用 `grep "不自带默认值\|只由用户给\|一律问"` 搜一遍，应为 0 命中。

## 三、案例/背景 → 抽象化

判据：**留方法与数字，去书目、型号、路径**。目标不是把文件变模糊，而是换成另一个人拿过去也能校准。

三步：

1. **定分界**：厂商名、芯片型号、真实书名、真实磁盘路径 → 换；技术示例（接口名、协议、文件格式后缀）、方法、所有数字 → 留。
2. **删掉的字数换成方法解释**。抽象化后文件往往变长而不是变短——把省下的身份信息换成「为什么这么切」「这里为什么不能那样做」。只删不补，等于把案例掏空。
3. **文件头加口径表**，让人一眼看出哪几处是刻意的：

```markdown
## 0. 抽象化口径（读之前先知道哪些被换掉了）

| 处理 | 内容 |
|---|---|
| 原样保留 | 流程切分、组数与篇数、全部数字、格式与模板 |
| 换成通用表述 | 厂商名、芯片型号、书名、真实磁盘路径 |
| 有意不换 | `.adc`/`.xdc` 这类文件格式后缀——技术示例，不是身份指纹 |
| 按类别理解 | 域名/分类名——它们是内容类别，不是项目代号 |
```

**只改案例文件不够**：同一份指纹常常还散在 pitfalls（矛盾台账示例）、派活模板（举的例子）、pipeline（示例标题）里。改完在主目录 `grep` 一遍全词表，确认只剩文件名本身。

## 四、超长 SKILL → 按「何时读」拆分

阈值参考 5000 字符（本库 `ARCHITECTURE.md`）；过 8000 基本该拆。

四条纪律：

1. **按步骤切，不按主题切**。切完每个 references 要能回答「走到哪一步才需要它」。
2. **用「必读」标记，不用「参见」**。正文每个步骤开头写「X 之前必读 `references/…`」；只写「详见」等于让代理自行决定读不读，拆了白拆。
3. **按行号原样切片，不重写**。用 Python 取行区间，避免手抄把数字、阈值、命令改走样；`###` 降 `##` 也一并处理。
4. **拆完必须验保真**：原文有效行逐条比对 + 关键要素关键词清单，缺失 0。常见漏项是代码骨架、校验「为什么必须跑」的理由、脚本能力描述。

## 五、双库并存 → 单向同步

存在「本地在用的库」和「准备公开的副本库」时：

- 先问清**哪边是权威版**，写进 README 或记忆，别每次重新判断。
- **同步方向单向**：从干净版 → 本地版。反向会把私有信息推回去，前面所有工作白做。
- 本地版可以保留本机默认值段（它只在本地跑），副本版必须零本机值。
- 每次同步后跑 `diff -rq`，差异必须**只剩预期项**且能逐条解释。差异数量本身不是问题，「解释不了的差异」才是。

## 六、文档同步 → 不留假账

改完正文必须回头改文档，否则下一个人会信错：

- README / 审计表里的**行号全部作废**。不要试图维护行号，改成「无行号状态表 + 指向实测计数」。
- 计数要重跑，不能沿用旧数。旧的写错过一次就要在文档里承认写错了，别悄悄改。
- **没做完的不要标已完成**。判不了的一律标「未决 / 快照值」。
- 文档里提到的文件被删了，所有指向它的句子都要清掉（悬空引用）。

## 七、翻车点汇总

| 现象 | 根因 | 正确做法 |
|---|---|---|
| 改完发现同一句话在别处还有 | 只按文件改，没按词改 | 先建全词表，再全库 grep，改完复扫 |
| 越改越「空」，读起来像模板 | 只删不补 | 删掉的身份信息换成方法解释 |
| 两库越改越不一致 | 双向同步 | 固定单向，每次 diff 核对 |
| 改了 9 处但声称改了 10 处 | 没复扫 | 改完复扫，数字以复扫为准 |
| 备份「应该没问题」 | 没验证 | 核对文件数 + MD5，两处可恢复 |
| 用户要的只是「先看看」，却动了文件 | 没识别只读意图 | 出现「先/规划/不要改」即全程只读 |
