# 探查分类：六类判定、扫描命令、误报清单

第 2 步探查前必读。目标是把「这 skill 有多脏」变成一张**可复现、可复核**的表，而不是一段印象。

## 一、判定总则

判「该不该算作指纹」只问一句：**换个人的机器 / 换个读者的视角，这条信息还成立吗？**

- 「`<库根>` 下应有域目录」→ 成立，是**方法**，留。
- 「`…/<项目目录>/<库名>`」→ 不成立，是**本机事实**，改。
- 「`.adc` 与 `.xdc` 两种后缀」→ 换人也成立（技术示例），留。
- 「文件名里带厂商名，如 `case-<厂商>.md`」→ 不成立，是**厂商指纹**，改。

判别方法类时用「方法 / 事实」二分；判别事实类时用「别人的机器上还是这个值吗」。

## 二、六类细则

### A 身份
命中物：系统用户名、主机名、真实姓名、邮箱、账号、家目录展开后的绝对路径。
判定：`C:/Users/<某个具体名>`、`/home/<名>`、`%USERPROFILE%\<名>` 一律算；写成 `<家目录>` 占位的不算。

### B 私有数据
命中物：真实素材目录、真实库根、真实输出路径、项目代号命名的目录。
判定：路径里含**中文实体名**（项目名、资料集名、库名）基本都算；含 `<尖括号>` 占位的不算。
注意：`_素材/`、`99-存档` 这类**目录约定**不算——它们是命名习惯，不是私有值。判断依据是「它出现在 argparse 默认值里吗」：出现在默认值里会影响行为，只出现在 docstring 与 `--help` 示例里则不影响。

### C 环境事实
命中物：venv 绝对路径、解释器路径、工具链安装根、固定端口、固定缓存目录。
判定：这类**不一定要删**。正确处理是「保留默认值 + 加存在性检查 + 失败降级」，不是清空。直接删掉会让 skill 变成「到本机反而要手填」。

### D 项目背景
命中物：厂商名、芯片/板卡型号、工具链商品名、真实书名、公司名、**文件名里的上述词**。
判定：正文里出现算，**文件名里出现也算**——文件名里的厂商词比正文里的一句更显眼，而且会被所有引用它的文档反复带出去。
最容易被漏的一类：同一份指纹散在多个文件（如矛盾台账的示例同时出现在案例、pitfalls、派活模板里），只改一处等于没改。

### E 结构缺陷
命中物：超长 SKILL（经验阈值 8000 字符）、必读标记缺失、悬空引用、文档与事实不符（假账）。
「假账」专指：README / 审计表声称「已处理」，但文件里没改；或反过来改了没记。这类问题比路径泄露更伤——它让后来的人信错东西。

### F 可执行性缺陷
命中物：占位符被重复拼接、命令模板指向不存在的目录、默认值写死导致换机必失败、占位符出现在无法插入变量的位置。
判据：**把这个占位符代入它的定义值，看拼出来的路径是否存在**。

最典型的一种：`<库根>` 按定义已经是「成品库的根」，模板里却写 `--base "<库根>/01-概念笔记"`，代入后变成 `……/01-概念笔记/01-概念笔记`，一个不存在的目录。这种错误不会报错，只会在真跑时静默失败或产出到错位置。

这类缺陷**不会**被 A–E 的字符匹配发现，只能靠代入检查。做法：把每个命令模板里的占位符全部替换成定义值，逐条念一遍路径是否成立。凡有 `--x "<占位>/<子目录>"` 形式的，重点怀疑。

## 三、扫描命令（Git Bash 实测可用）

```bash
# A 身份
grep -rnE "C:/Users/[A-Za-z0-9]|/home/[a-z]" --include="*.md" --include="*.py" .

# B 私有数据：盘符 + 中文首段
grep -rnP "[A-Za-z]:[\\\\/][^\\\\/\\s]*[\x{4e00}-\x9fff]" --include="*.md" --include="*.py" .

# D 项目背景：按你实际用过的厂商/型号/书名自建词表
grep -rniE "厂商A|厂商B|芯片型号|板卡型号|工具链名|真实书名" --include="*.md" --include="*.py" .

# E 结构：SKILL 规模
for s in */SKILL.md ; do printf "%-46s %6s\n" "$s" "$(wc -m < "$s")" ; done

# 悬空引用：文档里提到的 references/xxx.md 是否都存在
grep -rhoE 'references/[a-z0-9-]+\.md' --include="*.md" . | sort -u | while read f ; do
  [ -f "$f" ] || echo "缺失: $f" ; done
```

`grep -P` 不可用时退回 `grep -rE`，把中文字符类换成 `[一-龥]`。

## 四、误报清单（都真踩过）

| 现象 | 原因 | 处置 |
|---|---|---|
| `usage:\n` 被判成盘符 `e:` | 正则把「字母 + 冒号 + 反斜杠 + 字母」当路径 | 逐条看真实命中，别照数字删 |
| 两库 byte 比对报 16 个文件不一致 | CRLF 与 LF 差异（`git archive` 导出产物） | 先归一化换行符再比 |
| `dir` 显示 `<DIR>` 却不是普通目录 | 那是个 junction，`dir` 对 junction 也显示 `<DIR>` | 用 `os.path.realpath()` 或 `readlink -f` 确认 |
| `cd scripts && rm -f 名` 返回 0 但文件还在 | 链式命令的工作目录没按预期生效 | 改绝对路径通配，删完**复扫**确认 |
| `tar -czf "C:/..."` 报 `Cannot connect to C:` | tar 把 `C:` 当远程主机 | 用 `/c/...` 或加 `--force-local` |

**规则：任何一个数字异常，先解释再动手。** 解释不了的不许改。

## 五、分级标准

| 级别 | 判据 | 例子 |
|---|---|---|
| 必须改 | 直接泄露身份 / 私有数据，或让 skill 在别人机器上必然失败 | 家目录绝对路径、真实库根当默认值、文件名里的厂商名 |
| 建议改 | 削弱可移植性但不致命 | 单个示例里的真实书名、docstring 里的真实目录 |
| 可不动 | 换人也成立的通用示例、或纯技术示例 | `.adc`/`.xdc` 后缀、`C:/Program Files` 通用路径、目录约定 `_素材/` |

分级表是给用户拍板用的——**不要自己把「建议改」并入「必须改」**，那等于替用户决定了公开尺度。

## 六、计数规则（要可复现）

- 计数单位写清是「处」还是「文件」；两者都报。
- 报告里附上跑计数的那行命令，让人能自己复跑。
- 主观分类（如「算不算背景指纹」）在表里标 `(判断项)`，与机器可复现的计数分开列。
- 同一处命中跨文件的，按文件分别计数再加总，不要只给总数。
