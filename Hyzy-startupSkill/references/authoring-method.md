# 创作方法：五要素、最轻架构与泛化门

## 一、先确认值得做
Skill 成立当且仅当：工作反复出现 / 路由易误判 / 用确定性执行更安全 / 需要可携带与治理。一次性问答、普通文档、翻译、解释、尚未发生的臆想流程不打包。

记录：用户与重复任务、真实输入与成品、排除项与近邻、权限与副作用、权威事实源、成功标准与所需证据。缺项会改变产品类别 / 权限 / 不可逆范围时，停一次问一个问题；否则写保守假设继续。

## 二、keep / adapt / reject / invent
参考外部元 skill 或同类实现时，只借机制与结构，不复制长段表述或私有内容：

| 动作 | 判据 |
|---|---|
| keep | 本库独有且已生效（记忆复盘、二次确认、索引与 git 治理） |
| adapt | 机制可用但需按本库平台、路径、权限改写 |
| reject | 面向公开发布、团队治理、跨平台的重资产，个人本地用不上 |
| invent | 本库特有的方法论与真实语料 |

先例研究只在用户明确要求比较、机制无法可靠选定、或存在来源 / 许可 / 信任风险时做。

## 三、最轻架构
从根 `SKILL.md` 起步，只有能减少歧义、重复劳动、路由风险或证据风险的资源才创建。模式由 Agent 推断，不让用户选：

| 模式 | 触发条件 | 交付线 |
|---|---|---|
| Scaffold | 个人、本地、可逆 | 根 SKILL.md + 真正赚到的资源；结构校验通过 |
| Production | 团队复用 / 触发易误伤 | 补触发案例、边界与输出验收 |
| Library | 共享基础设施 / meta skill | 补稳定结构与回归样例 |
| Governed | 公开发布 / 账号密钥 / 高风险写入 | 补 owner、review cadence、回滚与证据标注 |

> 普通可恢复的本地文件写入不单独触发 Governed；改写执行规则、覆盖或删除重要数据、变更权限配置按高风险处理。

## 四、泛化门
1. 把单个案例 / 失败改写成领域中立的失效机制。
2. 分类：核心不变量 / 可选适配 / 仅 eval fixture。
3. 只把安全、事实、权限，或在 ≥ 2 个无关领域复现的行为升为核心规则。
4. 一次性细节留在 fixture 或专门 reference。
5. 重跑原案例 + 一个无关边界案例，确认没把特例写成通例。

## 五、上下文与单一事实源
- 根文件只放路由与执行必需内容，长篇方法论不进根。
- 每个事实只有一处权威来源，其他文件指向它；报告里的生成结果不反向塞回 `SKILL.md`。
- 改动本库规范时同步 `ARCHITECTURE.md`、SKILL.md、`INDEX.md`，避免流程出现第二份描述。

## 六、失败路径
意图不清 → 只问边界问题；事实过期 → 标为未决；工具不可用 → 声明回退或缺口；权限不足 → 停在写入前；架构需要臆想文件 → 不建，只记未来触发条件；改名会碰撞 → 停，不改文件。
