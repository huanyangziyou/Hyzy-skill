# 环境自适应（startupSkill）

> **何时读**：选型与信息恢复阶段（§二）必读；准备写入文件包之前复核第三节的权限边界。

本 skill 的"环境"不是解释器，而是**三类宿主位置**：skill 库根、记忆目录、需求 SSOT。它们决定去哪读、能往哪写。

## 一、三个宿主位置

| 项 | 怎么定 | 缺失时 |
|---|---|---|
| skill 库根 | 由本 `SKILL.md` 所在目录推导；查重与安装都相对它做 | 推导不出就停下问，不猜一个家目录 |
| 记忆目录 | 当前项目的 `.workbuddy/memory/` 每日日志 + `MEMORY.md` | **不存在就不创建、不追问**，直接跳过复盘并注明「无历史记录」 |
| 需求 SSOT | 当前项目目录下默认找 `需求说明.md` | **不存在则不创建、不追问**，按已有信息继续 |

> 关键：后两项是「存在才读」，不是「必须存在」。把缺失当成错误去追问，是本 skill 最常见的过度交互。

## 二、写入权限（不是路径问题，是授权问题）

- 仅授权目录 `skills/<name>/` 内可写；**目录之外一律只读**。
- 刷新 `INDEX.md`、提交、安装到在用库——都需**明确授权**后才做，不因"顺手"而执行。
- 工作区已有无关改动时**不代为提交**，先报告状态。
- 不为个人本地 skill 造 README / manifest / Skill IR / 发布脚本 / 报告目录 / 空目录。

## 三、可发现性与规模约束

- 一个包只能有一个可发现的根 `SKILL.md`；内嵌示例用 `SKILL.example.md` 或 `SKILL.fixture.md`。
- 核心 ≤ 5000 字，超了按**决策边界**拆 `references/`，并用「X 之前必读」而非「参见」驱动按需加载。
- `scripts/` 里的脚本装前必审计（仅本地读写、无网络外发、无删除操作）。

## 四、硬门

- 不把本机绝对路径写进 `SKILL.md` 正文；需要具体值时放进本文件的「本机默认值」节并加 `先检查再用`。
- 查重结果要能复现：给出实际扫描过的目录与命中文件，不用「应该没有」结案。
- 评测结论必须区分**设计优势 / 已验证优势 / 假设 / missing evidence**，不把「调用步数变少」说成「更快」。

## 五、本机默认值

无。skill 库根由文件位置自解析，记忆目录与需求 SSOT 都是「存在才读」，三者都不需要固定本机值。此节留空是**有意**的。
