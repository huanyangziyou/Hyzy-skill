# 交付验收清单

> 分级依据 `SKILL.md` 第五节；只报实际达到的最高级，不跳级声称。

## 一、路由与结构
- [ ] description 单行，含正例说法与否定排除；`refresh_index.py` 能正确解析
- [ ] 目录名与 frontmatter `name` 一致；全包只有一个可发现的根 `SKILL.md`
- [ ] 五块齐全 + 停止条件 / 失败处理 / 验收标准 / 约束三级
- [ ] 核心 ≤ 5000 字；长内容按决策边界拆进 `references/` 且在根文件有链接
- [ ] 每个 `references/` 与 `scripts/` 引用路径真实存在（区分真实缺失与文档示例占位符）
- [ ] 无空目录、无仪式文件（README / manifest / IR / 发布脚本，除非任务确实需要）

## 二、触发
- [ ] `evals/trigger_cases.json` 覆盖应触发、不应触发、近邻三类
- [ ] 本轮真实请求能命中；「只解释概念 / 一次性需求」不命中
- [ ] 改动 description 后复核过三类样例

## 三、行为与边界
- [ ] 硬约束含二次确认、暂存删除、只读审计三类动作权限
- [ ] 失败处理表覆盖信息不足 / 事实不可验证 / 工具缺失 / 权限不足 / 校验失败 / 部分完成
- [ ] 泛化门已执行：单样本细节未升格为核心规则
- [ ] 无不可检验形容词、无编造的身份与完成证据

## 四、安全审计（含 scripts/ 时必做）
- [ ] 无网络外发、破坏命令、密钥、提示词注入；标准库良性 = P2
- [ ] 脚本有 `--help` 或可测契约；装前风险已向用户指出

## 五、四级验证
| 级别 | 检查 | 达成 |
|---|---|---|
| 1 结构校验 | frontmatter / 引用 / 资源 / 脚本静态检查 | [ ] |
| 2 真实任务冒烟 | 至少 1 个真实主要任务跑通并通过验收 | [ ] |
| 3 留出与回归 | 留出样例通过、无关键回归 | [ ] |
| 4 安装核对 | 安装来源可装，内容与源目录逐项一致 | [ ] |

## 六、证据边界
- [ ] 结论标注为 设计优势 / 已验证优势 / 假设 / missing evidence
- [ ] 未把「调用数下降」写成「耗时下降」；未按 `eval-method.md` 拆解过就不下效率结论
- [ ] 交付写明：路径、解决的问题、最高验证等级、未验证风险、下一级缺什么证据

## 七、治理
1. 写入 `skills/<name>/`（覆盖前二次确认）
2. `python tools/refresh_index.py` 重建 INDEX.md
3. git 提交（工作区有其他无关改动时先报告，不代为提交）
4. 3–5 轮真实任务迭代，把复盘结论沉淀回记忆 / wiki
