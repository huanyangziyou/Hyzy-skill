# SKILL.md 模板（五块 + 三附加）

> 五块是最低结构（见 `ARCHITECTURE.md` 第 2 节）；停止条件、失败处理、验收标准是让 Agent 不跑偏的必要附加。

## frontmatter

````yaml
---
name: <kebab-case-name>
description: <单行；写「何时触发」+ 关键说法 + 明确的排除项，不要只写「是什么」>
category: <obsidian-notes|doc-convert|canvas|clarify-plan|skill-dev|meta>
updated: <YYYY-MM-DD>
---
````

本库 `tools/refresh_index.py` 只按行首正则读取 `name/description/category` 三个字段，**description 必须单行**，不得用 YAML `|` 块；否则 INDEX.md 表格会被破坏。

## 正文骨架

````markdown
# <Skill 名称>

<一句话：这个 Agent 要完成的活和最终交付物。先写活，角色只在改变决策时才写。>

## 触发条件
- <用户会自然说出的句子 1>
- <变体 2>
- <变体 3>
- 信号特征：<出现某类输入 / 文件 / 短句时>
- 排除：<最像但不该接的相邻任务>

## 你的工作流程
1. 当 <可观察条件>，做 <具体动作>，验证 <检查>，然后 <继续或停止>。
2. <下一步>
3. <照人读通顺写，Agent 照推进>

## 约束分级
- 硬约束：<违反即失败>
- 推荐默认：<有反例才偏离，并记录理由>
- 允许自主判断：<在命名边界内自选，仍须满足输出合同>

## 停止条件
- <缺授权 / 事实冲突且无安全优先级 / 必需工具无回退 / 会覆盖无关文件> → 停，并说明原因。

## 失败处理
| 情况 | 必须怎么做 |
|---|---|
| 信息不足 | 问一个会改变边界的问题，或写保守可逆假设后继续 |
| 事实无法验证 | 标注为未知 / missing evidence，不把推断写成事实 |
| 工具不可用 | 走已声明的回退；无回退则保留现场并说明缺口 |
| 权限不足 | 停在写入前，点明缺哪项授权 |
| 校验失败 | 保留失败输出，修最小责任规则，重跑同一检查 |
| 只完成一部分 | 报已完成 / 剩余 / 可恢复的下一步 |

## 不能做的事
- <绝对边界 1，至少 5 条>
- <绝对边界 2>

## 输出格式
<表格列名 / bullet 层级 / JSON 字段，写死一次>

## 验收标准
- <可检查的产物路径、必含章节、必含排除项>
- <禁止出现的内容：私密路径、token、无证据的完成声明>
````

## 写作检查

- 每条指令都能映射到动作、判断、边界、失败响应或验收项。
- 「专业 / 高效 / 全面 / 更完整」换成可观察条件或阈值。
- 硬约束、默认、自主空间不互相冲突。
- 示例只用于消除歧义，不替代规则；长示例移出根文件。
- 按需加载：只有当前分支用得上的判断方法才进 `references/`。
