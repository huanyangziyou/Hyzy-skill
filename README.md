## 一、共同设计前提

13 个 skill 写法不同，但共享同一条工程取向。先看这 6 条，再看单个 skill 会快很多。

1. **核心薄、参考厚**：根 `SKILL.md` 只放触发边界、关键判断、主流程、输出合同，控制在 5000 字内；细则、长示例、口径全部拆进 `references/`，按决策需要时才读。
2. **脚本只做确定性动作**：格式转换、结构校验、索引生成、图片落地交给 `scripts/`；需要理解语义的部分明确禁止写成正则脚本（有反例：复制体结构化写解析脚本反而比模型直读更慢更错）。
3. **硬边界写在正文**：每个 skill 都有独立的「不能做的事」段，而不是散在注释里。其中包括「不静默覆盖用户文件」「不编造原文没有的参数」「不宣称未验证的完成」。
4. **单 pass 产出 + 末轮一次校验**：禁止「写 → 校验 → 改 → 再校验」的往返，校验发现的问题合并成一轮修正。
5. **轮次是主成本项**：长文本内联会随每轮对话被反复重读，所以长文一律建议先落 `.txt` 走单次读取；能并行的工具调用合并在同一条消息里。
6. **证据先于断言**：交付必须带「命令 + 关键输出 + 退出码」，无法核实的项单列「未核实」并写明阻断点。这条由 `Hyzy-VerifyGate` 统一执行。

### 2.1 按功能分类（速查）

十三个 skill 按「在流水线里站在哪一环」分成四域，而不是按产物格式分：

| 功能域 | 在做什么 | Skill | 输入 → 输出 |
|---|---|---|---|
| ① 采集与入库 | 把未经整理的原始材料或已发生的过程记录变成可检索的 Markdown 知识 | `Hyzy-rawprocess`、`Hyzy-PDFtomdnotemap`、`Hyzy-AIGrowthNote` | 录音稿 / 剪贴板 / 网页 / 成套教材 / AI 协作过程 → 干净 md、概念笔记库、成长笔记 |
| ② 提炼与表达 | 把已入库的知识、源码或一手实测数据再加工成可交付的成品件 | `Hyzy-KnowtoMethPath`、`Hyzy-IndustryRadar`、`Hyzy-HDLtoSVG&Explain`、`Hyzy-PhysLabReport` | 知识文档 / 行业线索 / HDL 源码 / 原始数据照片 → 方法路径文档、研究报告、SVG 链路图、规范报告 docx |
| ③ 完成前闸门（横切） | 不产内容，只判定「凭什么说做完了」 | `Hyzy-VerifyGate` | 任何待交付结论 → 证据三件套 / partial |
| ④ Skill 治理（元层，整合包） | 生产、改造、验收、盘点 skill 本身；入口是 `Hyzy-SkillRouter` | `Hyzy-SkillRouter`（入口）、`find-skills`、`Hyzy-startupSkill`、`Hyzy-skillPortable`、`skill-library-governance` | 模糊需求 / 一个需求 / 已有 skill 包 / 整个库 → 候选清单、新 skill 包、通用化变更台账、审计报告 |

- ①② 是内容主线（7 个），③ 横切所有交付（包括 ④ 自己的交付），④ 面向 skill 资产本身（6 个，含 1 个路由入口）。
- **④ 是一个整合包**：5 个成员平级摆在库根，靠 `Hyzy-SkillRouter` 做统一入口。为什么不用文件夹把它们装起来——本库的发现机制是 `skills/<name>/SKILL.md` 单层扫描，物理归并会让 5 个成员一起失效。这一做法与 superpowers 的 `using-superpowers` 同构：入口本身也是一个平级 skill，靠 description 在会话开头被拉起。
- `Hyzy-skillPortable` 是 ④ 里唯一输入为**已有 skill 包**的；④ 其余四个的输入分别是「一个模糊需求」「一个待实现的需求」「整个库」「一次待宣称的结论」。①②③ 八个的输入都是领域材料。
- `Hyzy-VerifyGate` 单列成域，是因为它没有行业内容、也不落在①或②的任何一个产物上，把它塞进任一域都会低估它的横切性。
- frontmatter 的 `category` 字段**不按此分类重排**：该字段是在用库全体 skill 共用的索引维度，当前按产物落点分组，单独改这十三个会让 `INDEX.md` 的分类总览对不上。功能分类只写在本节。

逐个说明见 §3.1–§3.13，同一副骨架的横向对比见 §四。

### 3.1 `Hyzy-rawprocess` · 原材料 → Markdown

**作用**：把录音稿/逐字稿 `.txt`、复制体 + 剪贴板截图、网页 HTML 源码、docx/PDF 清洗、结构化、图片本地化，产出可入库的 Markdown。自述实战底稿包括 30+ 份会议记录 docx 1:1 镜像、19 份 GBK/UTF-8 纯文本会议记录、多份直播逐字稿、知识星球 HTML 去重与远程图本地化。

**触发**：用户给出 `.txt/.docx/.pdf/.html` 或直接粘贴长文 + 截图，要求「转成 markdown」「整理成笔记」「入库 wiki」「去噪转 md」。**不触发**于只是问文档内容、要摘要、或不需要落盘。

**方法论**：

1. **先识别输入形态，再进固定流程**。五类分流（docx/pdf、txt 逐字稿、复制体+截图、html 源码、URL），每类绑定已预置的工具，明确禁止临场写脚本或临场装包。
2. **结构化路径分两套，绝不混用**：复制体/长文由模型直读语义、一次性 Write 成品，禁止写 Python/正则解析脚本（正则脆弱、层级易误判、debug 重跑更慢）；只有含「系统音：」「内容记录（AI总结）」这类噪声的 `.txt` 才交给清洗脚本产出「去噪基座」。
3. **去噪不改写语义**。同音错字用「原词（纠正）」保留原字；录音稿去噪后**必须补 H2/H3 内容小标题**，不允许「每 4 句一段」的扁平长段落——这条与「仅去噪不结构化」明确区分。
4. **图片强制本地化**：剪贴板图/远程图一律落到 `./images/` 并用相对路径引用；图序以用户消息里的 `@image#n` 顺序为准，不靠「目录最新 N 张」猜；缺图用唯一约定写法占位，不出现多种变体。
5. **校验单步化**：成品写完后跑一次 `validate_md.py`（结构 / 图片引用解析 / 残留标记 / 围栏 / 大小），整树搬迁后跑 `validate_tree.py` 批量查断链。脚本只验「存在性与闭合」，**存在性通过 ≠ 图义正确**，这层边界写在正文里。
6. **成本分档闸门**：纯长文 > ~1500 字、带图复制体 > ~3000 字时，先请用户存 `.txt` 再发路径；带图但 ≤3000 字直接内联处理。目标轮次 ≤ 3。

**资源**：`references/` 六份（cleaning-standard 噪声标准 / dispatch 分流 / html-to-md / image-localization / install 环境 / skeletons 骨架）、`scripts/` 五个（convert_docx、localize_clipboard、raw2md_clean、validate_md、validate_tree）。

### 3.2 `Hyzy-PDFtomdnotemap` · 教材 → 概念知识库

**作用**：把成套 PDF 教材/手册批量转 md 并全量融合进 Obsidian 概念知识库。六阶段：PDF→md → 章节行号定位表 → 域级映射分组 → 并行子任务写笔记 → 脚本核验 → 概念地图同步。自述实战底稿为 6 本 / 1433 页教程 → 11 个域映射 → 7 组并行 → 概念笔记 131 → 195 篇、全库终校 0 结构缺陷。

**触发**：同时出现「一个含多个 PDF 的目录」+「一个知识库根目录（有域目录与总索引）」即命中。**入口闸门**：只有 1 本书 / ≤10 篇笔记时不要启动六阶段，直接按目标库规范写。

**方法论**：

1. **Stage 0 契约勘察先行**：库里有 `_规范-*.md` 时它是唯一执行标准，凌驾于 skill 内置契约之上；无规范才用内置九小节兜底，并明确告知用户「该库无规范」。
2. **定位表是省 token 的枢纽**：把每本书的标题 + 行号 + 图片名前缀 + 页数索引成表，子任务按行号 `Read --offset/--limit` 取段，**绝不整篇读**（一本 380 页 md 整读一次就能吃光子任务上下文）。
3. **并行写作 + 主控复核**：切 3–7 组并行派活，每组 prompt 必带五件套（域与篇名清单、行号范围、规范路径、图片目录与命名、汇报协议）。铁律：子任务说「完成」不算验收，主控必须跑核验脚本。
4. **诚实标注四类**：原文矛盾（两说 + 采信哪一说 + 依据）、原文未载（标「待核实」，宁可空着）、派活说明与素材不符（当场反驳，不迁就）、借用其他章节/其他书的参数（逐行标来源）。配套禁令：不把凭先验记忆的技术参数写进派活要求。
5. **结构决策先问**：新建域、改规范、动旧笔记属结构决策，先出提问卡；正文按批交付，每批停下等确认，不跨批推进。
6. **全库终校分两类**：A 类＝本次融合范围内，必须 0 缺陷；B 类＝历史遗留（口径确立前的旧写法），列表交用户裁定，**不擅自批量改**。

**资源**：`references/` 七份（env-adapt 环境自适应 / pipeline 执行细则 / note-contract 笔记契约 / parallel-prompts 派活模板 / pitfalls 翻车对照 / case-fusion-6books 实战案例 / **exec-details 执行细则·报账模板·脚本清单**）、`scripts/` 五个。核心只留决策层与硬边界，进入任一 Stage 之前按「必读」标记加载 `exec-details.md`。

### 3.3 `Hyzy-KnowtoMethPath` · 知识 → 方法路径

**作用**：把叙述型知识文档提炼成「标准化流程文档」——SVG 路径选择决策图 + 表格式概括 + 每条路径每个类型一个可验算案例，落在 `<原文档目录>/method path/` 下。自述底稿为复变函数积分一章 677 行 → 12 条路径 / 12 个算例 / 三张概括表，交付前 12 个算例全部数值反算通过。

**触发**：用户说「把这篇整理成流程」「做成方法路径文档」「出个带路径选择图和算例的标准流程」「照 method path 那套再做一份」。**信号特征**：给的是叙述型文档（有定理/步骤但无决策结构），且期望输出含决策图/表格/案例中至少两项。

**方法论**：

1. **判据先于路径**：先从原文抽「决策判据链」（找「若…则…」「当 X 时」的分岔点 → 排序使互斥且覆盖 → 每条终点边收敛到一个方法），再由判据推导路径。反过来做（先想好 ABCD 再找依据）必然切出互相重叠的伪路径。
2. **编号与顺序承载信息**：路径用 A/B/C（不与章节号 `## 4.` 混淆），子类型 A1/A2；「建议顺序」列按省力程度排，这是本文档与普通教材的关键差别。
3. **SVG 先规划后写**：先出坐标规划表（含画布高度、每个元素 x/y/w/h）再写标签，跳过必返工；`viewBox` 宽固定 680，颜色按功能分组最多 3 组。
4. **案例必须真算**：每个案例用独立途径（cmath 数值 / sympy 符号 / 蒙特卡洛 / 残差）反算，验算记录写入 `_verify-log.md` 并随交付贴出。只推导不反算的案例视为未完成。
5. **入口闸门防硬凑**：少于 3 个可分辨方法就如实说「该主题方法空间较窄」，超过 12 条说明粒度过细要合并；两条也是合法结果。

**资源**：`references/` 四份（doc-contract 文档契约 / svg-spec 决策图规范 / case-writing 案例与验算手段 / pitfalls）、`scripts/verify_methpath.py`（结构 + SVG + LaTeX + 表格 + 案例覆盖一体校验）。

**可能暴露的本机信息**：**无**。A–E 五级扫描在所有 6 个文件中零命中——该 skill 全部用相对路径与抽象示例表述，是全库两个「可直接公开」的之一。

### 3.4 `Hyzy-HDLtoSVG&Explain` · 源码 → 图解

**作用**：把源码（Verilog/VHDL 顶层与模块为主，兼收 C/Python/配置表）读成 SVG 图形化链路，并产出「图 + 九节逐级解释」的 Markdown。自述底稿为某平台 `system_top.v` 的 MIPI→ISP→DDR→HDMI 全链路（11 级、3 时钟域）。

**触发**：给源码/顶层/module 并要求「用图形化形式表示数据处理流程」「画成链路图」「生成图形化链路 md」。**不触发**：只问代码问题、要 review、改 bug、讲语法。

**方法论**：

1. **图上有底稿、说明有出处**：图上与文中的每个模块名、参数值、数值都必须能在源码里指出（信号名/参数名/行号）；读不清写「待确认」，绝不凭印象补。
2. **复杂度自动定图数，不问用户**：按实例数 / 时钟域 / 是否含控制状态机分三档出 1–3 张图；**叶子模块**（无实例化）改用「独立机制数」判据（一个机制 = 一组自己的寄存器 + 自己的更新规则），否则逻辑很密的模块会被误判成单图。专图总数上限 4。
3. **单图节点 ≤ 14，且节点判据是「宽 rect ≥ 100px 的个数」**——表格型图天然被高估（8 行 × 2 列 = 18 个「节点」）。处置顺序是：先判断是不是表格型 → 是则精简行数或直接改 Markdown 表格 → 是流程图才真拆。**禁止为压低节点数把流程节点硬塞进一张图**。
4. **色板是封闭集合**：只收每个色系的 50/600/800 三档 + 一张白名单，凭「容器浅一点」的直觉挑中间档必然触发告警。遇到告警只做一种修改——换同段档位或白名单色，不重新发明配色。嵌套图的内层固定用白色。
5. **落盘后必跑校验，且校验 ≠ 渲染**：`validate_svg.py` 抓「`<svg>` 提前闭合」「marker id 未定义」「字面下标」「文本溢出」「坐标越界」等肉眼易漏项；但脚本 0 错不等于排版正确，还要 headless 截图逐图核对——**截图窗口高度必须盖过全部图的累计高度**，否则末图被静默截掉。
6. **参数现读现抄，不凭上下文**：同一模块在不同工程里参数方向可能相反，`Read` 顶层时逐个把实例实参抄下来；涉及定点/移位/系数的一律把公式整理成代数式再与注释对账，**不一致时以算式为准并把差异写进文档**（这是高价值发现，不是噪音）。

**资源**：`scripts/validate_svg.py`（含两条最常返工的口径：色板封闭集、宽 rect 计数）；`references/` 5 份，按「走到哪步读哪份」拆分——`figure-count.md`（出图数判据）、`svg-spec.md`（画法硬规范）、`doc-structure.md`（九节结构与写作口径）、`render-check.md`（渲染核对与截断排查）、`env-adapt.md`（占位符探测）。

**可能暴露的本机信息**：已处理完毕，`.bak-20261011` 已删除，本 skill 全部 7 个文件 A/B 类零命中——逐类计数见 §5.2「替换后」表，改动过程见 §5.6。

### 3.5 `Hyzy-IndustryRadar` · 行业研究

**作用**：跑一期细分行业深度研究并产出报告，落盘 md + 同名 html。定位是「FDE 走近客户现场」式追问：真实工作流长什么样、人在哪里卡住、AI 能嵌进哪一步并产生可量化提效；同时必须回答经营侧问题——谁付钱、钱从哪来、省下的时间最后有没有变成钱。

2. **存量盘点 + 新旧分流**：先列输出目录已有报告，再从种子池抽细分环节（避开宽赛道）；已有报告走更新模式（聚焦「发生了什么变化」，保留原文、文末追加更新记录），无报告才新建。

4. **FDE 框架 + 经营视角门禁**：核心章「AI + 提效需求诊断」占 ≥30% 篇幅；门禁包括生意四问与两笔交易、两层竞争（含「维持现状」这个隐性对手）、四种业务阶段、四角色与预算归属、算最后的钱、三分证据。经营视角是**判断门禁 + 文末 ≤200 字收口段**，不是新增大章节，防报告膨胀。

6. **三分证据标注**：全文区分「已核实事实 / 你的解释 / 下一步问题」，未核实数字标「估计/待核实」。

### 3.6 `Hyzy-startupSkill` · Skill 自造

**作用**：创建、优化、审计或评测个人 Skill——把反复做的方法论变成最小可安装文件包，或对已有 skill 做只读审计与改造规划。这一份是「元 skill」：本仓库其他 12 个 skill 的写法约束基本来自它。

**触发**：「帮我做个 skill」「把这套流程封装成 skill」「优化这个已有 skill」「审计提示词与边界」「补触发样例和失败处理」「重构 skill 目录结构」「规划如何优化 skill」。**不触发**：一次性问答、普通文档、翻译、只解释概念、公开发布。

**方法论**：

1. **先查现成（创建/改造类前置）**：动手写之前先只读检索是否已有可复用方案——读索引与各 `SKILL.md`，必要时查外部技能目录。命中可复用就先给「复用或改造」建议，不新建；此步只读、不安装、不写文件，且不得因此增加澄清轮次。
2. **选型 3 问，不硬造 Skill**：一次性 → 一段 prompt；反复 + 流程固定 → Skill；反复 + 大量专属资料 → Skill + RAG 壳；全新能力 → 微调，超出范围。
3. **从材料恢复五要素，不做问卷**：重复问题 / 真实输入 / 成品 / 完成证据 / 最近排除项。信息足够就直接做；仅当某个缺失答案会改变「产品类别、权限边界或不可逆范围」时才问**一个**问题，其余缺项写保守可逆假设后继续。
4. **最轻包**：默认 Scaffold（个人本地可逆）——根 `SKILL.md` + 任务真正赚到的资源；**不为个人本地 skill 造** README、manifest、发布脚本、报告目录或空目录。团队复用、触发易误伤、跨平台、高风险权限、公开发布时才升级门禁。
5. **泛化门（防过度推广）**：单样本反馈先改写成领域中立失效机制 → 分类为「核心不变量 / 可选适配 / 仅 eval fixture」→ 只有安全、事实、权限或跨领域复现 ≥2 次才升为核心规则。一次性细节留在 fixture 或专门 reference。

### 3.7 `Hyzy-VerifyGate` · 完成前验证闸门

**作用**：任何准备宣称「完成 / 已修复 / 已通过 / 已上传 / 已安装 / 校验无误」的时刻，先过这道闸门。它是另外 12 个 skill 的校验出口。

**触发**：准备下完成类结论时；结论的唯一依据是脚本输出、退出码、上次运行结果、客户端自报或子代理回报时；交付任何产物、状态汇报或定时任务结果前。

**方法论**：

1. **铁律**：本轮没跑过验证命令，就不能说「通过 / 完成 / 已修复 / 已上传 / 已安装」。不得用「绑定成功」「未找到用量」「命令没报错」「上次跑过」替代结果证据。
2. **五步闸门**：IDENTIFY（找出能证明该结论的完整命令）→ RUN（本轮重跑，跑 FULL，不复用上次结果）→ READ（读全输出、退出码、失败计数、关键字段）→ VERIFY（输出是否真的支持该结论）→ ONLY THEN（才允许表达完成）。跳过任一步 = 撒谎。
3. **证据对照表**：为 10 类常见结论各自定义最低证据——例如「上传成功」必须服务端状态 + 最近上传时间戳，「子代理完成」必须独立复核产出物 / diff，「数量/哈希一致」必须本轮实测而非按预期值推算。
4. **反合理化表**：把「上次跑过没改动」「退出码 0 就是成功」「时间紧先报完成」这类想法逐条对上现实，堵住自我说服的通路。
5. **partial / 无法验证的处置**：partial 要列出未完成的具体项且不宣称全部成功；工具被拦、权限不足时明确写「未验证」+ 阻断点，**禁止用推测补结论**。
6. **阶段决策日志**：每个阶段结束向当日日志追加四元组——关键问题（一次列全）/ 用户原话（不改写不美化）/ 因此改变 / 时间戳（不估算、不用调用数替代）。这是给未来会话看的，与给用户看的证据汇报分开。

**资源**：单文件，无 references、无 scripts（刻意如此——闸门要短到能被每次读完）。

**可能暴露的本机信息**：**无**。全库另一个可直接公开的。

### 3.8 `Hyzy-skillPortable` · 私有 skill 可移植化

**作用**：把一个只在本地跑得通的 skill，改造成换机器能用、能公开、且方法论一条不丢的版本。交付的是改造后的文件包 + 变更台账 + 验证证据，不是建议清单。

**触发**：「把这个 skill 通用化」「去私有信息」「脱敏」「能不能公开」「换机器还能用吗」「抽象化这个案例」「推到 GitHub 之前要改什么」。

**方法论**：

1. **硬编码 ≠ 写具体路径**：判据是「无检查、无回退、无条件信任」。具体路径 + 先 `stat` + 缺失即降级是好实践——不要为了「通用化」把可用的本机默认值删掉。
2. **A–F 六类探查**：A 身份（用户名 / 主机名 / 家目录 / `name` 字段前缀）、B 私有数据（真实素材与库路径）、C 环境事实（venv / 解释器 / 工具链）、D 项目背景（厂商 / 芯片 / 书名，**含文件名**）、E 结构缺陷（超长 SKILL / 悬空引用 / 文档假账）、F 可执行性缺陷（占位符重复拼接，代入后指向不存在的目录）。
3. **改前必须物理备份**：skill 常处于未跟踪状态，`git rev-parse --show-toplevel` 可能指到外层无关仓库，Git 不能当回滚点。备份后核对「包内文件数 == 磁盘文件数」并记 MD5。
4. **本机事实不删，隔离**：塞进 `env-adapt.md` §五「本机默认值」，固定三段式 `先 stat → 存在就用 → 不存在降级`，标题写明「换机器整节删掉即可」——正文保持通用，本机仍开箱即用。
5. **抽象化要带口径表**：留方法与数字，去书目 / 型号 / 路径；文件头写明哪几处**有意不改**（如 `.adc` / `.xdc` 这类文件格式后缀），否则后人分不清刻意与漏改。
6. **保真四道**：数字多重集比对（每个「丢失」都要给理由）+ 关键词清单（30–80 项，缺失必须 0）+ 结构校验（表格列数、围栏配对、引用存在）+ 行为测试（派不知情代理跑同一道题，看它是否按标记读到正确的 references）。

**资源**：`references/taxonomy.md`（六类判定 + 扫描命令 + 误报清单）、`remediation.md`（六种修改手法 + 模板 + 翻车点）、`verify-eval.md`（保真四道 + A/B + 耗时拆解 + 诚实结论模板）。

**可能暴露的本机信息**：**无**。自检时它自己的示例曾命中 3 处（检测命令里写了系统默认账户名、示例里带「盘符 + 中文段」），已改成不匹配自身正则——**一个查指纹的 skill，必须自己不触发自己的规则**。

### 3.9 `Hyzy-PhysLabReport` · 物理实验报告流水线

**作用**：把「原始数据照片 + 教师内容要求 + 讲义 + 课后习题」做成可直接提交的本科物理实验报告 docx，并连带交付数据 Excel、专用约束与任务规划、定稿复盘。底稿来自 4 份定稿 + 3 轮定稿复盘，其中 2 份被用户逐字改过后回灌成规则。

**触发**：「完成 XX 实验报告」「写物理实验报告」「按通用约束规范出报告」「把这组数据写成报告」，且手上有实验目录或原始数据。

**方法论**：

1. **骨架由「内容要求」定，不由模板定**：开工先 `ls` 实验目录，按内容而非文件名认材料（历年目录名不完全一致）。要几张表、几张图、哪几道题只能从教师口径取；缺「内容要求 / 讲义 / 原始数据」就停下来问，不用通用知识补。
2. **数据必须能回溯**：报告里每个数都要能在原始照片或 Excel 里指出来，读不出的格标 `[存疑：辨认]` 也不猜。照片先判方向再转录；正反读数容差**按表分别给**（电学 ≤1 V、磁学 ≤6 mA），统一容差会误报。
3. **六阶段带门禁，P4 与 P5 之间必须目视**：P0 摄取 → P1 数据（用户明确说「数据正确」才放行）→ P2 约束（偏离逐条报批）→ P3 图 → P4 构 docx → P5 验收 → P6 定稿。**纯字符串检查查不出公式跨行断裂、图片被上边距裁掉、标题孤立在页底**，所以导 PDF 转 PNG 逐页看是硬闸门，不是可选项。
4. **硬规范 SSOT 双轨**：完整规范内置 `references/spec.md`（638 行），不再依赖项目目录存在该文件；项目内有同名规范时以项目文件为准，并在收尾把差异回灌内置副本——这样换机器仍可用，本机又能吃用户的增量规则。
5. **直构 OOXML/OMML，不编辑器粘贴**：宋体四属性齐全且 `SimSun` 计数必须为 0、字号只许 22/18/15/14/12、图片段落禁用 `lineRule="exact"`（会把内联图顶出页边距裁掉）。这些写成构建脚本里的断言，不留给事后目视。
6. **形式合规 ≠ 交付合格**：字数 / 字号 / 边框都能过检，但通篇复述照样被打回。判据是「删掉这段，读者会缺什么信息」。
7. **手改过的 docx 不许重跑覆盖**：用户手改是最终态，只能外科式补丁且先备份为 `（改前备份）.docx`；构建轮登记的遗留项（留空字段、旧数据辅助列）要在定稿轮逐条「补 / 删 / 保留」并写进处置表。

**资源**：`references/` 五份——`spec.md`（完整规范，判定任何条款前必读）、`pipeline.md`（进入任一阶段前必读）、`ooxml-recipes.md`（P4 写构建脚本前必读）、`content-rules.md`（定字数预算 / 写正文习题前必读）、`verification.md`（P5 验收前必读）；`scripts/` 五个——`build_report.py`（起点骨架）、`check_report.py`（16 项通用自检 + 专用可配）、`plot_curves.py`、`export_pdf.ps1`、`diff_docx.py`（手改段落级 diff）。

**可能暴露的本机信息**：中。**本 skill 为后建，此段记的是现行处置结果，不是替换前快照**。原文含真实学生**姓名 / 学号 / 班级 / 座位号**与一个解释器绝对路径：学号**按作者要求整字段删除**（不是打码），班级号打码 `XXXXXXX`、姓名 `XXX`、座位号 `XX`；解释器绝对路径改为「自动探测同时能 `import docx, lxml, numpy, PIL, fitz` 的解释器，缺依赖先问用户」；交付示例里的盘符路径改为 `<PROJ>\<实验>报告.docx`。复扫 12 个敏感词全部为 0。

### 3.10 `Hyzy-AIGrowthNote` · AI 成长经验沉淀器

**作用**：把一段真实发生的 AI 协作 / Agent 系统优化经历，按实际演进顺序沉淀成「核心问题与需求 → 逐步解决 → 系统结构变化」的成长笔记，含一张 680px SVG 演进链路图，一问题一文件存入个人笔记库。

**触发**：「把这次对话沉淀成经验」「按实际发生的过程记问题与解决」「扫描整个文件夹把这条问题的探索写完整」「照上次那套再存一份」。

**方法论**：

1. **真实演进顺序不可换**：禁止用抽象分类、分层体系替代时间顺序（这条是用户明确否过一次后写进去的）。笔记记的是「当时发生了什么、为什么改路线」，不是「这类问题应该怎么分类」。
2. **先扫空间，再建时间线，最后才动笔**：扫描根按「用户点名目录 > 当前工作区 > `.workbuddy/memory` > 项目子目录 > 目标笔记库 > 历史会话」六级取，只读、不改源文件。没有时间线就写，产出必然是任务流水账。
3. **阶段 = 能力层跃迁，过删除测试**：删掉这一步，后续能力是否还成立？仍成立就是操作细节，不是阶段。实验数、模块数、提交次数都不等于阶段数。
4. **需求写成「系统要具备什么能力」**：现象「图标双击没反应」不是需求，「入口要能自恢复且不重复起进程」才是。这一步是从流水账升级为经验的关键。
5. **ADR 三条件筛选决策**：难逆转 / 无上下文会惊讶 / 真实权衡，三条全真才记，缺一即并入叙述——宁缺不凑，避免把每个选择都包装成决策。
6. **一问题一文件 + 命名查重**：文件名与 H1 必须贴具体案例主体；落盘前 `ls` 查同名，同名停下问覆盖 / 追加 / 改名，绝不静默覆盖。
7. **SVG 680 宽 + 复用同库校验器**：画法与校验复用同库 `Hyzy-HDLtoSVG&Explain` 的 `validate_svg.py`，不在本包复制第二份规范；跑完 0 错 0 警后再补一次静态核对（XML 合法、坐标不越界、marker 已定义）。
8. **不谎报**：「结构校验通过」不等于「渲染通过」；没做真实渲染截图就写明是缺口。

**资源**：`references/output-contract.md`（产物形态、命名规则、SVG 最小规格、事实恢复优先级）、`references/space-scan.md`（扫描顺序、时间线、阶段判定、覆盖度 6 问）；`evals/trigger_cases.json`（7 条应触发 / 5 条不应触发 / 6 条近邻路由 / 3 条权限用例）。

**可能暴露的本机信息**：中。**本 skill 为后建，此段记的是现行处置结果，不是替换前快照**。原文含 1 处带账户名的家目录、1 处真实笔记库路径、1 处真实目录名、3 处真实项目名、1 处固定端口。其中 3 处真实项目名**按作者要求全抽象化**（用一个仅作 fixture 的案例名替换，六步演进结构保留作示例）；两处路径改为解析规则（用户点名 > 目标库同名子目录 > 问用户；校验脚本按同库根 `stat` 探测，缺失走静态检查回退）；固定端口与真实目录名删除。复扫 12 个敏感词全部为 0。

### 3.11 `Hyzy-SkillRouter` · 治理层路由入口

**作用**：治理层的统一入口。5 个成员（`find-skills`、`Hyzy-startupSkill`、`Hyzy-skillPortable`、`skill-library-governance`、`Hyzy-VerifyGate`）的触发词都含「skill」二字，单靠各自 `description` 容易选错；本 skill 只做一件事——**按用户当前处在哪一步，定位到唯一那个成员**，然后交出去执行。

**触发**：「我该用哪个 skill 管这件事」「这个 skill 能不能公开」「帮我做个新 skill」「skill 库是不是乱了」「这个 skill 改完了吗」「先找找有没有现成的」。**不触发**于具体领域任务（内容转换、报告撰写、图解生成、笔记入库）——那些直接走对应领域 Skill，本 skill 第六节点名去哪。

**方法论**：

1. **按处境路由，不按触发词路由**：触发词在五个成员之间大量重叠，查触发词不如查「你现在处在哪一步」。路由表三列——处境 / 走向 / 一句话判据，先查表再加载。
2. **只路由，不执行**：正文里出现的只是**步骤名**（「查现成」「建包」「先备份」「全量体检」），不是这些步骤的判据。判据只在成员自己的文件里写一次；搬第二份必然两处不同步。
3. **歧义消解表是核心资产**：四组两两最易混的成员（查 vs 造、造 vs 改、改一个 vs 看一库、闸门 vs 流程），每组给一句可执行的判据。没有这张表，路由表只能覆盖一半情况。
4. **「两可」要显式承认**：输出固定三行；两个成员都像时仍用三行，但第三行只写**一个**能分开它们的问题，不把两个候选都塞进「下一步」——那等于把选择推回给用户却不给判据。
5. **覆盖缺口要说清去哪**：只说「走对应领域 Skill」等于没说。第六节列了 7 个领域 skill 的去向表；同时明确「这一步的输出只能写到读它的 SKILL.md 为止，不要替它编一个第一步」。
6. **能力缺失显式降级**：成员不存在 → 直说未安装、不拿相近的顶替；成员在但跑不动（断网、无写权限、`npx` 超时）→ 降级并标注，不假装做到了。

**资源**：`references/members.md`（5 个成员各自的第一步、能力边界、依赖、已知坑、与相邻成员的差异，**调用任一成员前必读**）。

**可能暴露的本机信息**：**无**。本 skill 为 2026-11-20 新建，落笔即用抽象写法（`<库根>`、`<成员目录>`），没有脱敏前状态。R0 轮行为测试后修掉的 6 处问题是术语与覆盖缺口，不涉及本机信息。

### 3.12 `find-skills` · 先查现成

**作用**：把「我想做 X」这类模糊需求映射成一份可核验的候选 Skill 清单。三层检索——本地库 → 开放目录（`www.skills.sh` 排行与 GitHub API）→ 源码 / 中文源。

**触发**：「有没有现成的 skill 能做 X」「先找找看别人做过没有」「这个需求该装什么」。**不触发**于已明确要自己造（直接进 `Hyzy-startupSkill`，它内部会调本 skill）。

**方法论**：

1. **先定检索范围再动手**：只在本机库找，还是允许联网查开放目录？范围没定就问一句，不默认联网。
2. **三层递进，命中即停**：本地命中可复用的就交回用户决定，不继续往外查——继续查只会增加候选噪声。
3. **只列不装**：候选清单不等于「已安装」。用户没点名之前不给安装，不写文件、不刷新索引、不提交 git。
4. **单一中文词零命中不算完成**：必须做中英同义扩展后再判「本库无可复用技能」，否则很容易把已有的判成没有。
5. **超时按失败降级**：`npx --yes skills find` 实测易超时，20s 未返回就降级并说明「只查了本地」，不反复重试。
6. **库根先探测再用**：`~/.workbuddy/skills/` 存在就用它，否则用当前仓库根；没有 `INDEX.md` 时退化为扫 `<库根>/*/SKILL.md` 的 `name` 与 `description`。**只有 `skills/<name>/SKILL.md` 的仓库（例如本仓库）必然走降级路径，这是预期行为，不是故障。**

**资源**：单文件 `SKILL.md`，无 references / scripts。

**可能暴露的本机信息**：轻。**迁入本仓库时改了 9 处，全部是语义移植而非隐私清理**——原文把「库根 = `~/.workbuddy/skills/`」写死，并依赖该库专有的 `INDEX.md` / `tools/refresh_index.py` / `ARCHITECTURE.md`，本仓库三样都没有。已改为「先探测再用」+ 「存在则用、不存在则降级」，并在正文里写明降级是预期行为。A / B 类零命中。

> 这份 skill 是「库根假设」最典型的一例：它没有泄露任何隐私，但在别的仓库里会**指错地方**。脱敏扫描查不出这类问题，只有把 skill 搬到目标环境里读完才看得见。

### 3.13 `skill-library-governance` · 库级体检

**作用**：对一个扁平 skill 库（`skills/<name>/SKILL.md` 单层平铺）做周期性全量体检——摸家底、标功能重叠与内容残次、出观察名单与「保留 / 合并 / 暂存淘汰」三选一建议。

**触发**：「skill 库是不是乱了」「有没有重复的」「哪些可以清掉」「盘一下现在有哪些 skill」。**不触发**于改单个 skill（走 `Hyzy-skillPortable`）。

**方法论**：

1. **先摸家底，再谈诊断**：先出清单（有哪些目录、各自有没有 `SKILL.md`、文件数、最后修改时间），没有清单的诊断都是印象。
2. **功能重叠靠三处对齐判，不靠名字**：描述、触发条件、产物形态三处同时像才算重叠；名字像但产物不同的不算。
3. **内容残次分三类**：空壳（只有 `SKILL.md` 且无实质流程）、半成品（有流程但缺 references / scripts）、过期（描述与正文已不一致）。三类处置方式不同。
4. **三选一建议必须给理由**：保留 / 合并 / 暂存淘汰，每项都要写清依据，不给「感觉没用了」这类判断。
5. **「长期未用」只能标为近似值**：没有真实调用日志，只能用「人工自认 + 上次审计时间戳」近似，必须如实标注，不伪装成统计结论。
6. **全程只读，删除只提不做**：即便用户说「帮我清一下」，也只出建议；处置动作另起一轮，且先入暂存区。

**资源**：单文件 `SKILL.md`，无 references / scripts。

**可能暴露的本机信息**：轻。迁入本仓库时改了 6 处，其中 **1 处是真实的 A 类命中**——原文写死了管理 SOP 的绝对路径（含系统用户名与账户目录），已改为 `<库根>/Skill库管理SOP.md`（存在则读，不存在则本轮即首次建立）。其余 5 处是：边界表述由「用户级仓库」放宽为「一个库根」；「已知基线（2026-09-07 首次审计）」改为「基线示例」，并把真实规模（25 个目录 / 24 个有效 skill）抽象为占位；frontmatter 补 `updated`。

> 这 6 处里**只有 1 处是隐私问题，另外 5 处是可移植性问题**：原文明说「只管用户级仓库」，换到别的库会拒绝执行；原文明写作者自己的库规模，换台机器就是假数据。

## 四、纵向对比：同一副骨架的两种变形

### 4.1 内容型 7 个

| 环节 | rawprocess | PDFtomdnotemap | KnowtoMethPath | HDLtoSVG | IndustryRadar | PhysLabReport | AIGrowthNote |
|---|---|---|---|---|---|---|---|
| 前置勘察 | 判定输入形态 | Stage 0 契约勘察 | Stage 0 素材卡 | 读码取结构清单 | 盘点存量 | 认材料不认目录名 | 先建探索时间线 |
| 硬闸门 | 入口成本分档 | 批间等确认 | 路径数 2–12 | 复杂度定图数 | 无人值守零提问 | 硬规范先锁版式 | 真实顺序不可换 |
| 产物 | 1 md + images | 一批概念笔记 | 1 方法路径文档 | N 图 + 九节 md | 1 md + 1 html | 1 docx + 4 件配套 | 1 份成长笔记 md |
| 校验 | validate_md | verify_notes / fullcheck | verify_methpath | validate_svg + 渲染核对 | 三分证据标注 | 导 PDF 逐页目视 + check_report | validate_svg + 覆盖度 6 问 |
| 收尾 | 校验清单 | 三个数必须对得上 | 交付摘要 + 验算记录 | 五条关键发现 | 5 句摘要 + ≤200 字收口 | 定稿复盘 + 规则回灌 | 路径 / 阶段数 / 缺口 |

**共同点**：每个都有一个「不许省的那一步」——rawprocess 是分流、PDFtomdnotemap 是契约勘察、KnowtoMethPath 是案例验算、HDLtoSVG 是渲染核对、IndustryRadar 是口径审计、PhysLabReport 是「导 PDF 逐页目视」、AIGrowthNote 是「先建时间线再动笔」。这些不是装饰，都能追溯到一次真实翻车。

### 4.2 治理层 6 个（整合包）

这一层不产领域内容，骨架也换了一副：**先判定该不该由自己做，再决定用谁的规矩做。**

| 环节 | SkillRouter | find-skills | startupSkill | skillPortable | governance | VerifyGate |
|---|---|---|---|---|---|---|
| 前置勘察 | 查路由表定位 | 定检索范围 | 读记忆 + 查现成 | 定目标形态 + 备份 | 摸家底出清单 | 找出该跑的命令 |
| 硬闸门 | 不按触发词猜 | 只列不装 | 泛化门 | 备份 + 逐处 assert | 只读，删除只提不做 | 五步不可跳 |
| 产物 | 一段三行判断 | 候选清单 | 1 skill 包 | 变更台账 + 证据 | 审计报告 + 观察名单 | 一份证据汇报 |
| 校验 | 两可时只问一个问题 | 中英同义扩展后再判空 | 四级验证 | 保真四道 + 行为测试 | 重叠需三处对齐 | 证据对照表 |
| 收尾 | 交给成员执行 | 交回用户决定 | 路径 / 问题 / 等级 / 风险 | 台账 / 证据 / 未决三块 | 三选一建议 + 理由 | 证据三件套 |

**共同点**：同样各有一步不能省——SkillRouter 是「查表不猜」、find-skills 是「只列不装」、startupSkill 是泛化门、skillPortable 是「先备份再动手」、governance 是「只读只提不做」、VerifyGate 是重跑。

**与 4.1 的真正差别**：内容型 skill 的危险动作是「产物做错」，改一遍就行；治理层的危险动作是**「替用户改了他的资产」**——所以这一层里「只读」「先备份」「只提不做」出现的频率远高于 4.1，而且三个成员（`find-skills`、`skill-library-governance`、`Hyzy-SkillRouter`）明文规定不写任何文件。

其中 `skillPortable` 是唯一**寄生型**的：它的方法论全部由其余 skill 的真实改造过程沉淀而来（§5.6 记录的是第一轮；`Hyzy-PhysLabReport` 是 2026-11-18 的第二轮，第一个「有真实私人数据要清理」的样本；`Hyzy-AIGrowthNote` 是 2026-11-20 的第三轮，第一个需要把「本机默认值」整表改写成解析规则的样本；同日迁入治理层两个成员是第四轮，**第一个「隐私只有 1 处、其余 5 处全是可移植性问题」的样本**），本身不产出领域内容。

拆分原则是**必读标记**而不是「参见」：正文在每个步骤开头写「X 之前必读 `…`」，不给代理跳过的余地。验证方式——让一个不知道背景的代理跑同一道 Verilog 题，看它是否主动读 `figure-count.md` 与 `svg-spec.md`，并能否报出具体坐标与色值出处。实测通过：它读了这两份、答对 1 张图、坐标引自 `svg-spec.md` 的对应行，同时把 `doc-structure.md` / `render-check.md` 正确推迟到各自步骤。

内容不丢：原文 210 条有效行逐条比对 + 75 项关键要素（680 宽、色板 50/600/800、`baseline-shift`、W4/W5/E10、九节名、硬边界 10 条等）全部在位。

**后续（2026-11-14）**：同一套「必读标记 + 行范围切片 + 保真四道」也用于 `PDFtomdnotemap` 与 `rawprocess` 的拆分，详见 §5.3 的本轮完成表。`INTERNAL-CONTENT-AUDIT.md` 已改为结论摘要、`HYZY_*` 经判定不改动，`_素材/` 已中性化，**当前剩余任务只剩配置 remote 与推送**。

## 六、移植到别的机器需要改什么

| 项 | 现状 | 换机要做的 |
|---|---|---|
| 路径变量 | **已改为占位符**，各 skill 自带「环境自适应」段与 `references/env-adapt.md` | 无需手改：能探测的自动解析，探测不到会主动问一句 |
| Python 依赖 | docx 镜像需 `markitdown`；PDF 需 `pymupdf4llm`；渲染核对需 `Pillow` + `numpy` | 按需装到自备 venv；脚本会探测并明确提示缺哪个库 |
| 外部程序 | 渲染核对调用本机浏览器 headless | 换成本机浏览器路径 |
| 目录约定 | 假设扁平结构 `~/.workbuddy/skills/<name>/` + 索引脚本 | 索引脚本路径按实际环境调 |
| 治理层成员 | `Hyzy-SkillRouter` 路由表点名 5 个成员，缺一个它就少一条路 | 少装哪个就按 `references/members.md` 六、七两节处理：直说未安装、不拿相近的顶替、跑不动要显式降级 |
| 风格锚点 | HDLtoSVG 依赖一份外部参照文档 | 换机后该文件不存在，走 skill 内置降级规则 |
| 个人习惯绑定 | IndustryRadar 的输出目录/命名/双份格式；rawprocess 的中度去噪标准 | 按自己的库与写作习惯改，这部分不可照搬 |

一句话：**方法论可移植，路径与个人偏好不可移植。**
