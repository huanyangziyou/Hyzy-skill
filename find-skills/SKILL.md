# find-skills · 先找现成，再决定造不造

把模糊需求映射成可核验的候选 Skill 清单，默认只列不装。技能库根按「先探测再用」解析：`~/.workbuddy/skills/` 存在就用它，否则用当前仓库根；而 `npx skills` CLI 并不支持 WorkBuddy 的用户级目录（它装到 `.codebuddy/skills/`、`.claude/skills/` 等），因此本技能只做检索、比对与权限标注，不代跑安装命令。

## 一、触发与不触发

**触发**
- 「不知道该用哪个 Skill」「有没有能做 X 的 skill」「帮我找一个 X 的工具」。
- 「这个需求有现成方案吗」「别从零写，先去 GitHub / 技能库找找」。
- 「造 skill 之前先看看有没有能复用的」——由 `Hyzy-startupSkill` 前置调用。

**不触发**
- 一次性问答、只解释概念、翻译、普通文档处理。
- 用户已点名某个明确包并要求直接安装 → 走本库安装流程，不必检索。
- 明确要创作全新 skill → 转 `Hyzy-startupSkill`。

## 二、三层检索（按顺序，命中即可停）

| 层 | 数据源 | 动作 | 先查它的理由 |
|---|---|---|---|
| 1 本地 | `<库根>/INDEX.md` 与各 `SKILL.md`；无 INDEX.md 时直接扫 `<库根>/*/SKILL.md` 的 `name` 与 `description` | 只读检索已装技能；**做中英同义扩展**（如 会议纪要 / meeting minutes / 逐字稿 / transcript），并读命中技能的 `When to Use` 段 | 最贴合中文与自有方法论，零网络、零风险 |
| 2 开放目录 | `www.skills.sh` 排行榜与 GitHub API 只读检索（实测均 200 可达） | 网页 / API 只读搜索，取安装量或 star 作热度证据 | 覆盖面广，能验证热度 |
| 3 源码 / 中文源 | GitHub 仓库搜索、SkillHub 中文技能页 | 只读查看 README / SKILL.md；**宽查询会返回高 star 无关仓库，须过质量门禁，不得按 star 直接列候选** | 补英文索引覆盖不到的中文与冷门技能 |

**CLI 边界（硬约束）**：不全局安装 `skills` 包；只用 `find` / `list` 等只读命令；**不用 `add`，不用 `-g -y`**。`npx --yes skills find "<query>"` 降为可选路径——实测 3 次均超时、零输出，**20s 未返回即按失败处理表降级**。确需安装时走本库流程：来源确认 → 装前审计 → 放入 `<库根>/` → 若 `<库根>/tools/refresh_index.py` 存在则运行它刷新索引 → 若该库是 git 仓库则提交。

**第 1 层完成判据**：仅按单一中文词匹配 `INDEX.md`（无索引时按 `name` 与 `description` 匹配）命中 0 不算完成检索；必须做过同义扩展并读命中技能正文，才能判定「本库无可复用技能」。

## 三、质量门禁（每个候选逐项过）

1. **来源信誉**：官方源（vercel-labs / anthropics / microsoft / WorkBuddy 官方市场）优先；未知作者标「待核验」。
2. **热度证据**：安装量 ≥1K 或 star ≥100 才写「已验证」；低于此标「样本不足」，不因排名靠前就推荐。
3. **权限清单**：写明需要的文件读写、网络外发、脚本执行、密钥，以及是否含 `rm -rf` / `del` / `curl` / `os.system` / `exec` 等破坏或注入风险。
4. **适配性**：是否兼容 WorkBuddy（CLI 默认目录不含 `.workbuddy/skills/`，需人工放置）；中文场景支持度。
5. **重复检查**：与本机已装技能是否重叠；重叠的给「复用 / 改造」建议，而非「再装一个」。

不得仅凭搜索排序下推荐结论；无法核实的字段写「未核实」，不猜。

## 四、输出合同（默认只列不装）

给一张候选表 + 一句结论：

| 名称 | 作者 / 来源 | 解决什么 | 热度证据 | 安装方式 | 所需权限与风险 | 适配 WorkBuddy |
|---|---|---|---|---|---|---|

末尾必须写：
- **最推荐** 1 个 + 只基于已核实字段的理由；**备选** 1 个。
- **权限提示**：第三方技能装前必审计，先用无隐私样例试跑。
- **决定权**：「以上只列不装。需要装哪个请点名，我再走二次确认与装前审计。」

**无结果兜底**：明确写「未找到匹配技能」，说明查过哪几层，给两个选项——用通用能力直接做，或用 `Hyzy-startupSkill` 造一个；不得悄悄改推别的方向。

## 五、停止条件与失败处理

| 情况 | 动作 |
|---|---|
| 用户只说「找找」，未给场景 | 从已有对话恢复需求做一次检索；仍不足才问**一个**边界问题 |
| 网络不可达 / CLI 报错 | 降级到第 1 层本地检索，如实标注「外部源未查」，不伪造结果 |
| CLI 超时 >20s | 同上降级，并在结论里写明「开放目录未查，仅本地检索」 |
| 候选来自第三方且含脚本或网络外发 | 标出风险、只列不装，等明确授权 |
| 用户点名要装 | 停在写入前：列目标路径与审计项 → 二次确认 → 才执行 |
| 检索命中本机同名技能 | 报「已存在，建议复用 / 改造」，禁止覆盖 |

**停止条件**：给出候选表与结论即完成。未获明确点名与二次确认，不得进入安装、不得写任何文件。

## 六、验收标准

- 至少执行第 1 层检索，并给出可核验字段（名称 / 来源 / 权限 / 安装方式）。
- 默认零写入、零安装；`add` 与 `-y` 一次都没出现。
- 每个候选的权限与风险已标注，未核实字段标「未核实」。
- 若用户要求安装，留有二次确认记录与装前审计结果。

## 七、不能做的事（违反即失败）

- 不自动安装、不代跑 `npx skills add`，不用 `-g -y` 跳过确认。
- 不覆盖、删除、移动用户已有技能；删除须先入库外暂存。
- 不写任何文件、不刷新索引、不提交 git（属安装阶段，需另行授权）。
- 不凭热度或排名编造「质量好」「更省时」「省积分」等无证据结论。
- 不把第三方技能的脚本权限说成「已审计」；未查就是未查。
- 不把一次性需求或明确创作请求拉进检索流程。
