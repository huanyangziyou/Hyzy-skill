# Skill 库治理审计

## 定位

对**一个扁平 skill 库**（WorkBuddy 用户级库 `~/.workbuddy/skills/`，或任何以 `<name>/SKILL.md` 单层平铺的仓库）做周期性全量体检：摸清家底、标出重复与残次、给出处置建议。

**边界**：只管一个库根。不碰官方插件缓存 `plugins/cache/...`，不碰任何项目的项目级 `.workbuddy/skills/`。

**铁律**：**全程只读**。禁止删除、移动、修改、重命名任何文件。本 skill 只产出报告和建议，处置动作必须等用户逐项拍板后另起一轮执行，且走暂存区（`_trash/<日期>/`），严禁 `rm -rf` / `del /S /Q`。

## 何时用

- 季度全量审计
- 事件触发：新装 skill 累计满 3 个 / 换主力项目 / 怀疑调用错版本 / 某 skill 连续两次效果不佳
- 用户问"我有哪些 skill""这个库里有没有重复的""某个 skill 是不是多余的"

## 执行流程

### 1. 读取基线

先读管理规范与上次台账（存在则读，不存在则本轮即首次建立）：

- `<库根>/Skill库管理SOP.md`（存在则读；不存在则本轮即首次建立）

拿到：判定标准、上次观察项、上次未决问题。

### 2. 全量扫描

对每个子目录提取：`name`、`description` 首句、文件数、子结构（`scripts/` `references/` `assets/`）、来源分类。

**来源分类图例**：`自`=自沉淀 ｜ `G`=GitHub 抓取 ｜ `写`=自写官方版 ｜ `官`=官方市场版

判断来源看线索：目录内有 `agents/openai.yaml` 且属 dbs 系 → G；名字为 Hyzy-* 或 github-skill-fetch → 自；`plugins/cache/` 下也有同名 → 官或写。

### 3. 体检判定（命中任一即列入观察名单）

| 标准 | 判定依据 |
|---|---|
| **A. 功能重叠** | 两个及以上 skill 处理同一任务，或职责边界含混、调用时难以抉择 |
| **B. 内容残次** | 无 SKILL.md、frontmatter 不合法、依赖脚本/引用缺失、描述看不出何时该用 |
| **C. 长期未用** | 台账中连续两个周期标为未用（**近似值，必须如实标注**） |

**依赖引用完整性检查**：对含 `scripts/` `references/` 的 skill，从 SKILL.md 提取被引用的相对路径，逐个验证存在性。注意区分**真实缺失**与**示例占位符**（如 `xxx.jsx`、`assets/google.svg` 这类写法是文档示例，不是缺失；`scripts/.tikhub_api_key` 是用户自建密钥文件，源仓本就不携带）。

### 4. 输出报告

三块，缺一不可：

1. **更新后的完整台账表格**（覆盖 SOP 第七节格式）
2. **观察名单**：每条写「命中标准 + 具体证据 + 保留/合并/暂存淘汰 三选一建议 + 理由」
3. **与上次差异**：新增了什么、上次的问题是否解决、有无新增风险

## 硬约束（违反即任务失败）

1. **只读**。任何写操作都要先取得用户明确同意。
2. **判编码必须精确**。检测 SKILL.md 编码或 frontmatter 是否损坏，用 Python 精确 decode：

   ```python
   raw = open(f, 'rb').read()
   try:
       raw.decode('utf-8')   # 通过才是真正常
   except UnicodeDecodeError as e:
       ...  # 这才是真损坏
   ```

   **不要靠终端 grep 的中文显示下结论** —— Git Bash 的 locale 会把正常 UTF-8 渲染成 GBK 乱码（如 `鐢ㄤ簲...`），据此判断会产出假警报。这条坑已实际踩过一次。
3. **"长期未用"没有真实数据**。WorkBuddy 无 skill 调用日志，只能用「人工自认 + 上次审计时间戳」近似。报告里必须写明这是近似值，不得包装成使用率。
4. **删除类建议只提不做**。即便用户说"帮我清一下"，也要先列出完整清单、说明理由、等确认，再另起一轮走暂存执行。

## 基线示例（作者首次审计，仅示范怎么记；不是本库数据）

- 规模：`<N>` 个目录 / `<M>` 个有效 skill + 空壳目录清单
- 编码与 frontmatter：**全量检测通过**（UTF-8 全部正常）
- 风险项 **R1 · 同名双份**：`find-skills`、`agent-browser`、`summarize`、`skill-creator` 在官方插件缓存中也有同名版本，存在"以为在改 A 版、实际跑 B 版"的风险。用户已划定本轮不处理。
- 观察项 **O1**：`markitdown-skill` / `defuddle` / `Hyzy-rawprocess` 均可"转 Markdown"，输入源不同（本地文档 / 网页 / 杂乱原始材料），建议保留但互相标注边界。
- 观察项 **O2**：`tools/` 仅有 `refresh_index.py`，无 SKILL.md，不会被加载，属空壳。

复跑时优先核销以上三项的状态变化。
